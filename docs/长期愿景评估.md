## 4. 评分纪律

1. 每循环收口时评分，数据必须来自当轮可核查证据（评估报告/测试报告/门禁台账）。
2. 单调不减是设计目标不是硬约束：真实下降如实记，隐瞒或无据改分视为审计事件。
3. 维度定义变更（如并回七维）须在本文件留版本注记。

## cycle-113 发布决策：`src/xuanji` 独立包——**暂不拆分**

- **决策**：维持 `src/xuanji` 为本仓内部目录，不发布独立 npm 包（cycle-112 流转项关闭）。
- **理由**：① 唯一消费者是 `XuanjiAdapter` 与 `/query` 路由，无外部需求信号；
  ② 拆分需要独立版本号/CHANGELOG/兼容承诺三件套，维护成本 ×2 而收益为 0；
  ③ 自包含守卫（import 不出 `src/xuanji`）+ 导出守卫 + 可达性守卫已保证「随时可拆」——
  拆分是机械操作，等真实需求出现再执行不迟。
- **复核条件**：出现第二个消费者工程，或宿主生态出现图算法包需求时重议。
