# 分层图库架构设计

> 混合方案 A+C：渐进式分层图库 + 分块渲染优化
> 日期：2026-09-09

## 1. 背景与动机

### 1.1 当前性能瓶颈

| 问题 | 位置 | 影响 |
|------|------|------|
| 全量重建过于宽松 | DataController.ts:58-84 | 任何节点属性变化 → 清空全部 Cytoscape 元素 → 重新添加 |
| 零缓存 | graphStore.ts:179-186 | 每次视图切换从头执行 assembleDiagram + computeClusteredGraph |
| 虚拟视口无空间索引 | VirtualViewportController.ts:72-90 | 每次视口变化线性扫描全部节点 |
| removeOverlaps 最坏 O(n²) | LayoutController.ts:324-416 | 30次迭代 × 空间网格桶内两两检查 |
| processBatchQueue 边过滤 | DataController.ts:207,210 | 每批处理遍历所有剩余边，O(B×M) |

### 1.2 设计理念转变

从"一张图搞定"转向**可交互、可分层的图库**：每种图谱不是一次性展示全部数据，而是从概览层开始，用户按需深入到细节层。

## 3. 数据模型

```typescript
interface DiagramLayer {

  name: string;
  nodes: GraphNode[];
  edges: GraphEdge[];

  edgeIds: Set<string>;
}

interface AssembledDiagram {
  layered: LayeredDiagram;
  metadata: {
    totalNodes: number;
    totalEdges: number;
    maxDepth: number;
    rootNodes: string[];
  };
}
```

### 3.2 层级过滤逻辑

每个 Assembler 在 `assemble()` 中计算所有节点的 `depth` 属性，然后按层级切片：

```typescript
function sliceByLayer(allNodes, allEdges, layerDef): DiagramLayer {
  const filteredNodes = allNodes.filter(n => 
    layerDef.nodeFilter(n)
  );
  const filteredNodeIds = new Set(filteredNodes.map(n => n.id));
  const filteredEdges = allEdges.filter(e =>
    filteredNodeIds.has(e.source) && filteredNodeIds.has(e.target)
  );
  return { nodes: filteredNodes, edges: filteredEdges, ... };
}
```

### 3.3 层级定义

每种视图模式有自己的层级定义配置：

```typescript
const LAYER_DEFINITIONS: Record<ViewMode, LayerDefinition[]> = {
  inheritance: [

    { level: 1, name: '2层继承深度', nodeFilter: n => n.depth <= 2 },
    { level: 2, name: '完整继承树', nodeFilter: () => true },
    { level: 3, name: '成员详情', nodeFilter: () => true }, // 特殊：基于选中节点
  ],
  // ... 其他视图模式
};
```

## 4. Assembler 改造

### 4.1 改造原则

- 每个 Assembler 的 `assemble()` 方法仍然返回完整的 nodes/edges（L2 层数据）
- 新增 `buildLayers()` 方法，基于完整数据切片生成所有层级
- `depth` 属性已在现有 Assembler 中计算，直接复用
- L3 层（成员详情）通过节点展开机制实现，不在 Assembler 中处理

### 4.2 InheritanceAssembler 改造

现有代码已计算 `depth`、`isRoot`、`descendantCount`。改造只需新增：

```typescript
buildLayers(assembledNodes, assembledEdges): DiagramLayer[] {
  return [
    sliceByLayer(assembledNodes, assembledEdges, {
      level: 0, name: '根接口概览',
      nodeFilter: n => n.depth === 0
    }),
    sliceByLayer(assembledNodes, assembledEdges, {
      level: 1, name: '2层继承深度',
      nodeFilter: n => n.depth <= 2
    }),
    sliceByLayer(assembledNodes, assembledEdges, {
      level: 2, name: '完整继承树',
      nodeFilter: () => true
    }),
  ];
}
```

### 4.3 CallGraphAssembler 改造

现有代码已计算 `depth`、`isEntry`。改造类似，按 depth 切片：

- L0: `depth === 0`（入口函数）
- L1: `depth <= 2`（入口 + 2层调用）
- L2: 全部

### 4.4 PackageAssembler 改造

现有代码已计算 `depth`、`isRoot`。按目录层级切片：

- L0: `depth === 0`（顶层包）
- L1: `depth <= 1`（顶层 + 子包）
- L2: 全部

### 4.5 ClassAssembler 改造

现有代码已计算 `depth`。按类层级切片：

- L0: 按包分组，每组创建一个包概览节点
- L1: 包内类列表
- L2: 完整类关系图

### 4.6 DependencyAssembler（新增）

当前依赖图没有专用 Assembler，直接使用原始数据。需要新增：

- L0: 目录级依赖（聚合同目录间的边）
- L1: 文件级依赖
- L2: 模块级依赖
- L3: 具体导入语句

### 4.7 代码图谱分层

代码图谱已有聚类机制（directory → file → function），分层与聚类层级对应：

- L0: directory 聚类（顶层目录）
- L1: file 聚类（文件分组）
- L2: function 聚类（全部节点）
- L3: 选中函数 → 微观图谱

```typescript
setViewMode: (viewMode) => {
  // 查缓存
  const cached = layeredDiagrams.get(viewMode);
  if (cached) {
    const layer = cached.layers[cached.currentLayer];
    set({ viewMode, currentLayer: cached.currentLayer, ... });
```

### 5.3 新增 setLayer 方法

```typescript
setLayer: (layer: number) => {
  const diagram = layeredDiagrams.get(viewMode);
  if (!diagram || layer < 0 || layer >= diagram.layers.length) return;
  const layerData = diagram.layers[layer];
  const result = computeClusteredGraph(layerData.nodes, layerData.edges, ...);
  set({ currentLayer: layer, nodes: result.nodes, edges: result.edges });
}
```

## 6. 渲染层优化（方案 C）

### 6.1 四叉树空间索引

替代 VirtualViewportController 的线性扫描：

```typescript
class QuadTree {
  insert(node: CyNode, position: { x, y }): void;
  query(bounds: { x1, y1, x2, y2 }): CyNode[];
  remove(nodeId: string): void;
  update(nodeId: string, newPosition: { x, y }): void;
}
```

- 节点添加/移除时同步更新四叉树
- 视口变化时用 `query(viewBounds)` 获取可见节点，O(log n)
- 布局完成后批量更新四叉树

### 6.2 LOD 渲染

基于 zoom 级别自动切换渲染细节：

| zoom 范围 | 渲染内容 | 样式策略 |
|-----------|----------|----------|
| < 0.2 | 仅色块（无标签） | `label: ''`, `width: 8`, `height: 8` |
| 0.2 - 0.5 | 形状 + 简短名称 | `label: truncatedName`, `width: 20` |
| 0.5 - 1.0 | 形状 + 完整名称 | `label: fullName` |
| > 1.0 | 完整 UML 标签 | `label: umlLabel` |

实现方式：在 StyleController 中监听 zoom 变化，动态切换样式规则。

### 6.3 DataController 增量更新优化

区分结构变化和数据变化：

```typescript
updateData(nodes, edges) {
  const structuralChange = hasStructuralChange(nodes, edges);
  const dataChange = hasDataChange(nodes, edges);

  if (structuralChange) {
    // 全量重建（节点/边的增删）
    this.fullRebuild(nodes, edges);
  } else if (dataChange) {
    // 增量属性更新（只更新变化的节点属性）
    this.incrementalUpdate(nodes, edges);
  } else {
    // 无变化，跳过
    return;
  }
}
```

`hasStructuralChange`：检查节点/边 ID 集合是否变化（O(n)）
`hasDataChange`：检查节点属性是否变化（O(n×k)，但只比较关键属性）

### 6.4 渐进式渲染

```typescript
class ProgressiveRenderer {
  renderVisibleFirst(): void {
    const visibleNodes = quadTree.query(currentViewport);
    // 第一帧：渲染可见节点
    this.cy.batch(() => {
      visibleNodes.forEach(n => this.showNode(n));
    });
    // 后续帧：逐步渲染外围节点
    requestIdleCallback(() => {
      this.renderRemaining();
    });
  }
}
```

## 7. 缓存层

### 7.1 Assembler 结果缓存

```typescript
class DiagramCache {
  private cache: Map<string, LayeredDiagram> = new Map();

  get(viewMode: ViewMode, dataHash: string): LayeredDiagram | null {
    return this.cache.get(`${viewMode}:${dataHash}`) ?? null;
  }

  set(viewMode: ViewMode, dataHash: string, diagram: LayeredDiagram): void {
    this.cache.set(`${viewMode}:${dataHash}`, diagram);
  }

  invalidate(viewMode?: ViewMode): void {
    if (viewMode) {
      for (const key of this.cache.keys()) {
        if (key.startsWith(viewMode)) this.cache.delete(key);
      }
    } else {
      this.cache.clear();
    }
  }
}
```

### 7.2 聚类结果缓存

```typescript
class ClusterCache {
  private cache: Map<string, ClusterResult> = new Map();

  get(nodesHash: string, edgesHash: string, level: ClusterLevel, expanded: string): ClusterResult | null {
    return this.cache.get(`${nodesHash}:${edgesHash}:${level}:${expanded}`) ?? null;
  }
}
```

### 7.3 数据哈希计算

使用快速哈希函数（如 xxHash）计算 nodes/edges 的哈希值，用于缓存键：

```typescript
function computeDataHash(nodes: GraphNode[], edges: GraphEdge[]): string {
  // 基于节点/边 ID + 关键属性的简单哈希
  const nodeHash = nodes.map(n => `${n.id}:${n.type}`).join('|');
  const edgeHash = edges.map(e => `${e.id}:${e.source}:${e.target}:${e.type}`).join('|');
  return `${hash(nodeHash)}_${hash(edgeHash)}`;
}
```

## 10. 预期性能提升

| 场景 | 当前性能 | 预期性能 | 提升倍数 |
|------|----------|----------|----------|
| 首次加载（L0） | O(n+m) 全量 | O(5-20) 概览 | 50-100x |
| 视图切换（缓存命中） | O(n+m) assemble + cluster | O(1) 缓存读取 | ~∞ |

| 节点属性更新 | O(n+m) 全量重建 | O(1) 增量更新 | n+m x |
| 布局计算（L0） | O(n) 全量布局 | O(5-20) 小规模布局 | 50-100x |

## 11. 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| Assembler 改造引入 bug | 保持现有 `assemble()` 签名不变，新增 `buildLayers()` 方法 |
| 缓存内存占用 | 设置缓存上限（最多 5 个视图模式 × 4 层 = 20 个 LayeredDiagram），LRU 淘汰 |
| 四叉树实现复杂度 | 使用成熟库（如 `d3-quadtree`）而非自己实现 |
| LOD 切换闪烁 | 使用 Cytoscape 的 `batch()` 批量更新样式，避免逐节点更新 |
| 层级切换布局跳变 | 层级切换时保留已有节点位置，只对新出现节点做增量布局 |
