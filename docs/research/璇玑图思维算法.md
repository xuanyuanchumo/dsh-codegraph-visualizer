# 璇玑图规则与规范 v1.0

**——通用图空间路径枚举与索引维护规范**

---

## 一、范围与术语

本规范定义“璇玑图”作为一种**图空间路径计算范式**的规则语言、数据结构、算法契约与一致性要求。它不绑定具体图数据库或存储引擎，可作为独立算法库实现，也可作为宿主图系统的路径索引层。

| 术语               | 定义                                         |
| :----------------- | :------------------------------------------- |
| **图空间** \(G\)   | 承载语义单元的有限有向多重图                 |
| **路径规则** \(R\) | 定义“一种读法”的约束集合                     |
| **合法路径**       | 满足 \(R\) 全部约束的节点-边交替序列         |
| **物化路径**       | 被索引存储、可直接返回的合法路径             |
| **规范化**         | 在等价关系下取路径代表元，用于去重           |
| **不变量**         | 索引健康度的可检查条件，违反触发局部重组     |
| **增量更新**       | 图变化时只维护受影响的路径索引，而非全量重建 |

二维网格、DAG、知识图谱、状态机均为图空间的特例。

---

## 二、核心抽象

### 2.1 图空间定义

\[
G = (V,\ E,\ \Sigma,\ \tau,\ A)
\]

- \(V\)：有限节点集，节点 \(v\) 有唯一标识 \(id(v)\) 和标签 \(label(v)\)。
- \(E \subseteq V \times V\)：有向边集，允许多重边。
- \(\Sigma\)：边类型字母表。
- \(\tau: E \to \Sigma\)：边类型函数。
- \(A: V \to \mathcal{A}\)：节点属性映射，承载角色元数据（如 `role`、`tag`、`boundary`）。

**路径**定义为节点-边交替序列：

\[
p = v_0, e_1, v_1, e_2, \dots, e_k, v_k
\]

其中 \(e_i = (v_{i-1}, v_i) \in E\)，\(k\) 为路径的**边数**（长度）。

### 2.2 路径规则定义

\[
R = (S,\ \Phi,\ \Lambda,\ \Psi,\ \Omega,\ \Delta)
\]

| 分量        | 类型                            | 语义                                                        |
| :---------- | :------------------------------ | :---------------------------------------------------------- |
| \(S\)       | \(V \to \{0,1\}\)               | 起点谓词，\(S(v)=1\) 表示 \(v\) 可作为路径起点              |
| \(\Phi\)    | \(E \to \{0,1\}\)               | 边谓词，通常由边类型集合 \(\Sigma_R \subseteq \Sigma\) 诱导 |
| \(\Lambda\) | \([l_{\min}, l_{\max}]\)        | 长度区间（边数），\(0 \le l_{\min} \le l_{\max}\)           |
| \(\Psi\)    | \(V \to \{0,1\}\)               | 节点约束，路径上每个节点必须满足                            |
| \(\Omega\)  | \(\text{Path} \to \mathcal{O}\) | 输出映射，将路径转为标签串、子图、聚合值等                  |
| \(\Delta\)  | 枚举                            | 规范化策略：`none` / `reverse` / `canonical`                |

**合法性**：路径 \(p\) 是 \(R\)-合法的，当且仅当：

1. \(S(v_0) = 1\)；
2. \(\forall i,\ \Phi(e_i) = 1\)；
3. \(k \in [l_{\min}, l_{\max}]\)；
4. \(\forall i,\ \Psi(v_i) = 1\)。

**规则输出**：

\[
O_R(G) = \{\, \Omega(p) \mid p \text{ 是 } R\text{-合法路径，且取 } \Delta\text{-规范形式} \,\}
\]

### 2.3 规范化与等价

\(\Delta\) 定义路径集合上的等价关系 \(\sim_\Delta\)，输出取商集：

| 策略        | 等价定义                | 代表元         |
| :---------- | :---------------------- | :------------- |
| `none`      | 恒等                    | 原路径         |
| `reverse`   | \(p \sim p^{rev}\)      | 字典序较小者   |
| `canonical` | \(p \sim\) 任意循环旋转 | Booth 最小表示 |

规范化必须在**输出映射之后**、**去重之前**执行，保证同一等价类只出现一次。

### 2.4 规则组合代数

规则可组合，新增读法无需修改引擎：

| 运算                         | 定义                                  | 用途       |
| :--------------------------- | :------------------------------------ | :--------- |
| **并** \(R_1 \cup R_2\)      | 起点/边/节点谓词取析取，长度区间取并  | 多读法合并 |
| **交** \(R_1 \cap R_2\)      | 谓词取合取，长度区间取交              | 叠加约束   |
| **拼接** \(R_1 \cdot R_2\)   | \(p_1\) 终点 = \(p_2\) 起点，长度相加 | 分段读法   |
| **迭代** \(R^*\)             | 零次或多次拼接，受 \(l_{\max}\) 约束  | 重复模式   |
| **差** \(R_1 \setminus R_2\) | 合法于 \(R_1\) 但不合法于 \(R_2\)     | 排除模式   |

组合运算满足封闭性：结果仍是合法的 \(R\)。

## 三、规则规范

### 3.1 规则声明格式

规则以声明式结构描述，与执行引擎解耦：

```yaml
rule:
  name: "horizontal_5"
  version: 1
  start:
    role: "row_start"          # 起点谓词：节点属性匹配
  edges:
    types: ["H"]               # 边类型集合 Σ_R
  length:
    min: 5
    max: 5
  nodes:
    require: ["in_grid"]       # 节点约束：所有节点须满足
    forbid: ["void"]
  output:
    type: "label_concat"       # 输出映射
  normalize: "none"            # Δ 策略
```

### 3.2 约束类型规范

| 约束类别         | 表达方式                         | 语义                             |
| :--------------- | :------------------------------- | :------------------------------- |
| **起点约束**     | `start.role` / `start.predicate` | 只有满足条件的节点可作为 \(v_0\) |
| **边类型约束**   | `edges.types`                    | 只允许 \(\tau(e) \in \Sigma_R\)  |
| **边属性约束**   | `edges.where`                    | 边权重、方向等附加条件           |
| **长度约束**     | `length.min/max`                 | 边数闭区间                       |
| **节点角色约束** | `nodes.require`                  | 路径上每个节点必须满足           |
| **节点禁入约束** | `nodes.forbid`                   | 路径上不允许出现的节点属性       |
| **重复约束**     | `nodes.simple: true`             | 是否允许重复节点（简单路径）     |
| **输出约束**     | `output.type`                    | 标签拼接 / 子图导出 / 聚合       |
| **规范化策略**   | `normalize`                      | `none` / `reverse` / `canonical` |

### 3.3 规则版本与热插拔

- 每条规则有唯一 `name` 和单调递增 `version`。
- 规则注册后进入 `RuleRegistry`，**不立即物化**；首次查询或显式 `eager` 标记时物化。
- 规则更新（同 `name` 新 `version`）时，旧版本索引标记为 `deprecated`，新查询走新版本，旧版本索引在无引用后异步回收。
- 规则删除时，其索引进入 `stale`，按不变量阈值批量回收。

### 3.4 规则的静态校验

注册时执行以下校验，失败则拒绝注册：

1. \(\Sigma_R \subseteq \Sigma\)（边类型必须存在于图空间）。
2. \(0 \le l_{\min} \le l_{\max}\)。
3. 若 `nodes.simple: true` 且 \(l_{\max} > |V|\)，告警（长度超过简单路径上限）。
4. `output.type` 必须是已注册的输出映射器。
5. `normalize` 必须是已注册的规范化策略。

## 四、数据结构规范

### 4.1 图存储 `GraphSpace`

| 结构        | 类型                | 用途                     | 复杂度           |
| :---------- | :------------------ | :----------------------- | :--------------- |
| `nodes`     | `Map<ID, Node>`     | 节点属性查询             | \(O(1)\)         |
| `outAdj`    | `Map<ID, Edge[]>`   | 出边遍历                 | \(O(\deg^+(v))\) |
| `inAdj`     | `Map<ID, Edge[]>`   | 入边遍历（前缀枚举必需） | \(O(\deg^-(v))\) |
| `edgeMap`   | `Map<"u->v", Edge>` | 边类型查询               | \(O(1)\)         |
| `version`   | `int`               | 全局版本号，单调递增     | —                |
| `changeLog` | `ChangeEvent[]`     | append-only 变更日志     | —                |

**契约**：`inAdj` 是前缀枚举的必要条件，不可省略；`edgeMap` 在多重边场景下需支持 `Map<"u->v->etype", Edge>`。

### 4.2 路径索引 `PathIndex`

每个规则维护一套索引：

| 结构          | 类型                                    | 用途                                |
| :------------ | :-------------------------------------- | :---------------------------------- |
| `startIndex`  | `Map<startNode, Map<len, PathEntry[]>>` | 按起点+长度分桶，加速查询与后缀匹配 |
| `endIndex`    | `Map<endNode, Map<len, PathEntry[]>>`   | 按终点+长度分桶，加速前缀匹配       |
| `hashIndex`   | `Map<hash, PathEntry>`                  | 规范化去重                          |
| `edgeToPaths` | `Map<"u->v", Set<hash>>`                | 删除时定位经过该边的路径            |
| `counters`    | `{total, stale}`                        | 增量维护，不变量检查 \(O(1)\)       |

**长度分桶的必要性**：`onEdgeAdded` 需要按 `len(pre) + 1 + len(suf) ∈ [l_min, l_max]` 配对，分桶后只遍历合法长度组合，避免全笛卡尔积。

### 4.3 路径条目 `PathEntry`

```typescript
interface PathEntry {
  nodes: ID[]              // 节点序列，用于前缀/后缀拼接
  hash: string             // Δ-规范形式的指纹
  version: number          // 生成时的图版本
  stale: boolean           // 惰性失效标记
  _labels?: string         // 惰性构建的标签串，首次查询时缓存
}
```

**契约**：`nodes` 必须存完整序列（拼接需要）；`_labels` 惰性构建，长尾路径不付出字符串成本；`hash` 必须基于 `Δ`-规范形式计算。

### 4.4 不变量定义

| 编号   | 不变量                                                       | 检查方式                     | 违反动作                     |
| :----- | :----------------------------------------------------------- | :--------------------------- | :--------------------------- |
| **I1** | 边类型覆盖：\(\Sigma_R\) 中每类边至少出现在一条物化路径中    | 遍历 `hashIndex` 统计覆盖    | 对缺失类型采样节点做局部物化 |
| **I2** | 角色覆盖：`nodes.require` 中每种角色至少出现在一条物化路径中 | 同上                         | 角色索引局部重建             |
| **I3** | 深度均衡：各边类型的平均路径长度差 ≤ \(\theta_{depth}\)      | 按类型聚合长度均值           | 对偏离类型触发局部重组       |
| **I4** | 失效比例：`stale / total ≤ θ_stale`                          | `counters` 增量读取 \(O(1)\) | 批量重建 stale 条目          |
| **I5** | 版本一致性：`PathEntry.version ≤ GraphSpace.version`，且删除的边不出现在非 stale 路径中 | 抽样校验                     | 标记不一致条目为 stale       |

**阈值建议**：\(\theta_{stale} = 0.3\)，\(\theta_{depth} = 3\)。阈值可配置，不变量是**启发式触发条件**而非硬性正确性保证——违反只导致性能退化，不导致错误输出。

## 五、算法规范

### 5.1 静态全量枚举 `enumerate(G, R, S)`

```
输入: 图 G, 规则 R, 起点集 S
输出: R-合法路径的规范形式集合

1. result ← ∅, seen ← ∅
2. for each s ∈ S where S(s)=1:
3.     DFS(s, [s], 0)
4. DFS(node, path, depth):
5.     if depth ≥ R.l_min and Ψ(node)=1:
6.         entry ← makeEntry(R, path)
7.         if entry.hash ∉ seen:
8.             seen.add(entry.hash); result.add(entry)
9.     if depth = R.l_max: return
10.    for each e=(node→nxt) ∈ G.outAdj[node]:
11.        if Φ(e)=1 and Ψ(nxt)=1 and (not simple or nxt ∉ path):
12.            DFS(nxt, path+[nxt], depth+1)
```

**复杂度**：最坏 \(O(b^{l_{\max}})\)，输出敏感时为 \(O(|O_R| \cdot L)\)。约束越强，剪枝越有效。

### 5.2 增量边插入 `onEdgeAdded(e)`

```
输入: 新边 e=(u,v,etype)
输出: 新增的物化路径

1. for each rule R where etype ∈ Σ_R:
2.     preBuckets ← endIndex[u]        # 按长度分桶
3.     sufBuckets ← startIndex[v]
4.     for (preLen, prefixes) in preBuckets:
5.         for (sufLen, suffixes) in sufBuckets:
6.             if preLen+1+sufLen ∉ [l_min, l_max]: continue
7.             for pre in prefixes, suf in suffixes:
8.                 if not Ψ(v) or not all Ψ(suf.nodes): continue
9.                 nodes ← pre.nodes + [u,v] + suf.nodes
10.                entry ← makeEntry(R, nodes)      # 含 Booth 规范化
11.                if hashIndex.has(entry.hash): continue
12.                hashIndex.add(entry.hash, entry)
13.                startIndex[entry.nodes[0]][len].add(entry)
14.                endIndex[entry.nodes[-1]][len].add(entry)
15.                edgeToPaths[每对相邻节点].add(entry.hash)
16.                counters.total++
17.                newPaths.add(entry)
18. return newPaths
```

**复杂度**：\(O(|P_{in}| \cdot |P_{out}| \cdot L)\)，长度分桶后合法配对数量显著降低。哈希计算用滚动哈希降为 \(O(1)\) 组合，规范化用 Booth 算法 \(O(L)\)。

### 5.3 惰性边删除 `onEdgeRemoved(e)`

```
输入: 删除边 e=(u,v)
输出: 无（标记失效）

1. for each rule R where etype ∈ Σ_R:
2.     hashes ← edgeToPaths["u->v"]
3.     for h in hashes:
4.         entry ← hashIndex[h]
5.         if not entry.stale:
6.             entry.stale ← true
7.             counters.stale++
8. 若 counters.stale / counters.total > θ_stale:
9.     触发批量重建（见 5.5）
```

**复杂度**：\(O(k)\)，\(k\) 为经过该边的路径数，通过 `edgeToPaths` 直接定位，不遍历全索引。

### 5.4 查询与回退 `query(R, start)`

```
输入: 规则名 R, 起点 start
输出: 物化路径或 null（触发回退）

1. entries ← startIndex[start] 的所有长度桶
2. live ← entries.filter(not stale)
3. if live 为空 or stale 比例 > θ_stale:
4.     return null        # 回退宿主枚举
5. return live 的 labels
```

**契约**：返回 `null` 表示索引不可用，调用方必须回退到全量枚举或宿主查询，**不得返回 stale 条目**。

### 5.5 不变量检查与局部重组

**检查**：`check(R)` 按 I1–I5 逐项验证，返回违规列表。I4 通过 `counters` 读取，\(O(1)\)；I1–I3 需要遍历 `hashIndex`，\(O(|O_R|)\)，按变更事件批量触发，不在查询热路径。

**局部重组（“旋转”）** ：

```
rebalance(node, R):
1. nbrs ← {node} ∪ outAdj[node].targets ∪ inAdj[node].sources
2. 失效 nbrs 内所有 R 的索引条目
3. for start in nbrs where S(start)=1:
4.     DFS 限定在 nbrs 内，重新枚举
5. 批量插入新条目，更新 edgeToPaths 与 counters
```

**复杂度**：\(O(\deg(v) \cdot \bar{P})\)，只影响 1-hop 邻域，类比红黑树旋转的局部性。

### 5.6 存在性快速判定（NFA 乘积，可选）

当仅需判定“是否存在合法路径”时，将 \(R\) 编译为 NFA（状态数 \(|Q|\)，由长度区间和边类型决定），与图做乘积：

- 边插入：\(O(|Q|^2)\)，只更新受影响状态层。
- 查询：\(O(|Q|)\)，检查接受状态可达性。
- 与笛卡尔积物化组成混合索引：NFA 先判存在，存在才触发物化。

**适用**：规则多、图变化稀疏、查询以存在性为主（如工作流合法性验证）。

## 六、复杂度分析总表

| 操作           | 时间                                                      | 空间                             | 备注                  |
| :------------- | :-------------------------------------------------------- | :------------------------------- | :-------------------- |
| 图构建         | \(O(V+E)\)                                                | \(O(V+E)\)                       | 邻接表                |
| 静态全量枚举   | \(O(b^{l_{\max}})\) 最坏；\(O(\|O_R\| \cdot L)\) 输出敏感 | \(O(\|O_R\| \cdot L)\)           | 强约束下接近线性      |
| 增量边插入     | \(O(\|P_{in}\| \cdot \|P_{out}\| \cdot L)\)               | 增量 \(O(\|\Delta P\| \cdot L)\) | 长度分桶裁剪          |
| 惰性边删除     | \(O(k)\)，\(k\)=经过边路径数                              | \(O(1)\) 标记                    | 通过 edgeToPaths 定位 |
| 查询（命中）   | \(O(\|O_R^{start}\|)\)                                    | —                                | 直接返回索引条目      |
| 查询（未命中） | \(O(1)\) 判定 + 回退成本                                  | —                                | 回退宿主枚举          |
| 不变量检查     | \(O(1)\)（I4）/ \(O(\|O_R\|)\)（I1–I3）                   | —                                | I4 增量计数器         |
| 局部重组       | \(O(\deg(v) \cdot \bar{P})\)                              | —                                | 1-hop 邻域            |
| 规范化         | \(O(L)\)（Booth）                                         | —                                | 原 \(O(L^2)\)         |
| 哈希计算       | \(O(1)\) 组合（滚动哈希）                                 | \(O(L)\) 幂次表                  | 前缀/后缀哈希已知时   |
| NFA 存在性     | 插入 \(O(\|Q\|^2)\)，查询 \(O(\|Q\|)\)                    | \(O(V \cdot \|Q\|)\)             | 仅存在性              |

**核心结论**：增量维护的收益条件是 \(|\Delta P| \ll |O_R|\)，即图变化局部化。当变化无局部性时，增量成本接近全量重建，应降级为批式重建。

## 七、正确性与一致性规范

### 7.1 正确性条件

| 编号                | 条件                                                         | 保证                                             |
| :------------------ | :----------------------------------------------------------- | :----------------------------------------------- |
| **C1 可靠性**       | 索引返回的每条路径都是 \(R\)-合法的                          | 插入时逐条校验 \(\Phi, \Psi, \Lambda, S\)        |
| **C2 完备性**       | 任何 \(R\)-合法路径 \(p\)，若其所有边在索引版本后未变，则 \(p\) 的规范形式 ∈ 索引 | 增量枚举覆盖所有经过新边的路径；初始化时全量枚举 |
| **C3 增量正确性**   | `onEdgeAdded(e)` 后新增路径恰为“经过 \(e\) 的合法路径”的规范形式 | 前缀 × \(e\) × 后缀 的完备枚举                   |
| **C4 惰性删除安全** | 查询不返回 stale 条目；stale 条目最终被重建或回收            | 查询过滤 stale；不变量 I4 触发批量重建           |
| **C5 规范化幂等**   | \(\Delta(\Delta(p)) = \Delta(p)\)                            | Booth 算法与 reverse 比较均幂等                  |

### 7.2 一致性模型

- **最终一致性**：删除操作标记 stale 后，索引在下次查询或下次不变量检查时达到一致。
- **读己之写**：同一 Agent 的写入触发 `onEdgeAdded` 后，后续查询立即命中新索引。
- **版本单调性**：`PathEntry.version` 单调递增，旧版本条目在新版本图下被标记 stale。

### 7.3 失败模式与降级

| 失败               | 检测                  | 降级                           |
| :----------------- | :-------------------- | :----------------------------- |
| 索引未初始化       | `startIndex` 为空     | 回退全量枚举，异步初始化       |
| stale 比例超限     | I4 违反               | 回退宿主查询，触发批量重建     |
| 规则版本冲突       | 注册时校验            | 拒绝注册，保留旧版本           |
| 图与索引版本不一致 | I5 违反               | 标记不一致条目 stale，触发重组 |
| 路径数爆炸         | `newPaths.length > K` | Top-K 截断，保留高权重路径     |

## 九、参考实现结构

```
xuanji/
├── core/
│   ├── graph-space.ts        # GraphSpace, DynamicGraph

│   ├── path-index.ts         # startIndex/endIndex/hashIndex/edgeToPaths
│   ├── incremental.ts        # onEdgeAdded / onEdgeRemoved
│   ├── invariant.ts          # InvariantChecker (I1–I5)
│   └── rebalance.ts          # LocalRebalancer (rotate)
├── query/
│   ├── query.ts              # query + 回退契约
│   └── topk.ts               # Top-K 截断
├── registry/
│   └── rule-registry.ts      # 规则注册, 版本管理, 热插拔
└── adapter/
    └── host-adapter.ts       # 宿主图系统适配层（可选）
```

**模块契约**：

- `core` 不依赖任何宿主，纯函数式，可独立测试。
- `index` 依赖 `core`，维护索引状态。
- `query` 依赖 `index`，实现查询与回退。
- `registry` 管理规则生命周期。
- `adapter` 是唯一与宿主耦合的模块，负责变更事件转换与查询委托。

**最小可用实现**：`core/graph-space` + `core/path-rule` + `index/path-index` + `index/incremental` + `query/query`，即可支撑静态枚举与增量维护；`nfa`、`rebalance`、`topk` 按场景渐进引入。

## 十、规范符合性检查清单

实现本规范的系统应通过以下检查：

- [ ] 规则声明可通过静态校验（3.4）。
- [ ] 静态枚举满足 C1、C2、C5。
- [ ] 增量插入满足 C3，且长度分桶生效（合法配对才做笛卡尔积）。
- [ ] 删除操作通过 `edgeToPaths` 定位，复杂度 \(O(k)\) 而非 \(O(|O|)\)。
- [ ] 查询不返回 stale 条目（C4）。
- [ ] 不变量 I4 通过增量计数器 \(O(1)\) 读取。
- [ ] 局部重组只影响 1-hop 邻域。
- [ ] 规范化使用 Booth 算法（\(O(L)\)）。
- [ ] 路径条目 `labels` 惰性构建。
- [ ] 规则更新/删除不破坏已注册的其他规则索引。
