# 项目图谱与 AST 按需加载方案（优化版）

> **文档状态说明**：本文档包含已实现部分和设计目标部分。标注 `[已实现]` 的内容在项目代码中已有对应实现；标注 `[设计目标]` 的内容为规划中的功能，尚未在代码中实现。

---

## 一、核心原则

1. **加载粒度是“节点路径”，不是“层级”。**
2. **L0/L1/L2/L3 只是语义分类或深度标签，不是批量加载单位。**
3. **进入插件首屏只请求 bootstrap：根节点 + 顶层第一页 + URL 路径恢复所需的父节点切片。**
4. **用户操作哪个节点，才加载哪个节点的直接子级。**
5. **绝不因为到了某一层，就加载该层全部节点。**
6. **跨文件边先聚合，后按节点细化。**
7. **“一次最多两个函数”是展开预算，不是数据截断。**
8. **服务端全量索引不阻塞首屏；索引未就绪时先展示 L0 骨架，后台异步构建/增量构建。**
9. **结构层、行为层、运行时层独立加载、独立预算，不叠加到同一张图。**
10. **活跃渲染节点 ≤ 1500（动态聚类策略，根据屏幕宽度自适应 800/1200/1500），超出时折叠为聚合节点或分段加载。** `[已实现]` — 见 `src/shared/constants.ts` `DYNAMIC_CLUSTER`

## 二、正确与错误做法对比

| 场景 | 错误做法：层级全量加载 | 正确做法：按路径节点加载 |
|---|---|---|
| 首屏 | 加载所有顶层目录、所有项目节点 | 只加载根节点 + 首屏可见顶层节点第一页 + URL 恢复父节点切片 |
| 展开目录 `src` | 加载所有目录的子节点 | 只加载 `src` 的直接子节点 |
| 展开文件 `main.ts` | 加载所有文件的符号 | 只加载 `main.ts` 的 outline |
| 展开函数 `foo` | 加载文件内所有函数体 | 只加载 `foo` 的 AST / 源码 |
| 展开跨文件边 | 加载全项目所有边 | 只加载当前节点的聚合边或直接边 |
| URL 恢复 | 恢复所有同级节点 | 只沿 URL 路径逐级恢复父节点的子节点切片 |
| 行为层分析 | 全量调用图一次加载 | 先文件/模块级聚合，按需展开符号级 |
| 运行时排查 | 全量 Trace/日志一次加载 | 按时间窗口、请求 ID、Trace ID 加载 |

## 三、语义分层模型

> 以下分层只表示节点类型和语义层级，不表示加载顺序或加载批次。

### L0 项目顶层
- 内容：根节点、顶层目录、模块、最近打开项。
- 首屏策略：只加载根节点和第一页可见顶层节点。
- 不加载任何子节点。
- 顶层节点过多时，必须分页、搜索或聚合。
- 服务端索引未完成时，先返回已有骨架或空骨架，不阻塞首屏。

### L1 目录 / 文件
- 用户点击某个目录，才加载该目录的**直接子节点**。
- 用户点击某个文件，才加载该文件的 **outline**。
- 不加载同级其他目录的子节点，也不加载其他文件的符号。

### L2 文件符号大纲
- 点击文件后，只拉取该文件的 `outline`。
- 内容包括：类、接口、函数、方法、变量、常量、枚举等签名。
- 此时函数体默认不展开，只显示签名。

### L3 符号 AST / 源码
- 点击某个函数 / 方法，才拉取它的完整 AST 子树或源码片段。
- 不加载同文件内其他函数的函数体。
- “完整函数体最多展开 2 个”的控制点在这里。
- 同时受单符号 AST 节点预算约束（见第五节）。

### L4 跨文件边
- 默认只显示文件级聚合边，例如：`main.ts → utils.ts：12 条引用`。
- 用户展开某个文件或符号后，才请求该节点的直接边。
- 不一次性拉取全项目边。

## 四、按路径节点懒加载规则

### 1. Bootstrap（首屏） `[已实现]`
进入项目插件时，前端只发起一个 `bootstrap` 请求，合并返回：
- 根节点信息；
- 顶层节点第一页（例如 50 个，带 `total`）；
- URL 路径恢复所需的父节点切片；
- 索引状态（就绪 / 构建中 / 部分可用）。

不请求任何函数体、目录子级、符号级边。
静态资源、健康检查不计入业务子图请求。

> **当前实现状态**：首屏通过 `graphStore.ts` 的 `loadBootstrap()` 已实现 bootstrap 分片加载（见 `src/client/store/graphStore.ts:837-861`），`src/client/index.ts:231-242` 已接入 bootstrap 流程。`VirtualViewportController` 在节点数 > 5000 时启用视口裁剪。URL 恢复通过 `restoreFromUrl()` 逐级加载实现。

### 2. 展开目录 `[设计目标]`
用户点击 `src`：
- 请求：`GET /nodes/src/children?cursor=0&limit=50`
- 只返回 `src` 的直接子目录 / 文件。
- 同级其他目录的子节点请求数必须为 0。

### 3. 展开文件 `[设计目标]`
用户点击 `main.ts`：
- 请求：`GET /files/main.ts/outline`
- 只返回 `main.ts` 内的符号签名。
- 其他文件符号请求数必须为 0。
- 函数体默认不展开。

### 4. 展开符号 `[设计目标]`
用户点击函数 `foo`：
- 请求：`GET /symbols/foo/ast`
- 只返回 `foo` 的完整 AST 子树或源码片段。
- 同文件其他函数体请求数必须为 0。
- 完整函数体最多展开 2 个，其余保留签名占位。
- 若单符号 AST 节点数或源码行数超过预算，折叠为摘要或分段加载。

### 5. 跨文件边 `[部分已实现]`
- 默认只显示文件级聚合边。 `[已实现]` — 聚类后边聚合见 `cluster/index.ts`
- 展开文件或符号后，再请求该节点的直接边。 `[设计目标]`
- 支持分页、游标、阈值采样和"显示更多边"。 `[设计目标]`
- 聚合阈值建议：同一对文件间边数 > 20 时先聚合显示，展开后分页拉取明细。 `[设计目标]`

### 6. URL 恢复 `[设计目标]`
统一使用 `?expand=` 记录展开路径，节点 ID 使用稳定短 ID，例如：

```
?expand=d:src,f:main.ts,s:foo
```

- `d:` 目录，`f:` 文件，`s:` 符号。
- 完整状态可存 localStorage，URL 只存关键路径。
- 设置 URL 长度上限，超长时降级为仅恢复文件级。
- 符号 ID 失效时，降级到文件级恢复，并提示“部分展开已失效”。

恢复流程：
1. 加载根节点子节点切片，找到 `src`。
2. 加载 `src` 子节点切片，找到 `main.ts`。
3. 加载 `main.ts` outline，找到 `foo`。
4. 加载 `foo` AST。

每一步只加载当前父节点的直接子节点切片，不加载同级其他节点。

## 五、“一次最多显示两个函数”的优雅实现

不要写成“只返回两个函数，其他丢弃”。

正确语义：

> **完整展开预算 = 2 个函数体；其余函数保留签名占位，可一键展开或按调用链展开。同时受单符号 AST 节点预算约束。**

具体策略：

- 函数签名全可见：函数名、参数、返回类型都显示。
- 完整函数体默认只展开 2 个：优先选中节点、视口中心、最近交互、调用链上下游。
- 其余函数折叠为一行：`function foo(...) { ... } 展开`。
- 显示预算提示：`已展开 2/12 个函数`。
- 提供入口：“展开更多”“只看调用链”“展开全部（警告节点数）”。
- 虚拟滚动：即使有 100 个函数，也只渲染视口内几行。
- 按需替换：展开第 3 个时，自动折叠最早展开的非固定函数，保持活跃节点不暴涨。

### 单符号 AST 节点预算
- 单符号 AST 节点上限：例如 800。
- 单符号源码行数上限：例如 1500 行。
- 超限时显示“该函数过大，已折叠为摘要 / 分段加载”。
- 完整函数体预算 = 2 个，且每个都受单符号预算约束。

## 六、性能控制关键机制

### 1. 服务端
- 全量索引，但按需返回子图。
- **索引构建不阻塞首屏**：进入插件时，已有索引直接返回骨架；未完成则后台异步构建/增量构建，前端先展示 L0 骨架。
- API 围绕单节点设计：
  - `/bootstrap`
  - `/nodes/:id/children?cursor=...&limit=...`
  - `/files/:id/outline`
  - `/symbols/:id/ast`
  - `/edges?from=:id&scope=file|symbol&cursor=...`
- 支持分页、游标、ETag、版本号。
- 增量索引：文件变更只更新对应文件 / 符号，不重建全图。

### 2. 前端状态
- 维护：`expandedNodeIds`、`loadedChildrenByNodeId`、`pendingRequests`、`activeNodeCount`、`viewport`、`pinnedIds`。
- URL 统一使用 `?expand=d:src,f:main.ts,s:foo`。
- 使用稳定短 ID，例如 `projectId:fileId#symbolPath`，不要用绝对路径。
- 刷新时按路径逐级恢复，只恢复可见分支，不自动展开全部。

### 3. 渲染
- 活跃渲染节点 ≤ 1000：可见节点 + 预取占位节点。
- 超过时折叠为聚合节点，例如 `+ 38 个函数`。
- 使用 Canvas / WebGL 渲染，DOM 只做交互层。
- 局部布局：新节点加入时只做局部力导向布局，固定已有坐标，避免全图重排。
- 边聚合：跨文件边先聚合，展开后再拉明细。

### 4. 缓存 `[部分已实现]`
- 前端 IndexedDB 缓存 outline、AST、边。 `[部分已实现]` — `IndexedDBCache.ts` 已定义 `getOutline/setOutline/getAST/setAST/getEdges/setEdges` 方法，已接入 `expandNode` 调用链（见 `graphStore.ts` expandNode 中 fetchFileOutline/fetchSymbolAST 的缓存读写）
- 内存 LRU 缓存最近文件 / 符号。 `[已实现]` — 见 `src/client/cache/DiagramCache.ts`（LRU 10条）、`GraphCache.ts`（LRU 8条）
- 预取：鼠标悬停目录 / 文件时，预取下一级；**并发 ≤ 2，可取消，不预取函数体，预取节点不进入活跃渲染，也不进入 URL 恢复**。 `[设计目标]`

## 七、分层职责

| 层 | 职责 | 加载策略 | 独立预算 |
|---|---|---|---|
| 结构层 | 目录、文件、符号导航 | 首屏只顶层，按节点路径展开 | 活跃节点 ≤ 1000 |
| 行为层 | 调用图、依赖图、影响分析 | 独立面板，默认文件/模块级聚合，按需展开符号级 | 符号级边分页，单次 ≤ 500 |
| 运行时层 | Trace、日志、性能排查 | 独立面板，按时间窗口、请求 ID、Trace ID 加载 | 单次时间窗口 ≤ 5 分钟或 1000 条 |

三层不要同时叠加到一张图。切换层时替换子图，而不是追加节点。

## 八、主要风险与修正

1. **索引构建阻塞首屏**
   - 服务端索引未就绪时，前端先展示 L0 骨架，后台异步构建/增量构建，不阻塞首屏。

2. **URL 过长 / 状态模型不统一**
   - 统一用 `?expand=`，节点 ID 用短前缀。
   - 完整状态存 localStorage，URL 只存关键路径。
   - 设置长度上限，超长降级为文件级恢复。

3. **符号 ID 失效**
   - 索引版本变化时，降级到文件级恢复。
   - 提示“部分展开已失效”。

4. **懒加载延迟**
   - 预取一级 + 骨架屏 + 缓存。
   - 保证点击展开 < 100ms。

5. **预取失控**
   - 并发 ≤ 2，可取消。
   - 不预取函数体。
   - 预取不进入活跃渲染和 URL 恢复。

6. **边爆炸**
   - 文件级聚合边 + 阈值采样 + “显示更多边”。
   - 不一次返回所有跨文件边。
   - 行为层单次符号级边 ≤ 500。

7. **千级节点布局抖动**
   - 固定已有坐标，局部增量布局。
   - 必要时切换为层次布局 / 树布局。

8. **“最多两个函数”造成误解**
   - UI 必须明确：不是数据没有，而是按预算展开。
   - 提供“展开更多”入口。
   - 单符号 AST 节点预算同时生效。

9. **行为层 / 运行时层节点爆炸**
   - 行为层默认聚合，按需展开。
   - 运行时层按时间窗口、请求 ID、Trace ID 加载。
   - 三层切换时替换子图。

## 九、验收指标

- 首屏业务子图请求合并为 1 个 `bootstrap` 接口；静态资源、健康检查不计入。
- 首屏不请求任何函数体、目录子级、符号级边。
- 首屏 TTI < 1s，首屏节点 < 200，首屏边 < 300。
- 展开 `src` 只请求 `src` 的子节点，同级目录请求数 = 0。
- 展开 `main.ts` 只请求该文件 outline，其他文件请求数 = 0。
- 展开 `foo` 只请求 `foo` 的 AST，同文件其他函数体请求数 = 0。
- URL 恢复只加载路径上的父节点子节点切片，兄弟节点请求数 = 0。
- 目录 / 文件展开延迟 < 100ms，命中缓存 < 30ms。
- 活跃渲染节点 < 1500（动态自适应），DOM 节点 < 2000，FPS > 50。 `[已实现]` — 动态聚类见 `getDynamicMaxVisibleNodes()`
- 内存占用 < 200MB。
- URL 恢复成功率 > 99%。
- 完整函数体默认 ≤ 2 个，但签名可见率 100%。
- 单符号 AST 节点 ≤ 800，源码行数 ≤ 1500，超限折叠为摘要 / 分段加载。
- 行为层单次符号级边 ≤ 500；运行时层单次时间窗口 ≤ 5 分钟或 1000 条。

## 十、结论

该方案可以实现按需加载和优雅的节点控制，核心在于：

1. **服务端全量索引，前端只拉子图；索引构建不阻塞首屏。**
2. **目录 → 文件 → 符号 → AST 按路径节点逐级懒加载。**
3. **跨文件边先聚合后细化。**
4. **结构 / 行为 / 运行时分层隔离，各自独立预算。**
5. **“一次最多两个函数”定义为展开预算，而不是数据截断，并受单符号 AST 节点预算约束。**
6. **千级活跃节点用虚拟化、聚合、局部布局控制。**
7. **预取受控，不破坏按需原则。**

最关键的一条是：

> **进入插件首屏只请求 bootstrap：根节点 + 顶层第一页 + URL 路径恢复所需的父节点切片；之后用户操作哪条路径的哪个节点，才加载那个节点的直接子级。层只是语义分类，不是加载批次。**

这样就能彻底避免“某一级别全部加载”的歧义，启动时只加载顶层和 URL 中的展开路径，进入项目插件就不会再出现超长等待。
