## 1. 用户与画像（通用插件口径）

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| U1 全自主驱动者 | 任何项目上让 agent 循环长期跑 cycle，人只在熔断/审计介入 | 流程不中断；**系统会自己变得更可信（或及时降级）**；一切事后可审计 |
| U2 门禁审批人 | 门到达时判断"是否放行" | 证据包一眼可读；一键通过/驳回；驳回留痕进账本 |
| U3 流程观察者 | 打开 DSH 想知道"什么在进行、什么被阻塞、接下来触发什么" | 有向图实时状态视图；不读 markdown 就能回答三问（graph.md:25） |
| U4 流程调优者（新画像：想改进流程本身的人） | 觉得现有门太多/评估维度不合适/阈值太紧 | **过程补丁机制**：提案→评估→带内自动生效或人工批准→度量→回退 |
| U5 其他技术栈开发者（新画像：非 Node 项目） | Rust/Python/Go/Java 项目想用这套流程 | init 向导识别技术栈；无 Node 假设；命令手填兜底 |

## 2. 核心用户旅程（验收主线）

- **J1 首次安装（任意项目）**：装插件 → 在目标工作区 `anic_init` → 向导探测技术栈（package.json/Cargo.toml/pyproject.toml/go.mod/pom.xml…）生成 `.cycles/config.yml`（build/test/lint 命令可编辑确认）+ `workflow-graph.yaml`（默认图可裁剪）+ 带 version 字段的工件骨架 → 顶部出现 "ANIC 循环" 标签。
- **J2 日常观察**：标签内看到当前工作流有向图（节点着色=运行时状态）→ 点节点看产物与账本记录 → 时间线回看历史 cycle。
- **J3 门禁审批**：门到达 → 审批卡（证据包）→ 批准=写账本+状态机 advance；驳回=留痕回上游。
- **J4 自主循环**：agent 经工具/MCP 驱动 eval→gate-check→review→audit→advance 全链；熔断命中 → 降级 → UI 状态条变红。
- **J5 事后审计**：按 cycle 浏览 → 打开任一账本记录（approver/commit/evidence/前驱哈希）→ 一键全链校验。
- **J6 信任成长（新）**：连续 N 个 cycle 各门高质量通过 → 信任分上升 → **自主级在授权带内自动上调**（如 L2→L3），UI 显式提示"为什么升级"且可在 N 分钟内一键撤销。
- **J7 过程进化（新）**：复盘发现"性能门太频繁且从未拦截真问题" → U4/agent 发起过程补丁（假设+变更+度量计划+有效期）→ 带内自动生效或走人工门 → 后续 cycle 度量对比 → 无改善自动回退 + 留痕。
- **J8 降级自愈（新）**：连续 2 个 cycle G2 反复失败且 auto-fix 无改善 → 信任分下降 → **自主级自动降档（L4→L3）** + 熔断条件按原语义触发 → 降级原因进账本，人修复后可恢复。

## 3. 功能需求

### 3.1 流程运行时（GAP-4/5）

- **F1 (P0) workflow-graph 状态机服务**：解析工作区 `.cycles/workflow-graph.yaml` 为活状态机；`status/advance/checkStrict`；advance 三拒绝（门记录不匹配/重复推进/无已批准触发边）+ **不自动启动下游**；schema 带 `version` 字段（修 P-7）。
- **F2 (P0) 门禁账本**：读写门禁账本哈希链（append/verify）；**格式与既有技能逐字节兼容**（76-cycle 历史账本可直接续写，旧 `ledger.json` 惰性迁入 `legacy/` 只读留存）；物理布局按 F23 升级为分段只追加；新记录带 schema version；**补丁应用记录也走同一账本**（单一真相，F20 依赖）。
- **F3 (P0) 工具面注册**：`ctx.tools.register` 暴露流程工具族（init/status/advance/record/verify/eval-run/gate-check/audit/cycle-list/trust/patch/sweep/prune/index），effect+disposer 范式（本仓库 src/index.ts:52-62 先例）；MCP server 形态保留供宿主外 agent。
- **F4 (P1) 事件广播**：门到达/通过/驳回、cycle 开始/结束、熔断、自主级变更、补丁应用/回退 → `ctx.emit('dsh-anic/…')`。
- **F5 (P1) LLM 评审引擎（宿主面已证实，M0-②）**：经 `ctx.llm.stream` 实现 E1-E8/Q1-Q8 中 Tier-1 判不了的语义评审（结论+证据引用+置信度），**多角色真评审**（builder/checker/adversary 独立上下文，修 P-8）；宿主不保证结构化输出，故必须是**闭合 JSON 协议 + 本地严格校验 + 失败即 `doubt`**（官方 `dsh-experimental-auto-review` 范式，见 [spike/host-llm-service.md](spike/host-llm-service.md) §3.1）；服务缺失或按错误码不可用时回落启发式（去中文假设化为通用版，修 §2.5 通用性缺陷）。
- **F39 (P0) LLM 接入形态与降级**：`'llm'` **不得**进入硬 `inject` 数组（缺适配器的宿主会让整个插件不激活）；用存在性探测 + 增量 `ctx.inject(['llm'], cb)`；provider/model **成对**配置，缺一回落会话路由；调用必须带超时（`AbortSignal`）与调用前留痕（`{provider, model, promptDigest, evidenceIds}` 入账本）；按 `NO_ADAPTER`/`INVALID_CREDENTIAL`/`QUOTA*` → 降级、`CONTEXT_WINDOW_EXCEEDED` → 缩证据重试一次、`EMPTY_RESPONSE`/结构非法 → `doubt` 分派；**不得**用 `purpose` 做归因（宿主闭合枚举 `'compaction'|'session-title'`）。
- **F6 (P0) 自主级与熔断**：L1-L4 生效语义与 SKILL.md 一致；8 熔断条件 + 先修复后降级；band-history 接入降级决策（修 P-2）。

### 3.2 通用性（GAP-8，修 P-6）

- **F7 (P0) init 向导多栈探测**：识别 package.json/Cargo.toml/pyproject.toml/go.mod/pom.xml/build.gradle/Makefile/CMakeLists.txt 等并预填 build/test/lint 命令；探测不到 → 手填表单；全流程不假设 Node。
- **F8 (P0) per-project 配置**：评估维度注册表（E/Q 维可增删改权重，per-project 覆盖默认集，修 P-5）；门角色/阈值可配置；一切配置可导出为 `.cycles/` 内声明式文件随仓库走。

### 3.3 可视化（GAP-2）

- **F9 (P0) 工作流图视图**：conversation.view 顶部标签渲染 workflow-graph 有向图；四类节点四色；状态着色；触发边指示。
- **F10 (P0) 节点详情**：产物清单 + 关联账本记录 + 最近评估摘要。
- **F11 (P1) Cycle 时间线**：横向时间线 + 门通过序列 + 工件跳转。
- **F12 (P1) 账本查看器**：链表格 + 验证徽章 + 记录详情。
- **F13 (P2) 代码图深链**：探测 codegraph-visualizer 在场才显示入口（only-ON，无痕隐藏）；纯可选增强，任何项目无此插件时完全正常。
- **F14 (P1) 进化可视化**：信任分曲线（按门角色分线）、自主级变更时间点、补丁生命周期状态（proposed/applied/measuring/kept/reverted）在时间线上一屏可见。

### 3.4 门禁体验（GAP-3）

- **F15 (P0) 审批卡**：证据包（diff 摘要/评估摘要/账本链尾）；批准/驳回**只写账本**，状态机消费账本推进（单一真相）；CLI/MCP 双通道写同一账本互见。
- **F15a (P1) gen2 增强**：userQuestionPanels 在场时审批卡升级为宿主问答面板，缺席静默留在标签内。

### 3.5 动态自主进化（GAP-6/7 核心，修 P-1..P-4）

> 设计前提：进化的对象**只有流程本身**（图形状/阈值/维度权重/自主级），**永不**是代码工件；护栏见 X8-X10 与 03 文档"进化宪法"。

- **F16 (P1) 信任模型**：按门角色（product_owner/engineer/code_owner/release_manager/oncall…）维护信任分；种子 = multi-agent-gate trustScore（兼容既有 ≥70% 语义）；**事件驱动累积**：门高质量通过 +、评审驳回/返工 −、熔断 −−、auto-fix 无改善 −；**滞回**：升降都需要连续 N 次证据，防止单次抖动；**非对称**：降分快、升分慢（错误成本 > 机会成本，沿用本仓库"宁多 200 不误 304"的偏置哲学）。
- **F17 (P1) 自主级动态升降**：信任分映射到**授权带内**的自主级调整（如 L2↔L3）；**带外与 L4 的进入/离开必须人类显式授权**（宪法）；升降都：写账本 + UI 显式说明原因 + **一键撤销窗口**（默认 30 分钟内人类可无理由回退）；8 熔断条件优先级永远高于信任分（熔断即降级，不受信任分阻拦）。
- **F18 (P1) 过程补丁生命周期**：复盘/评估/审查发现 → 结构化补丁提案 `{id, hypothesis, change: {graph|thresholds|dimensionWeights}, metricsPlan, expiry}` → 资格检查（是否触及宪法约束 → 拒绝）→ **安全带判定**（带内=可自动应用，带外=走对应人类门）→ 应用并**写账本** → 度量期（按 metricsPlan 对比前/后 cycle 指标）→ 判定 keep（转正）或 **auto-revert**（恢复前一版工件 + 账本留痕 revert 记录）。补丁模板默认源自 retrospectives/tech-debt 工件的结构化抽取（修 P-3 复盘不回流）。
- **F19 (P2) 阈值/维度权重自适应**：band-history（Western Electric 漂移检测，修 P-2「不在自动化链上」）+ 评估历史统计 → 在安全带内微调 G 门阈值与维度权重；每次调整带度量计划与有效期，机制同 F18。
- **F20 (P0) 进化审计**：一切进化动作（信任分变化/自主级升降/补丁应用回退）**追加进同一门禁账本**，含触发证据与决策依据；`anic_trust` / `anic_patch` 工具支持查询与人工覆盖。
- **F21 (P2) 进化提案集市（跨项目复用）**：补丁可导出为匿名化模板（不含项目数据）→ 其他项目 init 时可选用"经过验证的流程模板"；单机实现（本地模板目录），不做网络服务。
- **F22 (P1) 进化防抖与暂停**：同一参数 30 天内被 revert 两次 → 加入冻结名单（需人类解冻）；任何时刻可"暂停进化"（one switch），暂停期间信任分只降不升、补丁只能提案不能自动应用。

### 3.6 产物规模与生命周期（GAP-9，治「多次调用产生大量产物」）

> 完整设计见 [08-产物规模与生命周期治理.md](08-产物规模与生命周期治理.md)；实测基线：264 文件 / 1.55 MB / 57 cycle 目录（其中 12 个空目录）/ 单文件数组账本 56 条。

- **F23 (P0) 分段只追加账本**：`.cycles/gates/head.json`（O(1) 小文件：chainHead/segCount/entryCount/checkpointSeq）+ `seg-NNNNNN.jsonl`（每行一条，段满 1000 条开新段，链在段内与跨段连续）。追加 O(1) 写，与总量无关；`verifyIncremental` 只读末段；旧 `ledger.json` 惰性迁移到 `legacy/` 只读留存（N2 零迁移在物理层的落地）。**单文件数组方案被否决**：O(n²) 累计写入，10k 条 ≈ 44 GB（实测推导）。
- **F24 (P0) 证据外置与内容寻址**：v2 记录只留 `detailSummary`（≤280 字符硬上限）+ `detailRef` 指针 + `detailDigest`（sha256）——治实测「末条 detail 4.4 KB / 占全链 9%」的无界字段；相同 digest 的证据只存一份（治重复调用产生重复证据）；正文按需读、单证据 >64 KB 或含凭据 ⇒ 拒绝并熔断。
- **F25 (P0) 幂等键**：每条 v2 记录带 `requestId = <宿主 runId>-<序号>`；append 前查重，命中返回既有记录——宿主崩溃重投/事件重发/用户双击都产生重复调用，账本是唯一真相，重复即污染。
- **F26 (P0) 索引与目录白名单**：`index.jsonl`（cycle→段范围/字节/文件数/mtime/closed）+ `.index/digests.jsonl`；只索引 schema 声明目录集，**其余标 unmanaged：不索引、不归档、不删除**（实测 `.cycles/` 根混入 probe-*.mjs / commit-*.txt / dsh-asar/ / j0probe/ 等研究残留，是用户资产，插件无权处置）；索引是派生物，丢了可全量重建。
- **F27 (P1) 分层归档（只移动不删除）**：热 20 cycle 原位 → 温原位仅索引 → 冷（>60 cycle 或 >90 天）移入 `archive/` + `archive/index.jsonl`；归档不断链（链与归档策略完全解耦）；`anic_prune` 默认 `--dry-run`，真删需 `--apply`，永不删 `gates/ledger*`/`archive/index.jsonl`/任何 unmanaged 文件。
- **F28 (P1) 游标分页与存储预算**：HTTP 游标分页 `?cursor=<segNo:lineNo>&limit=50`（上限 500）+ `nextCursor`/`totalHint`；单 cycle 产物 >256 KB 告警（实测近期 74 KB）；`.cycles/` 总占用超 `artifactBudgetMb`（默认 512）告警 + 建议归档，**绝不自动删**。
- **F29 (P2) 工件健康报告 `anic_sweep`**：只读扫描（空 cycle 目录——实测 12 个、空子目录、超龄未闭合 cycle、unmanaged 残留计数/字节），全部只报告不处置；处置由人类决定（删目录 or 标 abandoned）。
- **F30 (P2) 门通过记录去重**：`gates/G{n}-{ts}.md` 平铺文件改为按月分桶（治实测「门通过 N 次 = N 个文件同目录」，1k cycle = 4k 文件同目录 NTFS 枚举退化）；内容寻址去重。

### 3.7 结构契约族（GAP-10，复评轮新增，治 S-1..S-11 的复发机制）

> 完整设计与取证见 [09-结构优化与逻辑重构设计.md](09-结构优化与逻辑重构设计.md)。本族的需求编号对应 09 的 S 缺陷与 INV 不变量；**它们不是新功能，是让前面 38 条需求不会静默失效的骨架**。

- **F31 (P0) 契约单一事实来源（L0）**：路径/文件名/维度词表/门禁表/记录形状全部在 `contracts/` 一处定义、冻结、被引用；治 S-1（11 个文件各写一遍配置路径）、S-2（E1-E8 双词汇表）、S-9。**INV-10/INV-11**。
- **F32 (P0) 唯一配置 loader + schema 校验**：一个 loader 把 `.cycles/config.yml` 解析为类型化对象；**未知键拒绝**、**缺必填报错**、**禁止默认值兜底**（治 `band-detector.mjs:224` 的 `: 100` 把配置错误伪装成正常）；配置文件带 `schemaVersion`；旧文件惰性迁移。治 S-1/S-8。
- **F33 (P0) 效果即记录（Post-Verify）**：一切"声明式动作"（改配置/降级/应用补丁/归档移动）必须返回**观察值** `{intent, observed, ok}`，写入后回读断言；`observed !== intent` 即失败，且**不得**写"已完成"记录。治 **S-7（未降级但记录称已降级）**、S-5。**INV-16**。
- **F34 (P0) 未知标识符响亮失败**：未知维度 / 未知门禁 / 未知配置键 / 非法参数一律非零退出并列出合法值（采用 `multi-agent-gate.mjs:542-543` 已有的正确形态为范式）；治 S-11。**INV-19**。
- **F35 (P0) 一账本 + N 纯投影**：一切状态变更 = 一次账本追加；`workflow-state.json` 降为 checkpoint；报告/时间线/图/信任曲线全部是 `(contracts, ledger, artifacts)` 的**纯函数投影**；**派生可重算**（删掉派生文件后能重建等价内容）。治 S-4（5 副本）、S-10（band-history 独立写者）。**INV-13/INV-18**。
- **F36 (P1) 报告投影化，取消文本接口**：`项目评估报告.md`/`审计日志.md`/`交付清单.md`/`multi-agent-gate-report.md` 一律由投影生成；`auto-fix-loop` 不再正则解析中文 markdown（`/失败[：:]\s*(\d+)/`），改为消费结构化失败事实 `failures: [{id,message,severity}]`。治 S-8，并**解除 i18n 与脚本通信的耦合**（N7 因此才可能真正落地）。**INV-17**。
- **F37 (P1) 端口化：同一引擎三个适配器**：`DshHostPort`（tools/routes/slots）/ `CliPort`（16 个脚本语义的映射）/ `McpPort`（15 个工具）——技能脚本语义**不消失，降级为 CliPort 子命令**，而非各自独立的程序。这是通用性（N9）与可移植性的结构保障，也是 S-1/S-8 复发机制被取消的方式。
- **F38 (P0) 执行契约测试 + 守卫**：每个端口至少一条"调用→工件"执行用例（**INV-12**）；源码级守卫扫描裸字面量/文本协议/中文正则，且**必须带反向自检**（防止守卫自身正则写错后永久为绿）、**不得匹配自身样例字面量**、**必须同时扫写侧**。治 S-3——S-3 是其余 10 项缺陷的存活条件。

## 4. 非功能需求

- **N1 兼容 (P0)**：**ANIC 实测不声明 peerDeps**（`dsh-anic/package.json` 无该字段 ⇒ 唯一强制门必过，cycle-92 核对）；无 `engines.dsh`；manifestVersion 1；platform 'web'；exports["./client"]；icon ≤256KiB；多代策略 = only-ON 探测。父工程参考范围（cycle-92 抬窗）= `^0.2.0-rc.2||^0.3.0-rc.2`。
- **N2 工件兼容 (P0)**：`.cycles/` 目录结构、config.yml 键名、workflow-graph.yaml schema、ledger.json 哈希链格式零迁移；**新增字段一律向后兼容**（旧工件可被新版读，新工件带 version）。哈希链的规范化形式（键序/空白/字段集）必须**复现既有账本 hash**（M0-③ 反推交付 `ledger-canonical-form.md`，05 §3.2），否则续写第一条即断链。
- **N3 性能 (P1)**：76-cycle 量级图渲染首帧 <1s；账本校验 500 记录 <500ms；文件监听去抖 ≥500ms；**规模预算（08 §4）**：10k 条账本 `verifyIncremental` <100ms、10k cycle 时间线首屏 <100ms、冷启动（不扫 archive）<2s、UI 账本首屏 50 条 <100ms。
- **N4 可靠性 (P0)**：读写失败 → 功能降级 + 明确告警，绝不静默丢账本写；账本写前备份+fsync；补丁 revert 必须原子（先写 revert 记录再改工件，崩溃后可续）；**账本 append 是 O(1) 写**（分段布局）；**幂等：同一 requestId 至多一条记录**（INV-6）。
- **N5 安全 (P0)**：H1-H4 内建；真实用户数据/明文凭据无隔离 = 熔断；HTTP allowedOrigins 白名单。
- **N6 测试 (P0)**：覆盖率门禁；账本哈希链 mutation 测试；状态机非法转移全枚举；**信任模型/补丁生命周期用 76-cycle 历史数据做回放测试（M0-④ 仿真固化为准出测试）**；守卫测试带反向自检。
- **N7 i18n (P1)**：locale/en.json+zh.json，en 为锚；UI 全走 t()。
- **N8 观测 (P1)**：scoped() logger；门禁/熔断/降级/进化事件结构化日志。
- **N9 通用性 (P0)**：任何代码路径不得假设 Node/npm/中文/React；技术栈探测表可扩展；英文项目全流程可用（启发式降级版也要去中文假设）。
- **N10 Schema 版本化 (P0)**：所有插件产出的工件（含新增 trust-state/patch log/head.json/index.jsonl）带 `version` 字段；读取旧版本按迁移规则升读，永不原地改写旧文件格式。**账本记录形状是唯一例外且只在 M2 定死一次**（宪法条款 7 / F23-F25）：因为它是唯一"事后修改即破坏全部已写链"的数据结构。
- **N11 规模与保留 (P0)**：`.cycles/` 总占用默认预算 512 MB，超阈告警（永不自动删）；归档 = 移动 + 索引，**真相源（账本链 / head.json / index.jsonl / archive/index.jsonl）永不删除**；unmanaged（白名单外）文件永不触碰；追加 N 条累计写入 ≤ N × 1 KB。
- **N12 结构性不变量常驻 (P0)**（复评轮新增）：**INV-10..INV-19**（09 §7）全部转成常驻测试，不退化为一次性检查；其中**涉及安全的 INV-14（信任分可追溯且空证据不得 auto-approve）/ INV-16（自主级记录必须等于回读实际级别）/ INV-19（未知标识符必须失败）单独进定时任务**，防止随迭代无声回退。理由：这三条对应"放行型"与"记录失真型"失效，是最难被人眼发现、代价最高的一类。

## 5. 显式不做（负需求）

- X1 边不得自动化越过门；门保持人类；生产发布门是 agent 终点（hook 强制）。
- X2 不自动启动下游节点（advance 只推进不拉起）。
- X3 不自造工作流格式（schema 以 graph.md 示例为唯一权威）。
- X4 不实现幻影能力（LLM 服务面、gen2-only 面一律双向证据验证后才进实现）。
- X5 不做桌面端分支（web/desktop 共 bundle）。
- X6 不做任何项目专属代码（无 Node/npm/本仓库假设；项目相关的只有 `.cycles/` 数据与用户配置）。
- X7 不做"静默修复覆盖人类驳回"；驳回记录不可被任何自动环节改写。
- **X8（宪法）进化不得移除/削弱人类门**：补丁修改 workflow-graph 时，`type:human` 的门数量只可增不可减，角色只可升权不可降权。
- **X9（宪法）进化不得修改熔断条件、HITL 规则、账本格式**：这三者是安全的根基，硬编码在插件核心，不在任何补丁的可变面上。
- **X10（宪法）进化不触碰代码工件**：补丁只能改流程（图/阈值/权重/自主级带），改代码必须走正常 build/test/门禁路径。

## 6. 验收标准（对应里程碑门，详见 04 文档）

- **A1 (M2)**：本仓库（76-cycle 历史账本）上 status 正确回答当前节点/阻塞点/下一触发；ledger verify 全链绿；旧账本可直接续写。
- **A2 (M2)**：J3 全旅程走通，双通道写同一账本互见。
- **A3 (M3)**：J2 图视图渲染 76-cycle 项目 <1s 首帧；四类节点/状态着色正确。
- **A4 (M4)**：F5 条件满足时多角色 LLM 评审产出结构化报告且失败自动回落；不满足时显式 DEFER。
- **A5 (M6)**：全新空仓库（**非 Node 项目**）J1 ≤5 分钟完成 init 并看到空态图。
- **A6 (M5) 进化安全性**：M0-④ 回放仿真固化为准出测试——76-cycle 历史数据上，信任模型产生的自主级调整全部落在授权带内、零越权；每个补丁用例（含人为构造的恶化场景）都正确 keep 或 auto-revert，账本留痕完整。
- **A7 (M5) 进化有效性**：J6/J7/J8 三旅程演示通过；同一实验组（带进化）vs 对照组（静态配置）在模拟故障注入下，对照组要么卡死要么永久 L4 裸奔，实验组正确降级且降级可追溯。
- **A8 (M2-b/M3) 规模与幂等**：① 10,000 条账本 + 1,000 cycle 目录下 `verifyIncremental` <100ms、冷启动不扫 archive（M2-b）；② UI 账本首屏 50 条 <100ms 滚动无卡顿（M3）；③ 同一 requestId 连调 10 次 ⇒ 账本 +1、证据文件 +1（M2-b）；④ 相同 detailDigest 证据只存一份（M2-b）；⑤ append N 条累计写入 ≤ N × 1 KB（分段方案实测证明，M2-b）。
- **A9 (M5-a) 归档与预算**：① 冷却期归档后热区文件数/字节下降且账本 verify 仍绿；② `anic_prune` 默认 dry-run，`--apply` 不触碰 `gates/ledger*`/`archive/index.jsonl`/任何 unmanaged 文件；③ 预算超阈告警且未删除任何文件；④ 12 个实测空 cycle 目录在 sweep 报告中全部可见。
- **A10 (M1) 结构契约与迁移等价**（复评轮新增）：① 既有 `.cycles/` 上跑旧命令，输出与迁移前**逐字节等价**（三跑对比：clean HEAD / 迁移前 / 迁移后，失败清单只减不增）；② 引号写法 `autonomy_level: "L4"` 下触发降级 ⇒ **不产生"已降级"记录**且非零退出（INV-16）；③ `--dimensions E9` 非零退出并列出合法值（INV-19）；④ 删除任意派生文件后可由账本+工件重建出等价内容（INV-13）；⑤ 10 路并发 append 无丢记录、链完整（INV-15）；⑥ 置信度无字面量常量，链被篡改时 gatekeeper 必须 FAIL（INV-14）。

## 7. 新增用户旅程（规模相关）

- **J9 长跑观察（M3/M5-a）**：一个 500+ cycle 的项目打开标签 → 时间线秒开（读索引尾部）→ 切换到冷 cycle 详情按需加载 → 全程不卡；工件健康面板告知"总占用 X MB，建议归档"。
- **J10 归档治理（M5-a）**：用户点"整理工件"→ 看到 dry-run 清单（将移动 X 个 cycle / 释放 Y MB）→ 确认 → 归档完成、账本链校验仍绿 → 用户想找回某个 cycle，从归档索引一键定位。
- **J11 契约层迁移（M1，复评轮新增）**：开发者在既有 57-cycle 仓库上安装新插件 → 旧命令（CLI/MCP）语义不变、输出逐字节等价 → 同时新命令开始**响亮失败**于过去静默通过的输入（拼错维度、引号写法、缺配置项）→ 开发者据此发现旧流程一直在静默跳过的检查项。**这条旅程的价值恰在于"暴露既有静默失效"，而不是"平滑无感"。**
