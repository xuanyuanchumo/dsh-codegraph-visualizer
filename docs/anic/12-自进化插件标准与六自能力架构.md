# 12 · 六自能力架构 × 技能插件开发规范 × 独立性宪章

> 状态：**设计文档 v1.0（2026-10-13）**。用户需求（m03247）：11 号功能不够完善丰富——dsh-anic 必须是**不依赖项目插件 dsh-codegraph-visualizer 的独立工程**，并按 **DSH 开发规范/API/破坏性变更**（07 号文档）与**技能插件开发规范（模块化、扩展性…）**实现**自评审、自进化、自举、自迭代、自优化、全自主**的功能业务技能插件。

## 1. 独立性宪章（Independence Charter）

1. **源码零依赖**：`dsh-anic/src/**` 不得 import 父项目 `src/**`（守卫：契约测试扫描 import 图，出现 `from '.*(src|shared)/` 指向仓库根的引用即 FAIL——样例拼接构造）。
2. **构建自包含**（M2-a 退出判据）：`dsh-anic/package.json` 声明自己的 devDependencies（typescript/tsdown/vitest/@types/react），本地 `pnpm install` 后**断开父 node_modules 仍可 build+test**；当前借用父 node_modules 是 M0/M1 的过渡便利，不是终态（登记为待办 TD-A1）。
3. **可迁移**：整目录拷到任意路径/独立仓库，只需改 profile link 一行即恢复安装（路径无关性；`generate-snapshot.mjs` 的 PLUGIN_DIR 常量是唯一路径锚点，迁移时同步）。
4. **文档自持**：`dsh-anic/README.md` 必须自足（安装/J0/测试/热更新不要求读者先读 docs/anic/）。
5. **宿主假设最小化**：唯一宿主面依赖 = `webServer`+`sessions`（host）与 `slots`（client），全部按调用点探测、缺失响亮降级（11 §L-1）；07 的 unknown 宿主映射是默认姿态。
6. **父项目关系**：dsh-codegraph-visualizer 只是**验证场与狗粮场**（父 CLAUDE.md 纪律反向适用：父仓库的构建/测试/门禁不因 dsh-anic 存在而改变）。

## 2. 六自能力架构

### 2.1 自评审（Self-Review）——三层证据化裁决

| 层 | 对象 | 机制 | 失败形态 |
|---|---|---|---|
| 构建时 | 代码与清单 | 五层测试金字塔（L1 C1-C12 → L5 J0）；`validate-dsh` 是每次 build 的前置门 | exit≠0 阻断发布 |
| 运行时 | 自身不变量 | **Runtime INV Probes**：INV-13/18（投影可重算：定期 rebuild 深比较）、INV-21（投影输出不含从 detail 解析的 id）、INV-25/26（配置单入口/诊断域隔离，源码守卫常驻）、快照 digest 自校验 | 诊断面板 ERROR + 遥测 error 通道；不静默 |
| 评审时 | 行为与工件 | Tier-1 确定性评审（gate-check 语义）+ Tier-2 LLM 评审（03 §6：`ctx.llm` 探测接入、闭合协议、失败即 `doubt`）| `doubt` ≠ 通过；阻塞自主推进 |

**新增 INV-28（运行时自证）**：任何进入 M2-a 的自动化行为，必须携带同请求的 `evidenceIds`（账本条目/工件 digest）；无证据的自主动作在 L≥3 被拒绝并记 `SELF_REFUSAL` 事件（可审计的自抑制）。

### 2.2 自进化（Self-Evolution）——有宪章的变体管理

- 沿用 03 §5 全套（宪法 7 条款 / 信任滞回 / 授权带 / 补丁 keep-revert / 防抖）。
- **插件自进化参数域**（L4 才可无人值守修改，且全部走账本）：`refreshIntervalMs`、诊断缓冲上限、着色阈值、归档热区大小、轮询开关。
- **代码自进化边界**：补丁引擎只对**配置与参数**生效；对自身代码的"进化"= 产出 tech-debt/评估缺口 → 生成下一 cycle 任务清单（自迭代的输入），**不自我改写代码**（宪章条款 5 的插件侧落地：代码变更必须经人类门 or 技能引擎的 PR 流程）。
- **协同进化协议**（B-2.4 强化）：技能账本形状变更 → 先出 K1 类契约锁 → 插件投影适配 → 双侧 benchmark 回归 → 才允许插件消费新字段。

### 2.3 自举（Self-Bootstrap）——自己吃自己的狗粮

- `anic_self_init`（CliPort 子命令 / HTTP POST `/anic/self/init`）：对 dsh-anic 工作区执行技能 init-workflow（config.yml 的 test_cmd=`pnpm run test`、build_cmd=`pnpm run build`、lint_cmd=`pnpm run lint`——**技能插件的门禁实现就是它自己的测试金字塔**）。
- 自举后：ANIC 标签在 dsh-anic 工作区显示「本工作区循环」徽标；第一个 cycle 的任务清单 = 本篇 §1 宪章 TD-A1 + 11 号 §8 M1 待办（**自举的第一份输入是设计文档的遗留项**）。
- 断链防御：自举工作区的 `.cycles/` 与任何被观测项目物理隔离（宪章 2/B-2.2）；`anic_self_init` 拒绝在含既有 `.cycles/` 的工作区重跑（幂等 + loud）。

### 2.4 自迭代（Self-Iteration）——门禁是唯一暂停点

- M2-a CycleRunner：评估→规划→拆测→验证→修复→门禁→复盘 七步无人值守；G0-G3 全绿自动 advance；任何 FAIL→auto-fix-loop（≤3 次）→仍失败→熔断降级（先修复后降级）。
- 自迭代输入源：tech-debt 台账、评估报告缺口维（SKIP 维清单）、人类 review 意见（REVIEW.md）。
- 退出条件即 8 熔断 + 单会话 24h/上下文 85% 水位（技能 R 规则原样继承）。

### 2.5 自优化（Self-Optimization）——度量闭环

| 维度 | 度量源 | 优化动作 | 回滚 |
|---|---|---|---|
| 性能 | 快照构建耗时（X-ANIC 构建耗时头）、10k 投影 <100ms 判据（N3）、bundle 体积 | 调整轮询间隔/分页 limit/缓冲上限（参数域内） | 账本记录前值，异常回写 |
| 质量 | 契约套件分数、INV probe 触发数 | 缺口→tech-debt→自迭代 | — |
| 体验 | 收纳状态切换频率、诊断错误率 | 布局参数/默认值调整（L-view 域） | 用户可一键重置偏好 |

### 2.6 全自主（Full Autonomy）——授权带 + HITL 落地

- 授权带矩阵照 05 §5.2；**默认出厂 L2**（07 unknown 宿主保守映射），升级需人类批准。
- **HITL 的 DSH 原生形态**：人类门批准队列优先走 `userQuestionPanels`（gen2-only 标记，按调用点探测）；不可用时降级为标签内批准卡（W-3 抽屉的审批分区）+ `ctx.emit` 提醒；两条路都把批准/驳回写回账本（gate-check --record 语义）。
- 自主级变更三处同源可见：账本事件（真相）→ 诊断面板（观察）→ 标签徽标（投影）。

## 3. 技能插件开发规范（Skill-Plugin Development Standard）

> 本节是 dsh-anic 的"成文开发规范"，地位等同父工程 CLAUDE.md——新增代码必须通过 §3.4 的守卫族。

### 3.1 模块化（Modularity）

1. **L0-L5 单向依赖**（09 §4.1）为铁律：L5→L0，反向依赖=架构违规（守卫 G-DEP）。
2. **特性模块制**：`src/client/features/<feature>/`（视图+状态+测试同目录），跨特性只经 L0 contracts 与 L3 编排器，禁止特性间深 import（守卫 G-FEAT 扫相对路径深度）。
3. **单实现原则**：同一语义全仓只允许一个实现（配置 loader/任务行解析/账本/词表——技能侧 lib/ 化的教训直接移植）；重复实现出现即守卫 FAIL（G-SINGLE，扫描关键符号的第二定义）。
4. **barrel 纪律**：每个特性模块一个 `index.ts` 出口；`deep import` 只允许测试文件。

### 3.2 扩展性（Extensibility）——五个注册表 + 一条稳定 API

| 注册表 | 扩展什么 | 扩展方式 | 校验 |
|---|---|---|---|
| DimensionRegistry | 评估/质量维 | L0 contracts 声明 + schema 版本号 | 词表唯一来源（INV-11）；禁改既有名 |
| GateRegistry | 门定义 | `workflow-graph.yaml` 声明 + `sub_gate` 归属 | 未知门响亮（INV-19）；门必有证据契约 |
| ProjectionRegistry | 投影（StepTrace/报告/导出） | L5 纯函数注册 | 可重算（INV-13）；heuristic 标注（INV-27） |
| EvaluatorRegistry | Tier-1/Tier-2 评审器 | L1 纯函数 / LLM 适配器（03 §6 协议） | 空证据拒绝（INV-14） |
| PanelSectionRegistry | 标签内分区（含未来第三方分区） | 分区声明（id/高度预算/收纳级） | 高度预算入 ArtifactBudget 类治理 |

**对外稳定 API（v0 承诺）**：HTTP 路由契约（`/anic/api/*` + ETag 语义）与账本只读投影为跨插件公共面——变更走 schema 版本 + 迁移链（05 §9）；其余内部面随时可改。
**事件外发**：关键状态变迁（gate PASS/FAIL、autonomy 变更、patch keep/revert）经宿主事件通道广播（声明合并事件类型，红线 5），供兄弟插件订阅——不要求、不假设订阅者存在。

### 3.3 其他规范（继承 07/CLAUDE.md 纪律，点名适用）

- 破坏性变更适配：B1-B11 清单 + unknown 宿主映射（07 §3/§4）——每次宿主升级跑九步 checklist。
- i18n：`t()` 全覆盖（C7 键集对齐守卫）；日志/诊断文案可用英文但用户可见文案必经 locale。
- 安全：路径越界约束（05 §11）+ 证据不落副本 + 凭据 redacted；`.cycles/` 只读（INV-26）。
- 性能预算：入 05 §8 表；超预算是 FAIL 不是 WARN（iteration-5 判据语义）。

### 3.4 守卫族（新增，并入 L3 契约测试）

G-DEP（依赖方向）/ G-FEAT（特性边界）/ G-SINGLE（单实现）/ G-IND（独立性：禁 import 父 src + 禁引用父 docs/scripts）/ G-REG（注册表注册项必须带 schema 版本）。全部遵守三条守卫纪律：反向自检、样例拼接构造、扫描集非空下限（09 §7）。

## 5. 风险

- **R-31（自指递归）**：插件自评审自身评审器 → 评审标准漂移。防御：评审器自身只允许 Tier-1 确定性断言 + 人类门修改词表/门定义。
- **R-32（独立性倒退）**：图省事 import 父工程工具。防御：G-IND 守卫 + M2-a 构建自包含退出判据（断开父 node_modules CI 试跑）。
- **R-33（扩展面失控）**：注册表开放后第三方分区破坏布局预算。防御：PanelSectionRegistry 高度预算治理 + 收纳级强制。
