## 1. 方法与流程（skill-creator 七步）

1. **快照基线**：`skill-snapshot/ai-native-iteration-cycle/`（56 文件）——旧版全部证据可复现；确认双副本（.dsh / .codeartsdoer）逐字节相等后才动手。
2. **旧评测基线**：旧 `evals/evals.json` 仅 5 条纯 prompt 评测（无断言、无 files）——印证 09/S-3"无执行契约"。
3. **脚本全文取证**：六脚本逐行读，锁定编辑锚点（DIMENSIONS :13-30、loadConfig、gatekeeper :417-423、auto-fallback :589-625 等）。
4. **抽取共享库 → 修脚本**：先立 lib（L0/L2 思想的脚本化近似），再逐脚本改走 lib；每文件最小改动 + S-x 注释。
5. **契约断言**：`contract-tests.mjs` 11 场景 × 新旧双跑（沙盒夹具，不改技能）。
6. **端到端 A/B**：两个独立 subagent 分别用新版/旧版在干净 toy 项目上走完 SKILL.md 快速启动全流程，只记录不修技能。
7. **聚合与镜像**：grading.json（skill-creator schema）→ aggregate_benchmark → 静态评审页 → robocopy /MIR + 哈希比对。

### 9.8 门禁完整性：三态裁决 + 漂移守卫（1.9.0，iteration-5）

iteration-4 把**账本**的写者收干净了；iteration-5 转向另一面——**读侧判据**。取证发现的不是"某个脚本写错了"，而是四轮修复里一直没被当成缺陷的一个家族：**无证据即通过（fail-open）**。

#### A. fail-open 家族（5 处，全是"没评估"被记成"通过"）

| 位置 | 缺陷 | 修法 |
|---|---|---|
| `eval-runner.mjs` 维度裁决 | 缺主题 / 缺证据 / 手工项一律 `{ pass: true, detail: '…(skipped)' }`——评估器对**没评估过**的东西记 PASS | 新增 `skipped()` → `{pass:false, skipped:true}`；`combine()` 在合取里**传播** SKIP（任一 FAIL⇒FAIL；无 FAIL 但有 SKIP⇒SKIP） |
| `eval-runner.mjs` 报告行 | 报告只写 PASS/FAIL，SKIP 无处可表达 | 报告行写 `SKIP`；退出码只由 FAIL 决定，但 SKIP 维度**响亮列出**（"没评估"与"通过"在屏幕上必须不同） |
| `eval-runner.mjs` 继承既有报告 | 合并上一轮报告行时 `pass = cells[2]==='PASS'`，SKIP 被读成 FAIL | 保三态（`pass`/`skipped` 分别解析） |
| `eval-runner.mjs` 附带两处 | `.env` 存在但无 `.gitignore` 时 E6 静默跳过；手工项（无基线工件）记 PASS | 分别改为显式 SKIP / 不得 PASS |
| `gate-check.mjs checkQualityGate` | 正则只拦 `FAIL`：**Q 行缺失（match=null）与 SKIP 都静默通过**——质量门禁无证据即可关门 | 三态：行缺失 → `(row absent)`、`SKIP` → `(SKIP)`，二者都判 FAIL（`gate cannot close without evidence`） |
| `gate-check.mjs checkG0 / checkG2` | G0 只查报告**存在**（空报告/只有标题也算）；G2 缺汇总表时按"0 失败"判 PASS | G0 要求 ≥1 条维度裁决行；G2 把报告格式当契约（缺 `通过/失败` 行 = 没有证据 = FAIL） |

**判据统一为一句**：**没有证据 ≠ 通过**。SKIP 是"本次没有证据"的显式表达——它不阻塞 `eval-runner`（否则没有任何 README 的文档型项目永远跑不完），但它**不可关门**（门禁的本质就是"必须有证据才放行"）。

#### B. 漂移守卫（4 类，机器检查替代逐轮人工 grep）

四轮进化里反复出现的漂移家族——版本三处漂移（1.5.0/1.6.0 曾并存）、配置入口分裂、绕过原子写、B 族旧词表残留——原先只能靠人工 grep，而且**每轮都能扫出新的一层**（人读文档 → agent prompt → 机器 schema/hook）。v1.9.0 把它们变成 `quick-validate.mjs` 的错误级检查（exit 1）：

1. **版本一致性**：`SKILL.md` 的 `MCP Tools (vX)`、`mcp-server.mjs` 的 Server version、`CHANGELOG.md` 顶层条目三处必须一致；**锚点找不齐也报错**（守卫必须能失败，否则会随被守卫物一起消失）。
2. **配置入口唯一**：脚本代码内不得出现 `.cycles/cycle-config.yml`（唯一豁免 `lib/config.mjs` 兼容层）。
3. **原子写**：`lib/fs-safe.mjs` 之外不得直接调用 `writeFileSync(`；另报"死 import"警告。
4. **词表漂移**：B 族旧维度名只在**与维度编号绑定**的上下文判罚（同行含 `E1-E8`/`Q1-Q8` 或 `name:` 绑定）。

#### C. 两次自我校准（守卫自身就是缺陷源）

- **守卫匹配到自己的样例字面量**：首次运行把 `quick-validate.mjs` 自己报了出来（它必须写出 `cycle-config.yml`、`writeFileSync(` 这些样例）。按 CLAUDE.md 的既有纪律改为**字符串拼接构造样例**（`'cycle-' + 'config.yml'`），并让错误信息本身也不含该字面量。
- **规则过宽 → 噪音 → 被忽略**：词表规则一开始扫"任意行含旧名"，于是 `.cycles/tech-debt/` 台账、复盘里的"减少技术债务"、`playbook.md:190` 的"技术债务台账"全被误判。加"必须与维度编号/`name:` 绑定"后，首次校准即抓出 **23 处真实残留**且零误报——这正是"守卫必须自证不误伤"的原因：**一个会误报的守卫会被学会忽略**。

#### D. 契约与基准（iteration-5 后）

| 场景 | 新版（1.9.0） | 旧版（1.6.0 快照，缺陷复现断言） |

### 9.9 M0-③ 账本规范化反推 + canonical 冻结锁（iteration-6，无技能代码改动）

链：**55/56 链接完好**，`chainHead == 末条 hash`；唯一断点是 index 0 的 **genesis**（`previousHash` 非 null，历史形态，非新缺陷）。跨工作区机制已在 `src/host/security.ts` 就位（白名单只来自宿主服务、`cmpPath === cmpRoot || startsWith(cmpRoot+sep)`）。

**这一轮同时纠正了两处自己的错误**：

1. **PowerShell 幻影**：首轮用 `ConvertFrom-Json` 读到 `timestamp = 10/05/2026 00:00:00`，一度判为「locale 格式、跨机器不可复现」的高危结论；实际是 PowerShell 把 ISO 自动转 `[datetime]` 再按本地格式渲染——账本里始终是 ISO（56/56）。**一个未经来源验证的显示值不是证据**。
2. **文档与实测不符**：[05](05-数据结构与算法设计.md) §3.2 原写「`sortedKeys` + `no whitespace` + `sha256(canonical + prevHash)`」——**三个半句全被实测否证**，已改为实测形式并新增 **INV-20（canonical 载荷冻结）**。这正是文档族最该防的漂移类型：规则写得像真的，实现却是另一回事。

**K1 契约场景（canonical 冻结锁）**：字面载荷 + **硬编码期望 hash**（`3d77e40f1610b0742bca2573165b2b95c7d4aeeb64e4641b02b8eb8f888df329`），要求 `--verify` 接受、追加后旧条不被动、新条 `previousHash` 指向旧 `chainHead`；测试内部**独立重算**（不复用被测代码）。两版都必须过 = 兼容锁。

**变异探针（守卫必须能失败）**：把 `lib/ledger.mjs` 的 `entryData` 键序 `gate,gateName,result` 换成 `result,gate,gateName` → **K1 与 F1 双双变红**（`Previous: 3d77e40f…` mismatch），21→19。第一次探针因 `-replace` 未匹配而"变异未生效"，此时结论无效——**改完必须证明变异生效**（与 CLAUDE.md 的既有纪律一致）。

**终态**：契约套件 **21 场景**，新版 **21/21（3557ms）**、旧版 **21/21（2500ms）**；R11 退场，替代风险 R11′（"顺手规范化"即断链）由 K1 + 变异探针守护。

### 9.10 M0-④ 进化引擎离线回放仿真（iteration-7，无技能代码改动）

回到插件主线的第二个 spike：用真实 `.cycles/` 数据回放进化引擎，验证「全程零越权 / 补丁 keep-revert 正确 / 账本留痕完整」。交付物 [spike/evolution-replay-simulation.md](spike/evolution-replay-simulation.md)，仿真器 `.anic-skill-evo/spike/evolution-replay.mjs`（只读真实数据；Tier B 的写盘发生在 `mkdtemp` 沙盒且走技能真实 `lib/ledger.mjs`）。

**判定 PASS**（不触发 04 §1 的"降级为建议模式"）：规则层 8/8 熔断条件有决定、自动修复仅限 CB3/CB4/CB8、破坏性动作不入任何授权带、**升级需人类而降级可自动**、补丁 keep/revert **4/4**、13 条决策 **13 条留痕**且沙盒 `verifyLedger` valid；真实数据层门禁序列 **14/14 组严格 `G0→G1→G2→G3`**、canonical **56/56**。

**真正的收获是数据层暴露的三项 P0 确认**（规则"没越权"远不如"历史工件不足以审计是否越权"重要）：

1. **自主级变更无法审计**：`incidents/` 2 份声明白纸黑字写着「自主级别回退：L4 → L3」，账本中对应记录 **0 条**，`config.yml` 至今仍 `L4`。诚实边界——账本 genesis 已断链（M0-③ 已证）且两条事故早于账本首条 17 天，因此**只能判定"无法审计"，不能判定"从未记录"**。两种情形都指向同一要求：级别变更每次入同一条账本 + 裁剪保留可审计路径（→ 新增 **INV-22**）。
2. **cycle 身份只存在于自由文本**：同一份账本，按 `detail` 文本归属得 **3 组"乱序"**，按位置归属得 **0 组**（5 条 detail 不含 cycle 号、15 条提到多个 cycle，例如 G1 文本里的"流转至 cycle-80"被误判给下一个 cycle）。→ 新增 **INV-21**。
3. **门禁事件与人类门检查事件分处两个载体**：56/56 全 PASS 说明历史降级**不可能由门禁触发**，而两次事故来自 H1/H3 人类门检查、只写入 `incidents/`——"为什么降级"与"降级了什么"分居两处。→ 印证 09 原则 3「一账本 + N 投影」。

**方法学纠正（本轮最该记住的一条）**：我第一版仿真把 3 组"门禁乱序"当成账本缺陷。它其实是我的解析器造出来的假象。正确动作是**并列两种归属方法 → 发现分歧 → 先判定哪种可靠 → 只把权威方法当判据，并把分歧本身记为发现**。这与本仓库历史上"把 Playwright 超时当诊断""把过期覆盖率当缺口"是同一类错误。技能侧复核进一步确认该发现**不该由技能承担**：`lib/cycle.mjs:9/16/27` 解析的是目录名，没有任何脚本从 `detail` 解析 cycle——把它写成技能缺陷同样是把假象当缺陷。
