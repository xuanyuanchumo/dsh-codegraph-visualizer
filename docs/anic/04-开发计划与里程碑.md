## 3b. M2-b — 规模地基（账本形状一次定死）

**为什么单列**：用户 m00196 点出的"多次调用产生大量产物"在实测里不是一个性能优化项，而是**一个形状决策**——单文件数组账本 10k 条需累计写 44.7 GB（O(n²)），分段只追加只要 8.9 MB，且证据字段无界（实测末条 `detail` 4.4 KB = 全链 9%）。形状一旦有真实 cycle 写入就冻结（宪法条款 7 / 条款 2）。

范围（08 §3 + 02 §3.6 的 P0 四项）：
1. `runtime/Ledger.ts` 物理布局改 `head.json` + `seg-NNNNNN.jsonl`（SEG_MAX=1000）；旧 `ledger.json` 惰性迁移到 `legacy/` 只读留存（N2 零迁移在物理层的落地）；
2. **v2 记录形状一次定死**：`version/requestId/gate/gateName/result/detailSummary(≤280)/detailRef/detailDigest/evidenceBytes/timestamp/previousHash/hash`；同链混代（v1 无 `version` 视为 v1，各按各自 canonical 规则算 hash）；
3. `requestId = <宿主 runId>-<序号>` 幂等查重（F25）；
4. 证据外置 + 内容寻址去重（F24：`detailRef` + `detailDigest`；>64 KB 或含凭据拒绝并熔断）；

- **状态不变量回归**：05 文档 §4.3 的 **INV-1..INV-30** 是常驻准出测试，任何触碰 Ledger/投影/信任/归档/契约/配置/开关的改动都必须全绿。来源链：INV-1..9（08 规模轮）、INV-10..19（复评轮，09 §7：INV-10 路径唯一来源、INV-11 维度词表同源、INV-12 每端口一条执行用例、INV-13 派生可重算、INV-14 信任分可追溯且空证据不得 auto-approve、INV-15 并发追加不丢、INV-16 自主级记录 == 回读实际级别、INV-17 跨模块无文本协议、INV-18 控制带可重算、INV-19 未知标识符必须失败）、INV-20（canonical 载荷冻结，M0-③）、INV-21（cycle/run 身份结构化，M0-④）、INV-22（裁剪/归档保留可审计路径，M0-④）、INV-23（LLM 裁决 doubt 语义，M0-②）、INV-24（`'llm'` 不进硬 inject，M0-②）、INV-25/26/27（配置单入口/诊断域隔离/投影诚实标注，11 号）、INV-28（运行时自证 SELF_REFUSAL，12 号）、**INV-29（核心链路不可关：标签壳+快照路由+只读工具不在可关清单，13 号）/INV-30（全开关可观测：诊断面板列出每个开关的生效值/来源层/关闭时间，13 号）**；
- **契约守卫常驻**：GUARD-1..GUARD-6 源扫描守卫（07/09）必须带**反向自检**，且不得匹配自身样例字面量、必须同时扫**写侧**；
- **规模判据常驻**：追加写入 ≤ N × 1 KB、`verifyIncremental` 在 10k 条下 <100ms、幂等（同 requestId 账本 +1）——三条进 CI 定时任务，防止性能/幂等在后续迭代中被无声回退；
- 视觉回归若引入：先冻结布局随机性 + 双端基线路径分离，否则不引入。
