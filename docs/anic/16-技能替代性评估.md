# 16. 技能替代性评估 —— dsh-anic 插件 vs 项目技能

> 评估问题（goal-6e516be5 核心）：**dsh-anic 技能插件能否完全替代项目技能（`.dsh/skills/ai-native-iteration-cycle/`）的功能业务？**
> 评估日期：2026-10-15 · 证据等级：字节级比对 + 端到端可执行验证

## 1. 结论先行

**能替代，且在四个维度上超出。** 内容 100% 字节相同、运行时 15/15 脚本全覆盖、接入面三通道（DSH 工具 ×9 / HTTP 路由 / 客户端 UI），并在安装自动化、全新项目自举、状态可视化、多代 DSH 适配上为插件独有增强。评估过程中发现并修复 2 个 P1 缺陷（§6），修复后以端到端测试钉死（7/7 绿）。

## 2. 内容层：100% 字节相同

`dsh-anic/assets/skill/` 与 `.dsh/skills/ai-native-iteration-cycle/` SHA256 逐文件比对：**63/63 相同，无差异无缺失**。构成：SKILL.md（19KB）、references/ ×14、scripts/ ×16、templates/ ×13、hooks/ ×3、evals/ ×2。

安装语义：`autoInstallSkill(workspace)` 把内联技能递归复制到 `workspace/.dsh/skills/ai-native-iteration-cycle/`——即插件安装后，目标项目获得的技能目录与"手动复制项目技能"产物完全一致。

## 3. 运行层：15/15 脚本全覆盖

### 3.1 调用器（`src/host/skillInvoker.ts`，唯一定义）

```
invokeSkillScript(scriptsDir, script, args, workspace, timeoutMs)
  → spawnSync('node', [scriptPath, workspace, ...args], { cwd: scriptsDir, timeout: ≤120s })
```

- 白名单 `SKILL_SCRIPTS`：恰 15 个业务脚本；`mcp-server.mjs` 有意排除（MCP 传输层非业务脚本，见 §5.3）。
- `resolveSkillScriptsDir(workspace)` 唯一定义（原 selfInitRoute 本地副本已删——双实现分叉是本轮 P1 之一）。候选链：`ANIC_SKILL_DIR` env → `workspace/.dsh` → `workspace/../.dsh` → `process.cwd()/.dsh` → 内联底座；全部候选过 `init-workflow.mjs` 哨兵检查。

### 3.2 P1 修复：位置参数约定

**缺陷**：调用器此前追加 `--project-dir <workspace>`，但 15 个脚本的项目目录约定全部是第一个位置参数 `args._[0]`（转录自 `mcp-server.mjs:35`：`node "<script>" "<projectDir>" <args...>`）。脚本把 `--project-dir` 当位置参数收进 `args._[0]`，解析出 `<scriptsDir>/--project-dir` 幽灵目录。

**为何长期潜伏**：所有单元测试只测状态机/白名单，从不真正 spawn 脚本——"调用器 × 真实脚本"接缝零覆盖（CLAUDE.md §2.aa 同族教训：writer + guard 各自全绿，组合必测）。

**修复后钉死**：`tests/unit/skillReplaceE2E.test.ts` 断言脚手架产物落在 workspace、调用目录无 `--project-dir` 残留、stderr 无 Usage、config.yml 的 name 不被污染。

### 3.3 脚本依赖审查

15 个业务脚本仅用 `node:` 内建 + `./lib/*.mjs` 相对导入，**零外部依赖**——内联底座即可运行，无 npm install 前置。

## 4. 接入面：三通道替代

| 通道 | 面 | 覆盖 |
|---|---|---|
| DSH 工具（`tools.ts` + `toolsSkillGateway.ts`） | `anic_evaluate` / `anic_iterate` / `anic_gate_check` / `anic_bootstrap` / `anic_snapshot` / `anic_self_check` / `anic_hitl` / `anic_status` + `anic_install`（真执行安装）+ **`anic_skill`（全白名单通用网关，script 枚举运行时取自 listSkillScripts）** ×10 | **15/15 脚本原生可达** |
| HTTP 路由（`skillRoute.ts` 等） | `POST /anic/skill/invoke` 通用网关（任意白名单脚本 + workspace 校验）、`GET /anic/skill/list`、`POST /anic/evaluate`、`POST /anic/iterate`、`POST /anic/self/init`（`--name` 透传） | 15/15 脚本可达（与工具同源同安全模型） |
| 客户端 UI | WorkflowGraphPanel 六域分区图 + 流程开关 | 插件独有（项目技能无 UI） |

**覆盖性契约**（用户需求：所有功能业务脚本必须能 DSH 原生调用）：`tests/unit/skillToolNative.test.ts` 钉死三层——(1) 白名单 15 项 ⇄ 内联底座 scripts/*.mjs（扣除传输层 mcp-server）集合恰好相等；(2) `anic_skill` schema 枚举 ≡ `listSkillScripts()`（单一事实源防漂移）；(3) 行为级 stub 宿主槽位真实 spawn（安装→init→workflow-state 全链退出 0）+ 白名单外拒绝 + dispose 全量清理。

## 5. 增强能力（插件独有，超出项目技能）

1. **安装自动化**：`/anic/skill/install` + `anic_install` 工具 + autoInstallSkill——项目技能需手动复制目录。
2. **全新项目自举**：`/anic/self/init` 一步完成脚手架（幂等 409 拒绝重跑、flow.selfInit 开关、`--name` 透传落盘 config.yml）——项目技能需手动 `node init-workflow.mjs <dir> --name <名>`。
3. **状态可视化**：`.cycles/` 工件渲染为六域工作流图（data/cycle/review/evolution/governance/self）——项目技能纯文件无界面。
4. **多代 DSH 适配**：`engines.dsh ">=0.2.0-rc.2 <0.4.0"` + peerDependencies 声明 + adapters 层——项目技能与宿主无关联。

### 5.3 mcp-server.mjs 的处置

打包携带（安装后目标项目可用于非 DSH 的 MCP 客户端），但插件自身**不运行它**：其唯一外部依赖 `@modelcontextprotocol/sdk` 不在 dsh-anic 依赖内，且 DSH 内部由 9 个原生工具承担同等职责。这是有意的排除，非缺失。

## 8. 残留差距（诚实披露）

1. **hooks/** 3 个脚本不在 DSH 工具/路由接入面内（它们是 Claude Code 侧 hook 机制，DSH 无对应槽位）——内容随安装完整复制，功能在 DSH 内由工作流状态机承接。
2. **templates/ 的 13 个模板** 经 init-workflow 落盘，但无独立单模板查看路由——按需再补。
3. 客户端 tab 在真实 DSH 宿主的加载问题见 15 号文档 §已知限制（宿主侧 Loader entries 机制，非插件缺陷）。
