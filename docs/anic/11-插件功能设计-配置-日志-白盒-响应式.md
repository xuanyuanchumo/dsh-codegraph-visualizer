## 1. 设计原则与复用清单

1. **配置单入口**（S-1/S-8 教训的插件侧版）：`.cycles/config.yml` 是技能域唯一规范配置；插件绝不发明第二个技能配置文件名；legacy `cycle-config.yml` 只在兼容层出现。
2. **fail-loud 读取、honest 降级**（iteration-5 三态裁决）：配置缺失=响亮错误；数据缺失=UI 如实标注来源与原因，永不伪装。
3. **派生可重算**（INV-13/18）：StepTrace/门禁着色/控制带着色全部是账本+工件文件的纯投影，删除派生缓存可重建。
4. **写读分域**（M0-④ 发现 3）：`.cycles/` 的写者只有技能（M1 阶段=CLI 端口；M2-a 后=引擎）；插件是读者与投影器。插件自身诊断绝不写入 `.cycles/`。
5. **unknown 宿主姿态**（07 §3）：渲染面乐观（标签/面板照常）、自动化面保守；能力探测只开不关、按调用点判定。
6. **九条红线**照抄：注册即 effect / disposer 不丢弃 / ESM / Host-Client 隔离 / 声明合并事件 / 显式配置 / Branded ID（本插件暂无需）/ 能力缝三角色 / waterfall 委托。

## 2. 配置管理（C-*）

### C-1 三层模型与优先级

| 层 | 载体 | 内容 | 谁写 | 谁读 |
|---|---|---|---|---|
| L-host | dsh-anic 的 cordis.patch.yml bundle row（**M1 暂不声明**，走宿主默认；M2 声明显式 config：requestTimeoutMs/refreshIntervalMs/maxBodyBytes） | 宿主面参数 | 用户（Host 配置 UI） | 宿主路由 |
| L-skill | `.cycles/config.yml`（**技能域，唯一规范入口**） | build/test/lint_cmd、autonomy_level、complexity_budget | 技能/用户 | 宿主路由（随快照投影 autonomy 等只读字段）、未来引擎 |
| L-view | localStorage `dsh-anic.prefs.v1` | 收纳状态/刷新开关/着色开关/诊断面板开合 | 插件客户端 | 客户端 |

优先级：同一语义字段**只属于一层**（不跨层覆盖——避免发明第三种真源）；跨层只传递**投影**（如 autonomy 是 L-skill 字段的只读投影）。

### C-2 加载器语义（转录技能 lib/config.mjs，非复制文件）

- `loadSkillConfig(projectRoot)`：canonical → legacy（stderr DEPRECATED 告警）→ 缺失 throw `CONFIG_MISSING`（提示正确指向 config.yml 与 init-workflow）。
- `getYamlString/getYamlInt/getAutonomyLevel`：引号可选、行尾注释剥离、`/^L[1-4]\b/i`。
- **未知键拒绝**：宿主路由读取时对已知键白名单外键名收集并在响应 `X-ANIC-Config-Warnings` 头返回（不失败——技能域配置归技能管，插件只警示不拦截，这是与技能侧 strict 模式的**刻意差异**，写进代码注释）。
- 配置热感知：M1 不做文件监听（.cycles 由技能写，天然低频）；每次请求现场读（快照路由已是逐请求构建）。

### C-3 配置 UI（M1：标签内抽屉；M2：宿主配置槽位）

- M1：ANIC 标签右上 ⚙ 抽屉 = 只读展示三层当前值 + 来源标注（host default / skill config / local prefs）+ 视图偏好编辑（L-view 层可写）。
- M2：客户端 `plugins.item` / `bundle.config` 槽位接入宿主插件配置卡（07 §2.4 槽位取证：bundle.config/row.config 是官方配置面）；L-host 层可写（写 cordis.patch.yml 是宿主职责，插件只声明 schema）。

## 3. 日志与错误管理（L-*）

### L-1 错误分类学与错误码

| 域 | 码 | 触发 | 用户可见形态 |
|---|---|---|---|
| route | `ANIC_ROUTE_NO_WORKSPACE` / `ANIC_ROUTE_NO_CYCLES`(404) / `ANIC_ROUTE_BUILD_FAILED`(500) | 解析链/快照构建 | 顶条横幅 + 诊断面板条目 |
| fetch | `ANIC_FETCH_OFFLINE` / `ANIC_FETCH_4XX` / `ANIC_FETCH_5XX` / `ANIC_FETCH_MALFORMED` | 客户端取数 | 底行来源标注切「live 失败→嵌入快照（原因）」 |
| render | `ANIC_RENDER_*`（图装配/越界数据） | 数据畸形 | 保留旧图 + 遥测 error |
| config | `ANIC_CONFIG_*` | C-2 域 | 警示条（不阻塞渲染） |

### L-2 宿主面：scoped logger（M1 最小实现）

- `src/host/logger.ts`：`createScoped('anic:snapshot')` → `{info,warn,error}`，前缀 `[dsh-anic]`；M1 走 console（宿主面允许，客户端面维持零 console 守卫不变——两半纪律不同，分别守卫）；M2 换接宿主日志服务（按 07 B11 探测，不硬依赖）。
- 每条错误日志携带 `requestId`（F25 幂等键同源）——**关联 ID 贯穿宿主日志 ↔ HTTP 响应头 `X-ANIC-Request-Id` ↔ 客户端诊断面板**。

### L-3 客户端面：遥测环形缓冲 + 诊断面板

- `window.__ANIC_TAB_SPIKE__` 扩展：`errors: RingBuffer<200>`（{ts,domain,code,message,requestId}）+ 现有 register/unregister 通道不变。
- 诊断面板（收纳区第 4 分区）：最近错误列表 + 复制按钮（JSON）+ 数据源状态（live/嵌入快照/上次成功时间）。
- **与技能域的边界**：插件错误永不写 `.cycles/incidents/`（incidents 的写者是技能熔断逻辑）；但**熔断相关的技能事件**（如 hitl-audit 记录）在诊断面板以"技能域事件"分区**只读展示**。

## 4. 步骤流程白盒透明化（W-*）

### W-1 四源投影模型（StepTrace）

```
StepTrace := project(graph.yaml, workflow-state.json, ledger.json, cycles/*)
  节点 = Play | Artifact | Gate（graph.md 四类节点）
  每个 Gate 节点绑定：ledger 中该 gate 的最近 N 条裁决（时间倒序）
  每个 cycle 绑定：八件套工件存在性 + 元数据（大小/mtime，不读内容）
  微迭代七步（评估→规划→拆测→验证→修复→门禁→复盘）按 cycle 目录工件映射为步骤条
```

### W-2 归属与诚实标注（承接 M0-④ 方法学教训）

- **cycle 归属只用位置法**（G0 开启新 cycle）；`detail` 自由文本只作展示，绝不作身份解析（INV-21）。
- 无法结构化归属的信息（如 detail 里的补充说明）显示时标注「来自账本 detail 文本（启发式）」；M2-b v2 记录形状（08 §3.2）落地后切换为结构化字段并去掉标注。

### W-3 UI 形态（与 R-* 收纳协同）

- **节点详情抽屉**：点 Gate 节点 → 该门裁决历史（PASS/FAIL/SKIP 三态色）+ detail 摘要 + 关联工件链接（`vscode://file/` 或相对路径展示，M1 不做文件内容读取）。
- **周期时间线**：顶部 cycle 选择器 → 微迭代七步步骤条 → 每步状态（有工件=完成、无工件=未做——如实显示，不做推断）。
- **「为什么」层**：G0-G3 当前门禁状态 + 阻塞原因（从最新 test-report/评估报告的表格行投影，格式契约即 iteration-5 的 `^\|\s*(通过|失败|错误)\s*\|` 行）。

## 5. 响应式动态收纳布局（R-*）

### R-1 分区结构与断点行为

```
ANIC 标签面板
├─ 头栏（cycle 选择器 · 来源标注 · 刷新 · ⚙配置 · 诊断角标）——永不收纳
├─ 图区（SVG 主画布）——永不收纳，占比自适应
├─ 右侧详情抽屉（节点详情/步骤时间线）——≥900px 侧栏；<900px 浮层 overlay
└─ 底部工具轨（过滤器 · 着色开关 · 诊断 · 配置抽屉入口）
    ≥1200px 平铺标签 │ 900–1199px 收成图标+悬浮提示 │ <900px 收进 ⚙ 菜单
```

- 宿主给的容器高度约束（panelMinHeight 240 / 默认 600 语义）用 `@container` 查询响应；**每处 `@container` 必须有 `@supports not (container-type: inline-size)` 回退 + `color-mix()` 必须有 rgba 回退文件**（07 §2 CSS 纪律，类名前缀 `an-`）。
- 图内簇折叠：按 phase 分层簇头部可点击折叠（折叠只影响视图投影，不改数据）；折叠状态进 L-view 偏好。
- 偏好持久化：`localStorage['dsh-anic.prefs.v1']`，读取失败/版本不符→丢弃重置（偏好的诚实降级）。

## 6. 可视化动态优化（V-*）

### V-1 条件请求（M1）

- 复用父工程已验证的全套结论：validator 维度 = workspace + 快照 digest + 请求键（请求键含刷新语义时不复用）；`etagGuard` 返回 `{handled, etag}` 一体；**偏向 200 的不对称偏置**（错发 200 代价小，错 304 吞更新代价大）；`X-ANIC-Snapshot-Digest`（已有）升级为正式 ETag。
- 客户端轮询间隔默认关（手动刷新优先），配置开启后按 L-host `refreshIntervalMs`（默认 30s，下限 5s）。

### V-2 数据驱动着色与脉冲（M1）

- 门禁色：每 Gate 节点按账本最近裁决三态着色（PASS 绿/FAIL 红/SKIP 黄——SKIP≠PASS 的视觉直译）。
- 控制带：band-history 连续超预算的域加 2σ/3σ 边框（Western Electric 视觉隐喻）。
- FAIL 节点红圈已有 → 增加缓慢脉冲动画（`prefers-reduced-motion` 时禁用）。

### V-3 增量投影（M3，不在 M1）

- 快照 digest 变化时按图 diff（节点/边增删）做最小重绘；全量重建只在新 workspace 或结构版本变化时发生（05 §5 投影纯函数语义）。

## 7. 自举闭环（B-*）：技能评估插件 × 插件是技能的插件化

### B-1 二元关系定义

- **写侧（技能→插件）**：ai-native-iteration-cycle 在 dsh-anic 工作区执行——G2 测试零错 ⇔ `run-tests.mjs`（validate 12 + vitest 36 + smoke 19）全绿；G3 构建零败 ⇔ build + typecheck；E 维评估 ⇔ 契约套件 + benchmark（review.html）；L4 op chain 的 gate-check/eval-runner 直接吃 `dsh-anic/package.json` 的 test/build 命令（技能 config.yml 指向它们）。
- **读侧（插件=技能的插件化）**：ANIC 标签在 dsh-anic 工作区渲染的是**插件自己的** `.cycles/`（开发迭代史）；用户看到的图=技能对插件的评估记录。这是"自举"的可见形态。

### B-2 边界纪律（防止自指事故）

1. 插件对 `.cycles/` **只读**；技能是唯一写者（INV-21/22；M2-a 后=引擎单写者）。
2. 技能跑在插件上产生的循环数据与父项目 `.cycles/` **物理隔离**（各自工作区各自的 .cycles/）。
3. 插件 UI 渲染自举循环时必须标注「本工作区循环」 vs 「其他工作区」（workspace 维度已在快照响应头）。
4. 技能进化（10 号文档 iteration-1..5 的 S/N 缺陷修复）**先于**插件消费对应字段——插件投影只消费技能已稳定输出的结构（位置法归属、三态裁决、格式契约行）。

### B-3 评估协议（技能评插件的固定动作）

1. `init-workflow` on dsh-anic（config.yml: test_cmd=`pnpm --dir dsh-anic run test`，build_cmd=`pnpm --dir dsh-anic run build`）；
2. 每 iteration：eval-runner 全维 → gate-check --gate all --quality --record → multi-agent-gate（确定性门）→ 结果入账本；
3. benchmark 回归：`.anic-skill-evo/` 契约套件对插件改动复跑（17+ 场景），分数进 review.html；
4. 复盘工件写 `retrospectives/`（当前 0 文件——自举会第一次填满它）。

## 9. 风险与新增不变量

- **INV-25（配置单入口）**：插件消费技能域配置只经唯一 loader；出现第二个配置文件名读取即架构违规（守卫进 L3 契约测试，正则扫描 src/ 禁 `cycle-' + 'config` 字面量——守卫自身样例拼接构造）。
- **INV-26（诊断域隔离）**：`src/` 宿主+客户端不得出现对 `.cycles/incidents/` 的写路径；写侧守卫扫 `join('.cycles', …)` + write 系调用的组合（写权限只存在于技能端口层）。
- **INV-27（投影可重算且诚实标注）**：StepTrace 任何启发式归属字段必须携带 `heuristic:true` 标记并可一键关停（关停后只显示结构化数据，宁缺勿猜）。
- **R-28**：自举循环里技能与插件同时改动 → 变异放大（技能改账本形状、插件投影跟着断）。防御：B-2.4 顺序纪律 + 契约套件把「账本形状」场景（K1 canonical 锁）纳入插件 CI 侧复跑。
- **R-29**：响应式收纳状态与宿主面板高度变化竞争。防御：收纳状态只在 `@container` 断点穿越时改写，宿主 resize 去抖 400ms。
- **R-30**：诊断环形缓冲持有大 detail 文本导致内存增长。防御：条目上限 200 + 单条 detail 截断 280 字符（同 F24 证据外置语义）。
