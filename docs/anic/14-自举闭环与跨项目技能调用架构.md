### 0.3 核心缺口

三个结构性缺口阻止 dsh-anic 成为真正的自举自进化插件：

1. **G-BOOT**：无自举闭环——dsh-anic 不能用自身路由驱动技能对自身代码跑评估→门禁→修复→验证。
2. **G-CROSS**：无跨项目调用——所有路由硬绑当前 workspace，无法评估/迭代其他项目。
3. **G-TOOL**：无 DSH 工具注册——其他 DSH 会话/agent 无法通过工具调用 dsh-anic 的能力。

## §1 自举闭环架构（G-BOOT）

### 1.1 自举语义

dsh-anic 自举 = dsh-anic 用自身的 HTTP 路由驱动技能脚本对 dsh-anic 自己的源码跑完整微观迭代：

```
评估(eval-runner) → 门禁(gate-check) → 修复(auto-fix-loop) → 验证(eval-runner) → 账本(gate-ledger)
```

关键约束（12 §2.1 自指变异放大 R-31）：
- **写侧隔离**：自举评估只产 tech-debt 提案（patchEngine.ts），不自我改码。
- **读侧诚实**：自举读自身的 .cycles/，必须如实标注 "self-bootstrap" 来源。
- **终止条件**：自举不无限递归——最多 N 轮（默认 3），每轮必须有可量化改善。

### 1.2 路由设计

| 方法 | 路径 | 语义 |
|------|------|------|
| POST | /anic/self/evaluate | 对 dsh-anic 自身源码跑 eval-runner，返回评估报告 |
| POST | /anic/self/iterate | 跑一轮完整微观迭代（eval→gate→fix→verify），返回迭代结果 |
| POST | /anic/self/gate-check | 对 dsh-anic 自身跑 gate-check，返回门禁裁决 |
| GET | /anic/self/status | 自举状态（当前轮次/上一轮结果/是否收敛） |

### 1.3 自举状态机

```
IDLE → EVALUATING → GATE_CHECKING → [PASS → CONVERGED] / [FAIL → FIXING → VERIFYING → GATE_CHECKING]
                                                              ↑                                    |
                                                              └──── (rounds < maxRounds) ────────┘
                                                              [rounds >= maxRounds → EXHAUSTED]
```

状态持久化到 `.cycles/self-bootstrap.json`：
```json
{
  "status": "EVALUATING|GATE_CHECKING|FIXING|VERIFYING|CONVERGED|EXHAUSTED",
  "round": 2,
  "maxRounds": 3,
  "lastEvalScore": 0.875,
  "lastGateVerdict": "doubt",
  "history": [
    { "round": 1, "evalScore": 0.82, "gateVerdict": "FAIL", "fixApplied": "N-3 CJK word count" }
  ]
}
```

### 1.4 自举与技能的关系

自举不是"插件改自己的代码"——而是"插件用技能的方法论评估自己，产 tech-debt 提案，由人类或外部 agent 决定是否采纳"：

```
dsh-anic/self/iterate
  → spawnSync node scripts/eval-runner.mjs --project-dir <dsh-anic-dir>
  → spawnSync node scripts/gate-check.mjs --gate all --quality --record
  → if FAIL: patchEngine.generateTechDebt(evalResult) → write to .cycles/tech-debt/
  → 不自动修复源码（R-31 自指变异放大防护）
  → 返回 { evalScore, gateVerdict, techDebtProposals }
```

## §2 跨项目技能调用 API（G-CROSS）

### 2.1 设计原则

所有路由增加可选 `workspace` 参数（query string 或 body 字段），允许指定目标项目目录：

- `GET /anic/api/workflow-snapshot?workspace=/path/to/other/project`
- `POST /anic/cycle/init` body: `{ "workspace": "/path/to/other/project" }`
- 未指定时回退到当前 workspace（向后兼容）

### 2.2 通用技能调用路由

| 方法 | 路径 | 语义 |
|------|------|------|
| POST | /anic/skill/invoke | 通用技能脚本调用（指定 script + args + workspace） |
| GET | /anic/skill/list | 列出可用技能脚本 |
| GET | /anic/skill/scripts/:name/info | 脚本元信息（参数/用途） |

`POST /anic/skill/invoke` 请求体：
```json
{
  "script": "eval-runner",
  "args": ["--dimensions", "E1,E2,E3"],
  "workspace": "/path/to/target/project",
  "timeout": 30000
}
```

安全约束：
- `script` 必须在白名单内（技能 scripts/ 目录下的 .mjs 文件）
- `workspace` 必须通过安全检查（不允许路径遍历 / 必须存在 .cycles/ 或先 init）
- 超时默认 30s，上限 120s
- 返回 stdout/stderr/exitCode，不流式（简单可靠）

### 2.3 跨项目评估路由

| 方法 | 路径 | 语义 |
|------|------|------|
| POST | /anic/evaluate | 对指定 workspace 跑完整评估 |
| POST | /anic/iterate | 对指定 workspace 跑一轮迭代 |
| GET | /anic/report/:workspace | 获取指定 workspace 的最新评估报告 |

## §3 DSH 工具注册（G-TOOL）

### 3.1 设计

dsh-anic 在 `apply(ctx)` 中注册 DSH 工具，供其他会话/agent 调用：

```typescript
// src/index.ts
export const inject = ['tools', 'webServer', 'sessions'];

apply(ctx) {
  // ... 现有路由注册 ...

  // 注册 DSH 工具（供其他 agent/会话调用）
  ctx.effect(() => {
    const disposers = registerAnicTools(ctx, { send, getWorkspaceRoot });
    return () => disposers.forEach(d => d?.());
  }, 'dsh-anic: tools');
}
```

### 3.2 工具清单

| 工具名 | 参数 | 语义 | 对应路由 |
|--------|------|------|----------|
| `anic_evaluate` | `{ workspace?: string, dimensions?: string[] }` | 评估指定项目 | POST /anic/evaluate |
| `anic_iterate` | `{ workspace?: string, maxRounds?: number }` | 迭代指定项目 | POST /anic/iterate |
| `anic_gate_check` | `{ workspace?: string, gate?: string, quality?: boolean }` | 门禁检查 | POST /anic/self/gate-check |
| `anic_bootstrap` | `{ maxRounds?: number }` | 自举（对自身跑评估迭代） | POST /anic/self/iterate |
| `anic_snapshot` | `{ workspace?: string }` | 获取工作流快照 | GET /anic/api/workflow-snapshot |
| `anic_self_check` | `{ workspace?: string }` | Runtime INV Probes | GET /anic/api/self-check |

### 3.3 工具注册实现

```typescript
function registerAnicTools(ctx, deps): Array<(() => void) | null> {
  const tools = ctx.tools;
  if (!tools?.register) return [];

  return [
    tools.register({
      name: 'anic_evaluate',
      description: 'Evaluate a project using the ai-native-iteration-cycle skill',
      inputSchema: { /* JSON Schema */ },
      handler: async (args) => { /* 调用评估逻辑 */ },
    }),
    // ... 其他工具
  ];
}
```

### 3.4 inject 变更

`inject` 从 `['webServer', 'sessions']` 扩展为 `['tools', 'webServer', 'sessions']`。

`tools` 是 DSH 宿主的工具注册槽位（同 dsh-codegraph-visualizer 的 `inject=['tools','webServer','sessions']`）。

## §4 结构优化分析

### 4.1 路由分区（26 → 6 域）

当前 26 路由按域分组：

| 域 | 路由数 | 路由 | 文件 |
|----|--------|------|------|
| **data** | 3 | workflow-snapshot, step-trace, self-check | snapshotRoute, stepTraceRoute, selfCheckRoute |
| **cycle** | 5 | cycle/init, advance, close, state, list | cycleRoute |
| **ledger** | 7 | ledger×3, seg-ledger×4 | ledgerRoute, segmentedLedgerRoute |
| **review** | 2 | review, stack-probe | reviewRoute, stackProbeRoute |
| **evolution** | 4 | trust, autonomy, breakers, tech-debt | evolutionRoute |
| **governance** | 4 | archive, budget, sweep, prune | governanceRoute |
| **self** | 1 | self/init | selfInitRoute |

优化后新增 **self** 域扩展（+3 路由）和 **skill** 域（+3 路由）和 **cross** 域（+3 路由）：

| 新域 | 新路由 | 里程碑 |
|------|--------|--------|
| **self** | self/evaluate, self/iterate, self/gate-check, self/status | M7 |
| **skill** | skill/invoke, skill/list, skill/scripts/:name/info | M8 |
| **cross** | evaluate, iterate, report/:workspace | M8 |

总计 26 + 7 + 3 + 3 = **39 路由**。

### 4.2 routes/index.ts 优化

当前 index.ts 130 行内联逻辑。优化为纯组合：

```typescript
// 优化后 index.ts（~40 行）
export function registerAnicRoutes(ctx, options) {
  const c = ctx as SnapshotCtx;
  if (!c.webServer?.register) return null;

  const send = makeSend();
  const root = () => resolveWorkspaceRoots(c);
  const flows = () => loadFlows(c, root);
  const agents = () => loadAgentCards(options.agentCardsDir ?? defaultAgentCardsDir());

  const disposers = [
    ...registerDataRoutes(c, send, root, agents),      // data 域
    ...registerCycleRoutes(c, send, root),              // cycle 域
    ...registerLedgerRoutes(c, send, root),             // ledger 域
    ...registerReviewRoutes(c, send, root, agents),     // review 域
    ...registerEvolutionRoutes(c, send, root),          // evolution 域
    ...registerGovernanceRoutes(c, send, root),         // governance 域
    ...registerSelfRoutes(c, send, root, flows),        // self 域（M7 新增）
    ...registerSkillRoutes(c, send, root),              // skill 域（M8 新增）
    ...registerCrossRoutes(c, send, root),              // cross 域（M8 新增）
  ];

  return composeDisposers(disposers);
}
```

每个 `register*Routes` 函数返回 `Array<disposer>`，index.ts 只做组合。

### 4.3 耦合分析

| 耦合点 | 当前 | 优化 |
|--------|------|------|
| send vs SendFn | 每路由本地 type SendFn | 提取到 shared/types.ts |
| getWorkspaceRoot | 每路由内联 resolveWorkspaceRoots | 提取到 host/workspace.ts |
| loadFlows | index.ts 内联 | 提取到 host/flowsLoader.ts |
| agentCardsDir | index.ts 内联 defaultAgentCardsDir | 提取到 host/agentCards.ts |

## §6 风险分析

| 风险 | 等级 | 缓解 |
|------|------|------|
| R-37 自举递归爆炸 | 高 | maxRounds 硬上限 + 每轮必须有可量化改善 + 不自我改码 |
| R-38 跨项目路径遍历 | 高 | workspace 白名单 + resolve 后检查 + 不允许 .. |
| R-39 DSH 工具注册 API 不稳定 | 中 | ctx.get('tools', false) 探测 + 降级为纯 HTTP |
| R-40 技能脚本超时 | 中 | 默认 30s + 上限 120s + 超时返回 TIMEOUT 而非挂起 |
| R-41 自举评估结果失真 | 中 | 如实标注 self-bootstrap 来源 + 评估维度包含"自举诚实性" |
| R-42 结构优化引入回归 | 低 | 逐域重构 + 每步全链验证 + 契约测试守卫 |

## §8 结论

**GO**：三个结构性缺口（G-BOOT / G-CROSS / G-TOOL）均可通过 M7..M9 闭合，且不破坏现有 26 路由 + 115 测试。自举闭环的核心约束是"评估自身但不自我改码"——这与 12 §2.1 的 R-31 防护一致。跨项目调用的核心约束是"workspace 安全白名单"——这与 11 §C 的配置安全一致。DSH 工具注册的核心约束是"可降级"——这与 INV-24 的"不进硬 inject"一致。

**前置条件**：M7..M9 按 §5 里程碑顺序实现，每个以全链验证收尾。
