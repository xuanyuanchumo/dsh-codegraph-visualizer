# 13 · 智能体编排（A 族）× 功能开关体系（F 族）

> 状态：**设计文档 v1.0（2026-10-13）**。用户需求（m03297）：① 技能插件要有**子代理和对应的 agents 等配置**用于 DSH 调用技能插件；② 技能插件的**功能与流程可独立开启/关闭**（同时不能影响插件使用）。
> 上位文档：[12](12-自进化插件标准与六自能力架构.md)（六自能力/独立性宪章/开发规范）、[11](11-插件功能设计-配置-日志-白盒-响应式.md)（功能面）、[03](03-架构设计草案.md)（L0-L5 与工具/HTTP 面）。沿用 INV-1..28。

## 0. 结论先行

| 族 | 一句话设计 | 关键不变量/守卫 |
|---|---|---|
| **A 智能体编排** | 插件发**资产**（agent 角色卡）+ **配方**（编排文档）+ **执行面**（anic_* 工具与 HTTP API）；DSH 的会话/子代理经工具面调用插件，角色从关键词计数升级为真 LLM 子代理 + 证据契约 | 工具白名单 schema 校验（R-34）；每卡 autonomyBand 受授权带约束 |
| **F 功能开关** | 三层开关（用户 > 工作区 > 部署）+ 每开关声明**关闭形态契约**；**核心链路不可关**，关闭=降级与隐藏，不是拆除 | **INV-29** 核心链路不可关；**INV-30** 全开关可观测；**G-TOGGLE** 特性必须注册开关 |

## 1. A 族：子代理与 agents 配置（DSH 如何调用技能插件）

### 1.1 诚实前提（双向证据纪律）

- 插件在宿主侧**能注册的公共面**是：工具（`ctx.tools.register`，03 §7 的 anic_* 工具面）、HTTP 路由（03 §8）、客户端槽位。**agent preset 的注册是宿主/部署概念，未发现插件可用的注册 API**（按 07 §2.3 双向证据规则，不发明不假设）。
- 因此"Dsh 调用技能插件"的真实形态是三条：**工具面**（任何 DSH 会话/子代理直接调用）→ **编排配方**（人类或 Team Lead 按配方派子代理）→ **资产卡**（配方引用的角色定义）。技能 `multi-agent-gate.mjs` 的 5 门 × 3 角色是同构原型，但其"agent"是关键词计数（S-5 家族）；本设计升级为**真 LLM 子代理**（M0-② 已证 `ctx.llm` 服务面可用，接入形态按 03 §6）。

### 1.2 agent 资产卡（`dsh-anic/assets/agents/*.md`，自举可覆盖）

每张卡一个角色，字段闭合（schema 校验，未知字段拒绝=INV-19）：

| 字段 | 语义 | 约束 |
|---|---|---|
| `id` / `role` | 角色标识与职责一句话 | 与门定义（GateRegistry）引用名一致 |
| `gate` | 服务的门（intent/spec/plan/pr/release…） | 必须是已注册门 |
| `systemPrompt` | 角色 system 提示（结构化输出协议内嵌） | 要求闭合 JSON 输出 + `evidenceIds` 必填 |
| `toolsAllowlist` | 可调用工具白名单 | 仅 `anic_*` 只读工具 + 显式列名的写端点；宿主只读工具需逐个列名（默认白名单为空） |
| `autonomyBand` | 该角色的自主级上限 | ≤ 授权带（05 §5.2）；破坏性动作不入任何卡 |
| `outputContract` | 输出闭合 schema（结论/置信来源/证据引用） | `evidenceIds` 非空且在注入集合内（INV-23）；不满足即 `doubt` |
| `escalation` | 何时升级人类门 | 指向 HITL 队列（12 §2.6） |

- **分发与覆盖**：出厂卡随插件 `assets/agents/` 分发；`anic_self_init` 复制到目标工作区 `.cycles/agents/`，工作区卡优先（可定制不改插件本体）；卡加载即 schema 校验，非法卡**拒绝加载并响亮**（不静默跳过）。

### 1.3 DSH 调用面（三条路径，全部已取证可行）

1. **工具面（最低保证）**：插件注册的 `anic_*` 工具对所有 DSH 会话可见——包括用户手动开的会话、`subagent`/Agent Teams 派生的子代理。工具描述自带用法契约（参数、幂等键、返回 shape）。这是"Dsh 调用技能插件"的兜底路径，不依赖任何编排设施。
2. **编排配方（orchestration recipe）**：`docs/anic/agents/orchestration.md` + 任务板 prompt 模板（`team_task_create` 可直接粘贴）——Team Lead 按门拆子代理（每门并行 3 角色：规划/实现/评审），汇总 `trustScore` 后过 gatekeeper；配方明确：每张卡的工具白名单、证据要求、失败即 `doubt`、门禁不自动通过。
3. **HTTP 面**：`/anic/api/*` 供无工具环境的脚本代理使用；写端点必带 `requestId` 幂等键（08 §3.3）。

### 1.4 与六自能力的关系

- 子代理是**全自主的手**（12 §2.6）：L3/L4 的自主动作由子代理执行，但每张卡的 `autonomyBand` 受授权带约束、`outputContract` 强制 INV-23/INV-28、escalation 终点是人类门队列。
- **R-36 编排成本**：每门 3 子代理有真实开销——Tier-1 确定性门能裁决的不升 Tier-2；每 cycle 子代理数上限纳入 ArtifactBudget 类治理（08 §3）。

## 2. F 族：功能与流程独立开关（关而不残）

### 2.1 三层开关模型（与 11 §C-1 配置三层同构）

| 层 | 载体 | 生效时机 | 适配 |
|---|---|---|---|
| L-用户 | 客户端 prefs（`dsh-anic.prefs.v1`） | 即时（不重载） | 所有 UI 流 |
| L-工作区 | `.cycles/config.yml` 的 anic 段（唯一 loader，INV-25） | 下次快照/会话 | 流程与门禁行为 |
| L-部署 | 宿主 bundle config（cordis.patch.yml，M2 显式） | 重启宿主 | 部署级禁用 |

- **合并规则**：越具体越优先（用户 > 工作区 > 部署）；冲突在诊断面板显示每个开关的**生效值 + 来源层**（INV-30）。未知键只警示不拦截（11 §C-2 刻意差异）；开关值非法 → **fail-safe 回默认值并响亮告警**（S-1 教训：不许静默兜底）。

### 2.2 开关清单（首版，随特性注册表增长）

| 开关 id | 控制什么 | 关闭形态（degradation contract） |
|---|---|---|
| `flow.workflowTab` | ANIC 标签槽位 | unregister 槽位（既有 disposer 路径，热重开已验证）；宿主路由/工具**照常** |
| `flow.stepTrace` | 白盒流程分区 | 分区隐藏，其余分区/数据不受影响 |
| `flow.diagnostics` | 诊断面板 | 面板不注册；遥测仍在内存环形缓冲（不丢证据） |
| `flow.approvals` | 批准卡/HITL 队列 | 队列只读展示 + 指引改走技能 CLI（自主级自动降 L2） |
| `flow.autoRefresh` | live 轮询/刷新 | 回退手动刷新按钮（V-1 条件请求仍在） |
| `flow.gateRecord` | 门禁结果自动入账本 | 不自动记账，UI 显式标注「未入账本」（诚实降级） |
| `flow.budgetEnforce` | 预算熔断 | 降级为只告警不熔断（显示风险横幅） |
| `flow.selfInit` | 自举命令 | 命令返回响亮禁用提示 |
| `flow.agentsOrchestration` | 子代理编排流 | 编排配方标记停用；工具面照常（手动编排不受影响） |

### 2.3 核心链路不可关（INV-29）

- **标签壳 + 快照数据路由（`/anic/api/workflow-snapshot`）+ 只读工具**是插件存在的底线，**不在可关清单**；任何一层配置试图关闭核心链路 → 配置校验直接拒绝该键（错误文案列出可关项）。
- 关闭任一 flow 后必须满足：其余 flow 正常、数据路径正常、诊断面板可解释当前状态（"哪些开着、哪些关了、谁关的"）。

### 2.4 关闭即降级（不是拆除）

- UI 流关闭 = unregister 槽位/隐藏分区 + 遥测记 `flow-disabled` 事件 + 诊断面板禁用清单；**重开即热重注册**（M0-① 已验证 unregister→reregister 路径）。
- 宿主流关闭（gateRecord/budget/selfInit/agents）= 对应路由与编排返回响亮的禁用响应（结构化错误码 `ANIC_FLOW_DISABLED_<ID>`，不是 500）。

### 2.5 守卫

- **G-TOGGLE**：`client/features/<f>/` 与宿主流模块**必须注册开关并声明关闭形态**；守卫扫描特性模块清单与开关注册表对齐（缺注册即 FAIL；三条守卫纪律照旧）。
- **INV-29** 核心链路不可关；**INV-30** 全开关可观测（诊断面板列出全部开关：id/生效值/来源层/关闭时间）。
- **R-35 组合爆炸**：关闭形态契约化（每开关只有一种关闭形态）+ 组合测试抽样（核心链路 + 任一 flow 关闭的最小组合矩阵），不做 2^n 全组合。

## 4. 风险

- **R-34 角色卡漂移**：卡引用的工具/门与注册表不同步 → 卡加载即 schema 校验 + 未知工具名拒绝（INV-19）+ 契约测试钉住工具白名单清单。
- **R-35 开关组合爆炸**：见 §2.5（契约化关闭形态 + 抽样组合矩阵）。
- **R-36 编排成本**：见 §1.4（Tier-1 优先 + 每 cycle 子代理预算上限）。
