## 1. 独立性分析

### 1.1 包级独立性 — ✅ 通过

```
dsh-anic/package.json:
  name: "dsh-anic"
  version: "0.2.0"
  dependencies: （无）
  peerDependencies: （无）
  无任何 dsh-codegraph-visualizer 引用
```

dsh-anic 是**完全独立的 npm 包**，不依赖父项目 dsh-codegraph-visualizer 的任何代码、类型或运行时。符合 docs/anic/12 §1 独立性宪章 6 条中的源码零依赖（G-IND）、可迁移（路径无关）、父项目仅验证场三条。

### 1.2 源码分层 — 两层架构

dsh-anic 源码自然分为两层：

**独立层**（读 `.cycles/` 工件，不调用技能脚本）：

| 模块 | 文件 | 功能 |
|---|---|---|
| 可视化 | snapshotCore.ts, WorkflowGraphPanel.ts, gateColors.ts, renderStepTrace.ts, renderDiagnostics.ts, prefsDrawer.ts | 快照生成+图渲染+门禁三态色+面板 |
| 运行时 | ledger.ts, segmentedLedger.ts, stateMachine.ts, stackProbe.ts, cycleRunner.ts | 账本+状态机+多栈+cycle 生命周期 |
| 进化 | trustModel.ts, autonomyGovernor.ts, patchEngine.ts | 信任分+8 熔断+tech-debt 提案 |
| 治理 | archiver.ts, budget.ts, sweep.ts, prune.ts | 归档+预算+清扫+孤儿检测 |
| LLM 评审 | reviewEngine.ts | ctx.get('llm') 探测+闭合 JSON fail-closed |
| 配置 | config.ts | .cycles/config.yml 唯一 loader |
| 共享 | flows.ts, errors.ts, fs-safe.ts, stepTrace.ts | 开关+错误码+原子写+四源投影 |
| 路由 | snapshot/stepTrace/selfCheck/cycle/ledger/segmentedLedger/review/evolution/governance | 26 路由全原生 |

**技能依赖层**（调用技能脚本 via `resolveSkillScriptsDir`）：

| 模块 | 文件 | 依赖方式 |
|---|---|---|
| 自举初始化 | selfInitRoute.ts | spawnSync `init-workflow.mjs` |
| 脚本调用器 | skillInvoker.ts | 15 脚本白名单 + spawnSync |
| 自举闭环 | selfBootstrapRoute.ts | spawnSync `eval-runner` + `gate-check` + `auto-fix-loop` |
| 跨项目 | skillRoute.ts | spawnSync 任意白名单脚本 |
| DSH 工具 | tools.ts | 6 工具均调 resolveSkillScriptsDir |

**关键事实**：`resolveSkillScriptsDir` 在 5 个文件中出现 24 次，全部在技能依赖层。独立层零引用。grep `.dsh/skills` = 9 命中，全在技能依赖层。

### 1.3 裁决

> **dsh-anic 无需项目技能即可运行**——独立层（可视化+运行时+进化+治理+LLM 评审）完全自足，只读 `.cycles/` 工件。技能依赖层在技能缺席时优雅降级：`resolveSkillScriptsDir` 返回 null → 路由返回 404 响亮报错，不崩溃。
>
> **但**：自举闭环（M7）、跨项目调用（M8）、DSH 工具（M8）三个里程碑的功能在技能缺席时不可用。这是**设计意图**（12 §1.5 宿主假设最小化），不是缺陷——这些功能本质上就是"调用技能脚本"，没有技能就没有调用对象。

## 2. 安装模型分析

### 2.1 当前安装形态

```
技能 ai-native-iteration-cycle:
  位置: .dsh/skills/ai-native-iteration-cycle/（项目级文件）
  分发: 无 npm 包，纯文件复制
  安装: 手动放置或 git clone

插件 dsh-anic:
  位置: D:\Projects\...\dsh-anic\（独立工程）
  分发: npm link: 安装到 profile
  安装: profile package.json dependencies + dsh.profile.bundles
```

### 2.2 问题：双体分离

用户问：**"当前要使用技能时技能插件与项目技能需要分别安装吗？"**

**答**：是。当前是双体分离安装：
1. dsh-anic 插件：通过 profile link: 安装（已完成 web + desktop）
2. ai-native-iteration-cycle 技能：通过 `.dsh/skills/` 文件级放置

这意味着：
- 在新工作区使用 dsh-anic 的自举/跨项目功能时，需要同时确保技能在场
- 技能没有独立分发渠道（不是 npm 包）
- 插件无法自动安装技能

### 2.3 三种改进方案

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **A. 内联技能脚本** | 将技能 scripts/ 复制到 dsh-anic/assets/skill-scripts/，resolveSkillScriptsDir 优先查内联 | 完全自包含，单包安装即全功能 | 两份脚本需同步维护 |
| **B. 技能 npm 包** | 将技能发布为 npm 包（如 @deepseek-ai/anic-skill），dsh-anic peerDep optional | 标准分发，版本管理 | 技能非 npm 生态，改造成本高 |
| **C. 混合** | A + 外部覆盖：内联为底座，`.dsh/skills/` 在场时优先用外部（最新版） | 自包含 + 可升级 | resolveSkillScriptsDir 逻辑稍复杂 |

**推荐方案 C**（混合）：内联保证开箱即用，外部覆盖保证可升级。`resolveSkillScriptsDir` 改为：

```
1. workspace/.dsh/skills/ai-native-iteration-cycle/scripts（外部最新，优先）
2. dsh-anic/assets/skill-scripts/（内联底座，兜底）
3. 找不到 → 404
```

## 4. 透明性分析

### 4.1 已建透明性

| 机制 | 位置 | 覆盖 |
|---|---|---|
| StepTrace 四源投影 | shared/stepTrace.ts | workflow-graph × workflow-state × ledger × cycle 工件 |
| 节点详情抽屉 | gateColors.ts renderNodeDetail | 节点类型/状态/门禁裁决/启发式标注 |
| 自检面板 | renderDiagnostics.ts | 6 探针 PASS/FAIL + INV 编号 |
| 偏好抽屉 | prefsDrawer.ts | 9 开关 + 三层来源 + degradation |
| 遥测 | WorkflowTabIntegration.ts | disabledFlows + warnings + 注册/卸载事件 |
| 请求 ID | routeContext.ts makeSend | X-ANIC-Request-Id 贯穿 |

### 4.2 透明性缺口

| 缺口 | 描述 | 影响 |
|---|---|---|
| **G-T1 维度分解** | eval-runner 的 E1-E8 + Q1-Q8 评分不可见 | 用户看不到评估细节 |
| **G-T2 修复迭代** | auto-fix-loop 的每次尝试（改了什么/重新验证结果）不可见 | 修复过程黑盒 |
| **G-T3 信任分** | multi-agent-gate 的 per-agent 信任分不可见 | 门禁决策不可追溯 |
| **G-T4 事故历史** | 熔断/降级事件无时间线 | 自主性变更不可审计 |
| **G-T5 脚本来源** | StepTrace 不标注哪个脚本产出了哪个工件 | 工件来源不透明 |
| **G-T6 cycle 全景** | 单个 cycle 的完整七步流程不可视 | cycle 生命周期黑盒 |

### 4.3 建议补建

1. **G-T1**：stepTrace 加 `evalDimensions?: {id:string, score:number, max:number}[]`，从 .cycles/cycles/cycle-N/test-reports/eval-report.md 解析 E1-E8 + Q1-Q8。
2. **G-T2**：stepTrace 加 `fixIterations?: {round:number, diagnosis:string, patch:string, reverify:string}[]`，从 .cycles/incidents/ 解析。
3. **G-T3**：reviewRoute 响应加 `agentResults?: {agentId:string, verdict:string, confidence:number}[]`。
4. **G-T4**：新建 `host/governance/incidentTimeline.ts`，读 .cycles/incidents/ → 时间线。
5. **G-T5**：stepTrace 每个工件加 `producedBy?: string`（脚本名）。
6. **G-T6**：新建 `client/features/cycleTimeline/renderCycleTimeline.ts`，可视化单 cycle 七步。

## 5. 连通性分析

### 5.1 已建连通性

| 链路 | 路由 | 状态 |
|---|---|---|
| 快照→图渲染 | GET /anic/api/workflow-snapshot → WorkflowGraphPanel | ✅ |
| 步骤追踪→面板 | GET /anic/api/step-trace → renderStepTrace | ✅ |
| 自检→面板 | GET /anic/api/self-check → renderDiagnostics | ✅ |
| 自举初始化 | POST /anic/self/init → init-workflow.mjs | ✅ |
| cycle 创建 | POST /anic/cycle/init → cycleRunner.initCycle | ✅ |
| cycle 推进 | POST /anic/cycle/advance → stateMachine.advance | ✅ |
| 账本追加 | POST /anic/ledger/append → ledger.appendEntry | ✅ |
| LLM 评审 | POST /anic/review → reviewEngine.runLlmReview | ✅ |
| 信任分 | GET /anic/api/trust → trustModel.buildTrustScores | ✅ |

| 归档 | POST /anic/governance/archive → archiver.archiveOldCycles | ✅ |

### 5.2 连通性缺口

| 缺口 | 描述 | 影响 |
|---|---|---|
| **G-C1 全链 cycle** | init→eval→gate→fix→verify→close 不在一流中 | 用户需手动调 6 个路由 |
| **G-C2 多 cycle 编排** | 无"连续跑 N 个 cycle"的编排 | 自迭代不可自动 |
| **G-C3 tech-debt→fix 链** | patchEngine 产 tech-debt 但无路由触发 fixLoop | 修复提案无人执行 |
| **G-C4 熔断→降级→重评** | checkBreakers 输出降级建议但无自动执行 | 熔断后需手动降级 |
| **G-C5 跨项目→自举回写** | skillRoute 跨项目评估结果不回写本插件状态 | 跨项目与自举割裂 |
| **G-C6 DSH 工具→路由** | 6 DSH 工具调脚本但不经过路由层 | 工具与路由两套调用路径 |

### 5.3 建议补建

1. **G-C1**：新建 `POST /anic/cycle/run-full`，编排 init→eval→gate→fix→verify→close 全链，返回每步结果。
2. **G-C2**：新建 `POST /anic/cycle/run-batch`，参数 `{count:N}`，连续跑 N 个 cycle。
3. **G-C3**：新建 `POST /anic/evolution/apply-tech-debt`，读 tech-debt → fixLoop → 重新验证。
4. **G-C4**：autonomyGovernor.decideAction 返回 downgrade 时自动调 config.ts 降级 + 记账本。
5. **G-C5**：skillRoute 跨项目评估结果写回 .cycles/self-bootstrap.json。
6. **G-C6**：tools.ts 改为调路由（HTTP fetch localhost）而非直接 spawnSync，统一调用路径。

## 8. 结论

dsh-anic v0.2.0 已实现十里程碑（M1-M10），覆盖了可视化、运行时、进化引擎、治理、LLM 评审、自举闭环、跨项目调用和 DSH 工具注册。**独立性已达成**（源码零依赖，独立层完全自足）。

三个核心改进方向：
1. **安装自包含**（P0）：内联技能脚本，单包安装即全功能
2. **全链连通**（P1）：cycle 全链编排 + tech-debt→fix 链 + 熔断→降级自动
3. **深度插件化**（P2）：7 个未插件化脚本的原生实现 + 6 个透明性缺口 + 6 个连通性缺口

改进后 dsh-anic 将从"可视化+部分代理"进化为"全功能自包含自举插件"——技能的每一项能力都有原生的插件等价物，且单包安装即可使用全部功能。
