## 2. 反向矩阵：带 J 标注的测试 → 旅程

反向口径：测试文件内的 J 号（头注释或 describe 标题）必须对应旅程表里的同号行。
cycle-103 实测：e2e spec 22 个中 19 个带 J 标注；vitest 198 个中 24 个带 J 标注。
带标注文件的 J 号与旅程表逐号比对 ⇒ 反向缺口 0（所有出现的 J 号都在 J0-J45 内且指向一致）。

**未带 J 标注的文件不代表无旅程覆盖**——反向标注是「从测试找需求」的索引增强，
不是覆盖判定；覆盖判定以正向矩阵为准（每个旅程已有至少一个测试）。
存量未标注文件（vitest 174 个）按「新文件必带标注」政策增量收敛，本轮不追补（登记流转项）。

## 4. 维护规则

- 新增旅程必须同时给出测试文件（否则正向缺口 >0，G2 门禁可见）。
- 新增测试文件必须带 J 标注头注释（e2e 与单测同规则）——`// 旅程覆盖：J38（FR-53 智能缓存/条件请求）` 形式即可。
- 旅程改指向时同步更新本矩阵（本文件是快照+口径，用户旅程.md 是源）。
