## 与 DSH 框架的集成

本流程完全遵循 DSH 官方插件开发规范（九条红线，验证方式见主流程 §2.2）：

| # | 规范项 | 状态 |
|---|--------|------|
| 1 | 注册即 effect（`ctx.effect()` / `ctx.on()` 返回 disposer） | ✅ |
| 2 | waterfall 监听器必须调用 `next()` | ✅ |
| 3 | 跨边界 ID 使用 Branded 类型 | ✅ |
| 4 | 事件经声明合并扩展 | ✅ |
| 5 | 封闭联合以 `assertNever` 收尾 | ✅ |
| 6 | ESM only（包名引用 + `.ts` 本地导入） | ✅ |
| 7 | Host/Client 隔离（tsconfig.host/client 双面） | ✅ |
| 8 | 能力缝三角色完整 | ✅ |
| 9 | 配置显式化 + misconfiguration fails loud | ✅ |

待对齐项（登记技术债务，对齐 DSH配置文档 §6.2）：Profile 分层（`dsh.profile.bundles` 未声明）、事件 waterfall/serial 拦截未使用（当前均为 emit）、session-persistence seam 未接入。

## 使用建议

- **首次使用**：按主流程 §四「开机启动、项目评估与总规划」建立事实基座与项目评估报告
- **每次循环**：工作产物写入活跃工作区 `docs/anchor/cycles/.cycles/cycle-{N}/`
- **Phase 0 例行**：执行附录 D §1.2 依赖健康检查并登记结论
- **收敛判定**：统一执行附录 A 的 G0–G3 门禁
- **评估与度量**：分层测试（UI/Host/契约）、用户旅程 J1–J14、RTM、性能基线、混沌实验、长期愿景评分

## 长期愿景：六维标杆对标（J14，非每循环必测）

本插件最终形态须在六个维度对齐甚至超越标杆代码图谱工具（度量对象为插件最终形态）：

| 维度 | 标杆工具 | 目标 |
|------|---------|------|
| 底层能力 | CodeSee / SourceGraph | 高性能代码解析、跨仓库图谱构建（上游：`dsh-codegraph` / `dsh-tool-lens`） |
| 界面美观 | CodeSee | 现代美观、响应式交互、图谱可视化 |
| 生态繁荣 | SourceGraph | 多语言解析器生态、IDE 插件兼容 |
| AI 能力 | ReadAny | 代码理解、智能推荐、语义搜索 |
| 笔记体验 | Koodo | 知识管理、FTS 集成、标注系统 |

## 性能基线（详见附录C §4）

| 指标 | 门禁值 | 测量方法 |
|------|--------|---------|
| 图谱构建耗时 | < 2 s @ 1000 文件 | vitest 计时（固定数据） |

| 图谱渲染帧率 | ≥ 30 FPS @ 1000 节点 | Playwright performance API |
