# 附录C：评估与度量规范

> 本附录为主流程 `docs/anchor/cycles/项目迭代驱动验证流程.md` 的**评估与度量规范**

## 1. 分层测试与覆盖率门限

| 层 | 测试类型 | 载体/工具 | 门限 |
|----|---------|-----------|------|
| Client UI | 组件/交互/状态 | vitest（`packages/**/*.test.ts`）、Playwright | 关键路径用例通过率 100% |
| Host 服务 | 服务定义/实现/生命周期 | vitest（`tests/unit/*Service*.test.ts` 等） | 业务用例通过率 100% |
| 契约 | 类型对齐/序列化边界 | tsc 双面构建 | 零错位，`pnpm run typecheck` 零错误 |
| E2E | 端到端旅程 | Playwright（`pnpm run test:e2e`） | 覆盖关键用户旅程 J1–J13 |

> **全局覆盖率门限**：以根目录 `vitest.config.ts` 的 `coverage.thresholds` 为唯一强制来源——行 / 函数 / 语句 ≥ 80%、分支 ≥ 65%。调整阈值须修改该配置并同步本表。

**分模块覆盖目标**（对齐 `docs/测试策略.md` §2.1，作为各模块质量目标；低于全局门限的以全局门限为准）：

| 模块 | 目标 |
|------|------|
| CodeGraphService | ≥ 90% |
| GraphDataMerger | ≥ 90% |
| CodeGraphAdapter / LensAdapter | ≥ 85% |
| 工具函数/校验器 | ≥ 95% |
| React UI 组件 | ≥ 80% |

> Mock 策略按 `docs/测试策略.md` §2.3：ctx.fs→memfs、ctx.web→nock、sessions→内存存储、SQLite→`:memory:`、上游工具调用→vitest mock。

## 2. 项目评估维度（E1–E8）

| 维度 | 名称         | 关键问题 | 证据来源 |
|------|--------------|---------|---------|
| E1   | 功能覆盖     | 对照插件功能域清单（图谱构建/可视化/搜索/导航/导出）还缺什么？已实现是否达验收标准？ | 功能清单、J1–J14 |
| E2   | 架构健康     | 两层边界清晰？Host/Client 隔离成立？依赖方向合理？适配器模式隔离充分？ | codegraph 依赖分析、附录 D §5 |
| E3   | 技术债务     | 未收敛循环遗留项、TODO/FIXME 密度、适配器版本锁定 | 代码扫描、复盘记录、附录 D §4.2 |
| E4   | 测试成熟度   | 分层测试缺口、RTM 未映射功能、覆盖率是否达 vitest.config.ts 门限 | 测试报告、覆盖率报告 |
| E5   | 性能与稳定   | 图谱渲染帧率/内存占用/数据更新时延对比基线（§4） | Playwright 计时、Chrome DevTools |
| E6   | 安全与可访问 | XSS 转义/路径校验/cordis 权限面、a11y、依赖审计 | 安全扫描、a11y 检查、audit 命令 |
| E7   | 创新差异化   | 本插件是否有独特差异化价值（多数据源融合、实时图谱渲染）？长期愿景评分趋势是否向好？ | 创新点清单、长期愿景评分（§9） |
| E8   | 多源对照增强 | 对照主流开源代码图谱工具机制是否对齐并可增强？ | 多源对照矩阵（§8） |

## 3. 用户旅程 J1–J14（重映射至插件功能域）

| 旅程 | 名称 | 关键路径（正向） | 反向/异常场景 | 主验证载体 |
|------|------|-----------------|--------------|-----------|
| J1 | 仓库导入与校验 | 导入本地仓库 → 校验 → 扫描入库 | 损坏仓库拒绝、超大仓库上限 | tests/unit/FileValidator.test.ts、e2e local-repos |
| J2 | 图谱构建与可视化 | 仓库扫描 → AST 解析 → 图谱生成 → 画布渲染 | 超大文件解析超时、循环依赖 | tests/e2e/large-repo.spec.ts |
| J3 | 代码搜索 | 关键词查询 → FTS5/倒排索引 → 结果定位 | 空索引、特殊字符、FTS5 降级路径 | MetadataStore/CodeGraphService 测试 |
| J4 | 符号导航 | 点击符号 → 跳转定义/引用 | 跨文件符号、未解析符号 | tests/unit/SymbolResolver.test.ts |
| J5 | 依赖分析 | 生成依赖图 → 循环检测 → 高亮 | 深层嵌套依赖、外部依赖不可达 | tests/unit/DependencyService.test.ts |
| J6 | 图谱布局与交互 | 拖拽/缩放/筛选 → 布局更新 | 极端节点数（>10000）、布局算法超时 | Cytoscape.js 布局测试 |
| J7 | 导出与分享 | 选择格式 → 导出 → 下载 | 导出格式不支持、大图谱导出超时 | tests/unit/ExportService.test.ts |
| J8 | 主题与个性化 | 主题切换 → 布局偏好 → 持久化 | 主题配置冲突、偏好重置 | tests/unit/SettingsService.test.ts |
| J9 | UI 与 Host 边界 | React 组件经 Host 取数 → 状态同步 | Client 越权访问 Host 内部 | typecheck 双面 + UI 用例 |
| J10 | 异常恢复与容错 | 断网/崩溃后恢复 | 缓存损坏、上游工具不可用 | tests/e2e/chaos.spec.ts |
| J11 | 插件生命周期合规 | effect 注册 → dispose 清理 → 重载无泄漏 | 监听器泄漏 | 评审 + 生命周期用例 |
| J12 | 大仓库性能 | 万级文件仓库 → 渐进式构建 → 进度反馈 | 内存溢出、构建中断恢复 | tests/e2e/large-repo.spec.ts |
| J13 | 多仓库管理 | 多仓库并存 → 切换/合并/对比 | 仓库间符号冲突、路径重复 | tests/unit/CodeGraphService.test.ts |
| J14 | 六维标杆对标 | **长期愿景层**：评分趋势跟踪，不设每循环强制门禁 | 任一维度长期停滞 | §8/§9 对照矩阵 |

## 4. 性能门禁（两级）

### 4.1 项目性能门禁（目标层）

| 指标 | 门禁值 | 测试方法 |
|------|--------|---------|
| 图谱构建 | < 2s @ 1000 文件 | 导入 1000 文件仓库后重启 |
| 仓库扫描 | < 5s @ 500 文件 | 扫描中等规模仓库 |
| 搜索查询 | < 500ms @ 10000 节点 | 万级节点中搜索 |
| 图谱渲染 | ≥ 30 FPS @ 1000 节点 | Playwright performance API |
| 内存占用 | < 200MB | 打开大仓库后空闲 |
| 导出耗时 | < 3s @ 1000 节点 | 导出 JSON 格式 |

> 部分指标依赖万级节点数据集落地；未具备测量条件前，以 §4.2 当前可测代理基线执行回归对比，规模形态落地后切换至本表并校准。

### 4.2 当前可测代理基线（现有数据即可测量）

> 初版基线值由首个循环用固定数据校准后固化；此后作为回归对比基准。

| 指标 | 门禁值 | 测量方法 |
|------|--------|---------|
| 图谱构建耗时 | < 2 s @ 1000 文件 | vitest 计时（固定数据） |
| 搜索查询时延 | < 50 ms @ 10^4 节点 | vitest `:memory:` 计时 |
| 数据适配器转换延迟 | < 100 ms @ 1000 节点 | vitest 计时 |
| 页面内存峰值 | 浏览器页签配额内无告警 | Playwright + performance.memory 采样 |

## 9. 创新差异化评估（长期愿景层）

| 维度 | 评估要点 | 目标方向 |
|------|---------|---------|
| 界面美观 | 现代 UI/动效/图谱可视化 | 对齐 CodeSee |

| 笔记体验 | 知识管理/标注系统集成 | 渐进引入 |
