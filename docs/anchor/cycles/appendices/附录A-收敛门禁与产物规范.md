# 附录A：收敛门禁与产物规范

> 本附录为主流程 `docs/anchor/cycles/项目迭代驱动验证流程.md` 的**权威判定与产物规范**

## 1. 收敛门禁 G0–G3（不降级）

| 门禁 | 名称           | 判定标准（全部满足才通过） | 违反后果 |
|------|----------------|---------------------------|---------|
| G0   | 评估基线就绪   | 本循环《项目评估报告.md》已产出且覆盖本循环范围；**事实基座抽验通过**（抽验本循环将引用的 ≥5 条文档路径/命令在仓库真实存在，失败先修文档） | 禁止进入拆测/验证 |
| G1   | 任务清单清零   | P0-P3 全部任务已登记（含归属层：UI/Host/契约）；无未分配的测试用例 | 禁止进入下一循环 |
| G2   | 测试报告零错误 | 最新测试报告中：失败=0、错误=0；RTM 无缺口；J1–J13 覆盖零缺口；既有混沌用例全过、缺口已登记 | 禁止进入 Release |
| G3   | 构建零失败     | Debug 构建 = `pnpm run build` 通过；Release 构建 = `pnpm run build` + `pnpm run hygiene` 通过；冒烟(P0) 与全量回归全通过 | 禁止提交、禁止交付 |

> 门禁执行顺序：G0 → G1 → G2 → G3。任何门禁失败即停止流转并登记。

## 3. 产物内容最低要求

### 3.1 项目评估报告（G0 依据）

按 `templates/项目评估-template.md` 填写：三层评估摘要（Client UI / Host 服务 / 契约）、E1–E8 八维评估结论 + 证据、P0–P3 评估问题清单（含归属层）、与上轮趋势、本循环范围建议。

### 3.2 测试报告（每次验证必产）

必须包含六要素：**通过数 / 失败数 / 断言明细 / 日志 / 复现步骤 / 手工操作记录**；涉数据适配器/融合器变更附复杂度说明与基准数据（附录 D §5.3）。

### 3.3 页面状态

按真实功能域分组的验证矩阵 + P0-P3 问题清单，每行包含：功能项、验证结果（通过/失败/未覆盖）、问题级别、关联用例 ID。

### 3.4 任务清单

P0-P3 分级 + 拓扑排序（依赖在前）；每项绑定测试用例 ID 与文档变更项；归属层标注 UI/Host/契约；全部完成（含文档项）才可标记 completed。

## 4. 归档规则

- 收敛通过的循环：产物保留于循环工作区 `docs/anchor/cycles/.cycles/cycle-{N}/`
- Release 交付产物：按 `templates/交付清单-template.md` 打包为 `交付清单.md`
- 技术债务：登记至 `docs/anchor/cycles/.cycles/tech-debt/技术债务台账.md`

## 5. 验证签名

交付清单中的「验证签名」字段由执行者填写：`{执行者}-{日期YYYYMMDD}-{G0/G1/G2/G3 通过}-{报告路径}`
