# 交付清单 Template

> 来源：`docs/anchor/cycles/项目迭代驱动验证流程.md` §7
> 命名：`交付清单.md`；置于循环工作区 `docs/anchor/cycles/.cycles/cycle-{N}/`（仅最终循环）。**必须**包含以下 8 项内容，未齐不得视为交付完成。

## 1. 头部

| 字段         | 值                                   |
| ------------ | ------------------------------------ |
| 日期         | YYYY-MM-DD                           |
| Release 版本 | （workspace 各包 package.json version 一致值为单一来源） |
| 执行者       | AI-L4 全自主 / AI-L3 监督自主 / 人工 |

## 2. 交付项清单

| #   | 交付项           | 说明/路径                                                 |
| --- | ---------------- | --------------------------------------------------------- |
| 1   | Release 构建产物 | TS 构建输出（`pnpm run build`：host+client+web） |
| 2   | 最终测试报告     | 含全部测试结果及覆盖率（`test-reports/`）                 |
| 3   | 非功能验证报告   | 性能/内存/安全（`非功能验证报告.md`）           |
| 4   | 验证签名         | 见 §3                                                     |
| 5   | 文档更新记录     | 本次交付涉及文档变更清单（含互引一致性）                  |
| 6   | 环境配置说明     | Node 版本快照、数据基线                    |
| 7   | 数据清理记录     | 临时数据清理情况（P10）                                   |
| 8   | 审计日志         | H1–H4 自动评估记录 + 熔断/恢复记录（`审计日志.md`，主流程 §3.4） |

## 3. 验证签名

- 格式：`{执行者}-{YYYYMMDD}-{G0/G1/G2/G3 通过}-{报告路径}`
- 示例：`AI-20260807-G0G1G2G3-pass-test-reports/test-report_20260807_103000.md`

## 4. 门禁确认

| 门禁              | 状态 | 依据 |
| ----------------- | ---- | ---- |
| G0 评估基线就绪（含事实基座抽验） |      |      |
| G1 任务清单清零   |      |      |
| G2 测试报告零错误 |      |      |
| G3 构建零失败（Debug+Release 矩阵） |  |      |
