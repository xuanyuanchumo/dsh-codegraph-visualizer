# 07 · 界面与功能域规划

> 面向改 `src/client/**` 界面层与入口通道的开发者。
> 文档族版本 1.0.0 · 适用插件版本 0.2.0 · cycle-110 首次落地（T3 ui-ux）

本文件回答三个问题：**功能该长在哪个域里**、**它从哪条通道进入界面**、**哪条用例会为它变红**。
所有断言都带 `path:line`；没有机器守卫的项在 §8 显式标注。

---

## 1. 三个层次，不要混为一谈

| 层 | 含义 | 例子 | 谁决定 |
|---|---|---|---|
| **入口通道** | 用户从宿主界面的哪个位置进入插件 | 主会话顶部标签、右侧栏 tab、页脚按钮、浮动面板 | DSH 席位声明 + 本插件优先级链 |
| **功能域** | 进入之后看的是哪一类信息 | 结构 / 行为 / 运行时 / 对比 / 设置 | `ViewMode` + `ViewLayer`（`src/shared/viewModeUtils.ts`） |
| **界面组件** | 域内的具体控件与面板 | 工具栏、面板栈、叠加层、状态栏 | `src/client/components/**` |

一条常见的错误是把三者压成一层（例如「加个侧边栏页面放调用图」）：
入口通道是**互斥资源**（同一面板只该有一个入口，§3），功能域是**正交的视图模式**（§2），
组件是**可复用的呈现**。混在一起就会出现「运行时层里挂了图例却点不动」这类缺陷。

## 3. 入口通道矩阵（互斥资源）

`src/client/index.ts:71-102` 的调用顺序**即优先级**。cycle-110 起顶部标签改为
「预留 → 确认 / 超时 → 迟到撤回」，实现于 `src/client/integrations/IntegrationState.ts:130-232`。

| 优先级 | 通道 | 席位 / API | 注册时机 | 让位规则 | 可观测标记 |
|---|---|---|---|---|---|
| 1 | 顶部标签 | `ctx.slots.inject('conversation.view')` + `register({order:100})` | **异步**（席位声明后） | 预留期间其余通道**排队**（`deferIfTopTabPending`，`:180`）；超时 600ms（`:26`）后释放 | `<html data-cg-top-tab>` = `reserved`/`registered`/`failed`/`expired`/`degraded`/`unavailable`/`withdrawn`（`integrations/topTabObservability.ts`）；面板包装节点 `data-cg-top-tab="instance"` |
| 2 | 右侧栏 tab | `sidebarRightTabs` + `sidebar.right.pane.tab` | 异步 `ctx.inject` | 注入回调内再判 `navButtonRegistered`，已占位则让位 | 集成模式 `sidebar-right` |
| 3 | better-sidebar | `betterSidebar.registerTab` | 同步探测 | `navButtonRegistered` | 集成模式 `better-sidebar` |
| 4 | 页脚按钮 | `sidebar.footer.action` | 同步 inject | `navButtonRegistered` | 集成模式 `slot` |
| 5 | 浮动面板 | 自绘 `.cg-floating-container` | 同步 | `navButtonRegistered` | 集成模式 `floating` |

三条不能违反的约束：

1. **`navButtonRegistered` 是「有人占位」的唯一标记**；预留也置真（`:136`），
   所以降级通道必须先问 `deferIfTopTabPending`、再问 `navButtonRegistered`，
   顺序反过来就会丢掉整档优先级。
2. **失败必须能降级**：注册抛错 / 未返回 disposer / 超时 → `failTopTab` / `expireTopTab`
   （`:153`/`:165`）释放预留并按**调用顺序**回放排队通道。
   只预留不超时会让最小 profile（没有会话面板）**一个入口都没有**。
3. **迟到注册要收回成命**：顶部标签晚到时会执行降级席位的撤回器（`noteFallbackSeat`，`:192`），
   最终收敛为「顶部标签是唯一入口」（状态历史里留下 `withdrawn`）。

### 3.1 「快照为假」不等于「以后也没有」（cycle-110 / C1）

`apply()` 是同步一次性的，而 `compat.detectFlags()` 只是一瞬间的读数；`ctx.get(name, false)`
读不到「提供者 fiber 还在 loading」的服务（`cordis/lib/index.js:763-772`），
真机 `better-sidebar pending` 已证明**提供者晚到是常态**。因此三条互斥通道的
`if (!state.flags.x) return;` 全部改成「同步占位保留 + 快照为假可观测 + 服务晚到重试」：

| 通道 | 快照为假时 | 实时复核 | 晚到落地后的状态 |
|---|---|---|---|
| `conversation.view` | 写 `snapshot-miss` + `unavailable` | `ctx.get('slots', false)`（快照可能是旧的） | `late-registered` |
| `sidebar.right.pane.tab` | 写 `snapshot-miss`，**照旧**调 `ctx.inject(['sidebarRightTabs'])` | 注入即响应式触发器 | `late-registered` |
| `betterSidebar` | 写 `snapshot-miss` | 实时 `ctx.get('betterSidebar', false)` | `late-registered` |

重试用 `ctx.inject([service])` 当触发器，**回调里重跑的是同一条通道函数**，
因此仍然经过同一条同步优先级链的闸门（预留 → `navButtonRegistered`）：
更好的通道已占位时它记为 `yielded` 并让位，不会双入口，也不会造成优先级反转。
每条通道最多重试 3 次（`MAX_CHANNEL_RETRIES`），否则「注入回调立刻触发 → 重跑 → 再登记」
会形成自激循环。

可观测标记（`src/client/integrations/integrationProbe.ts`）：

```
<html data-cg-channel-conversation-view="late-registered"
      data-cg-channel-sidebar-right="snapshot-miss"
      data-cg-channel-better-sidebar="retry-pending"
      data-cg-channel-slot="registered"
      data-cg-channel-floating="registered">
```

状态集：`snapshot-miss` / `retry-pending` / `registered` / `late-registered` /
`yielded` / `failed`；另有 `window` 上的 `codegraph-visualizer/integration-channel` 事件。
真机排查顺序：**先读这个属性**，再怀疑注册代码——「没注册上」和「注册了但被切掉」是两回事。

跨源（`@linxin666/dsh-remote-web-ui`）的真实关系见 `src/client/styles/responsive.css:885-914`：
它不提供任何 panel/tab API，只占 `sidebar.footer.action` 席位并写 `body.dsh-remote-portrait` 标记，
因此本插件**适配版面**而不是调用它的接口。跨源读不到数据属于宿主 CORS 头问题，
真源是 `src/host/HttpHelpers.ts:116` 的 `buildCorsHeaders`（**不是本文档的写域**，见 §8）。

> **「标签不在标签栏」≠「注册失败」**（cycle-110 实测）：`dsh-client-ui-conversation`
> 用 `visibleTabs = preferred.slice(0, visibleViewLimit)` 渲染标签栏，`visibleViewLimit`
> 来自标签行上的 `ResizeObserver`，被挤掉的项进入「更多会话视图」菜单
> （`pinned: !unpinned.includes(id)` 决定是否固定）。同一份代码在 1540px 下
> 并排显示「对话 / 轨迹 / 代码图谱 / ANIC」四个同级标签，在 440px 下「代码图谱」
> 落在溢出菜单里。因此排查顺序是：先读 `document.querySelectorAll('[role="tab"]')`
> **加上**当前宽度，再看本插件的 `data-cg-top-tab` 状态，最后才怀疑 slot 注册代码。

## 4. 界面组件分层

```
GraphPanel                  面板根：data-cg-integration / data-cg-tier / data-cg-sheet
├─ Toolbar                  四组：Workspace · ViewMode · Actions · Settings
│   ├─ toolbar/ToolbarWorkspace      统计 + 工作区选择
│   ├─ toolbar/ToolbarViewMode       布局 / 视图模式 / 层级（紧凑档退化为图标）
│   ├─ toolbar/ToolbarActions        数据下拉 + 搜索 + 工具下拉（分段）+ 刷新/历史
│   └─ toolbar/ToolbarSettings       导出下拉 + 更多下拉（分段）+ 折叠
├─ LeftPanelStack            搜索 / 路径 / 规则 / 详情（均为可关闭面板）
├─ OverlayBar · FocusModeBar · MicroFunctionBar · 预算提示
├─ RightPanelStack           分析类面板（热区/上帝模块/核心函数/死代码/运行时/对比）
├─ 叠加层：Legend / MiniMap / GraphCanvasControls
└─ StatusBar · ResizeHandle
```

下拉与浮层的**统一实现**是 `components/Dropdown.tsx`：内容 portal 到 `document.body`、
用 `position: fixed` + `--cg-portal-*` 自定义属性定位、`resize` + **`scroll` capture:true**
重新测量（`:143`），窄面板（≤320px）退化为贴底抽屉（`:98-107`）。
不要在组件里再写一套 `position: absolute` 的下拉：容器 `overflow` 会裁掉它，
而 `position: fixed` 若漏掉 `capture: true` 的滚动监听，滚动 100px 菜单就会飘走 106px。

## 5. 响应式：三档 + 两套机制 + 窄档抽屉

| 档位 | 阈值 | 判定来源 | 表现 |
|---|---|---|---|
| wide | ≥ 768px | `useElementWidth`（工具栏）/ `usePanelTier`（面板） | 值文本 + 分隔符 + 独立搜索按钮 |
| compact | 480–767px | 同上 | 图标触发器、去分隔符、值进 title |
| narrow | < 480px | 同上 | 搜索收进「更多」；详情面板改**底部抽屉**；抽屉打开时小地图/图例让位 |

- JS 侧阈值：`UI.TOOLBAR_BREAKPOINT_COMPACT_PX/NARROW_PX`（`src/shared/constants.ts:394-395`）
  与 `PANEL_TIER_*`（`src/client/hooks/usePanelTier.ts:14-15`）—— 两组必须相等，由
  `tests/unit/panelTierContract.test.ts` 钉住。
- CSS 侧：`@container graphpanel (max-width: …)` 为主机制；`[data-cg-tier="narrow"]`
  为兜底（宿主无容器查询、或 `@supports not` 只能用**视口**媒体查询而 DSH 面板宽度与视口无关）。
  **两套机制声明必须逐条等价**，`panelTierContract.test.ts` 解析后逐属性比对。
- 窄档抽屉：`.cg-node-detail-panel` 改为贴底全宽、`max-height: 52%`；抽屉打开时
  `data-cg-sheet="open"` 让小地图/图例 `display: none`（`src/client/styles/responsive.css:940-987`）。
  这个标记由 `components/panelSheet.ts` 的纯函数生成，组件只转述事实。

**工具栏常驻**：`responsive.css:926` 用一条 `[data-cg-integration]:not(.cg-collapsed)`
规则保证任何集成模式下工具栏都不被空态/加载态/窄档挤掉；`:not()` 是必要的，
否则它会把折叠成 52px FAB 时的 `display:none` 一起覆盖掉。

## 6. 「技能 / 插件能力面」如何进入界面

DSH 的能力面有三类，本插件只使用前两类：

| 能力面 | 是否为插件自有 | 本插件如何整合 | 依据 |
|---|---|---|---|
| **插件自有面板** | 是 | 全部界面都在插件自己的 React 树里（`GraphPanel` 及其子组件），宿主只给一个容器 | `src/client/GraphPanel.tsx` |
| **DSH 席位（slot / tab）** | 否，宿主托管 | 顶部标签 `conversation.view`、右侧栏 `sidebar.right.pane.tab`、页脚 `sidebar.footer.action` | §3；席位契约见 `docs/agents/03-客户端API参考.md` §2 |
| **技能（`/` 斜杠命令）** | 否，命令贡献面 | 通过 `ctx.commandUi.register` 贡献命令，**不占席位**（与入口正交） | `src/client/integrations/CommandUiIntegration.ts` |

**判断新功能该放哪**：

1. 需要一块持续存在的画布/面板 → **插件自有面板**（加组件 + 域矩阵一行）。
2. 需要一个「用户能点进来」的入口 → **DSH 席位**（走 §3 的优先级链，不要自建第六通道）。
3. 需要一个「用户能调用一次」的动作 → **斜杠命令**（`commandUi`），并且必须**幂等**：
   命令不持有席位，重复注册只会多一条命令。
4. 需要工具（模型可调用）→ 宿主 `ctx.tools.register`（`src/tools.ts`，**不属于界面层写域**）。

> 反例（历史）：`spotlight` / `remoteWebUI` 两个「看起来应该有」的服务在任何 DSH 代都不存在，
> 曾各自生成一条永不执行的集成分支。判定方法见 `docs/agents/03-客户端API参考.md` §3.2：
> **静态 `provide(` 扫描 + 真实 `ctx.get` 调用点**，缺一不可。
