## 2. 两个数据库，两种生命周期

这是最容易搞错的一点：**仓库里有两个不同的 SQLite 文件**。

| 文件 | 路径 | 谁写 | 谁读 | 内容 |
|---|---|---|---|---|
| `codegraph.db` | `<workspace>/.codegraph/codegraph.db` | **上游 `dsh-codegraph` CLI** | 本插件只读 | `nodes` / `edges` 表（AST 索引产物） |
| `viz.db` | `<workspace>/.codegraph-visualizer/viz.db` | **本插件** | 本插件 | 快照、分析结果、用户偏好、布局预设 |

### 2.1 上游库：只读，路径必须校验

`src/adapters/CodeGraphAdapter.ts:310`：

```ts
export function resolveDbPath(workspacePath: string): string {
  const root = workspacePath && workspacePath !== '.' ? workspacePath : process.cwd();
  const normalized = normalize(root);
  if (normalized.includes('..')) throw new Error(`Invalid workspace path: ${workspacePath}`);
  return join(normalized, '.codegraph', 'codegraph.db');
}
```

> 注释明确：**调用方必须先经 `resolveWorkspaceFromRequest` 或 `validateWorkspacePath` 校验**，
> 本函数只做最后一道 `..` 兜底。安全边界在 `src/host/security.ts`，不在适配器。

读取入口：`readGraphFromDb`(`:320`)、`readGraphFromDbPaged`(`:363`)、`readTopLevelNodesFromDb`(`:426`)、
`readNodeChildrenFromDb`(`:441`)、`readFileOutlineFromDb`(`:460`)、`readSymbolASTFromDb`(`:474`)、
`readEdgesFromDb`(`:510`)、`readIncidentEdgesWithFilePathsFromDb`(`:545`)、
`readEdgesForNodesFromDb`(`:607`)、`readFilesFromDb`(`:657`)。
连接经 `closeAllDbConnections()`(`:60`) 在插件卸载时统一关闭。

### 2.2 自有库：4 张表

| 表 | 主键/唯一键 | 用途 |

### 4.2 按需加载（本项目的主干特性）

用户展开一个节点时，**不重取整图**，而是按需拉四个层次：

```
expandNode(nodeId)
  ├─ 子节点列表    GET /children?nodeId=…&cursor=…&limit=…     → loadedChildrenByNodeId
  ├─ 文件大纲      GET /files/{id}/outline                      → expandedNodeIds
  ├─ 符号 AST 分页 GET /symbols/{id}/ast?cursor=…&budget=…       → astPageByNodeId
  └─ 邻接边        GET /edges?fromId=…&scope=…&cursor=…&detail=… → nodeEdgesByNodeId
```

四个请求共享同一套纪律：

1. **代际守卫**：`expandGeneration` 只回答「图变了吗」，**不能**当请求所有权用；
   按节点分页需要 per-key 单调令牌（`astRequestSeq` / `edgeRequestSeq`）。
2. **部分页不入完整缓存**：写入门是 `!hasMore && cursor === 0`。
   若把一页 AST 写进「完整结果」缓存，下次访问命中缓存 → 跳过 fetch → 永远不再计算
   `hasMore`，用户**永久失去**被折叠的那部分。
3. **明细模式跳过缓存读与写**：缓存里那份 payload **正是用户点开的聚合视图**。
4. **先应用后登记**：`commitEtag(sink)` 必须在载荷**已应用**之后（§5.3）。

### 4.3 `/edges` 聚合的契约（`EDGES_AGGREGATION`）

稠密邻域会被折叠成「每对文件一条合成边」：

```ts
export const EDGES_AGGREGATION = { THRESHOLD: 20, PAGE_SIZE: 500 } as const;   // constants.ts:294
```

三条硬约束：

1. **聚合是关于顺序的契约，不是实现细节**：聚合发生在分页**之前**，否则一对文件会被拆到两页，
   每页单看都正确而合并结果错误。故 `readIncidentEdgesWithFilePathsFromDb`(`:545`)
   **刻意不接受 cursor/limit**——先读完整未切片集合，再决定聚合还是切片。
2. **聚合页会冒充完整页**：它报 `hasMore: false` 且 `total === edges.length`，
   这正是「已完全加载」早退守卫的判据。任何 `loaded.length >= knownTotal` 形式的守卫
   都必须能区分「完整」与「完整但被折叠」。
3. **显式意图必须变成粘性状态**：`detailEdgeNodeIds: Set<string>`
   （`store/types.ts:111`）——首屏 `detail=1` 只影响第一页的话，
   第二页会重新折叠，用户**静默失去**刚要求的东西。

### 4.4 视图分层与图装配

`src/shared/viewModeUtils.ts` 定义三层：`'structural' | 'behavioral' | 'runtime'`(`:7`)。

### 4.6 版本对比（Diff）：一条完整的「数据→渲染→生命周期」链路

`DiffEngine`（`src/merger/DiffEngine.ts:102-119`）在 `diffToGraphData()` 里给每个节点/边写入
`properties.diffStatus ∈ {'added'|'modified'|'removed'}`，宿主 `POST /api/v1/codegraph/diff`
返回 `DiffGraphData`。**这条链路的宿主侧在 cycle-104 之前就已经存在，但客户端零消费者**——
`grep diffStatus src/client` 为 0 命中，能力只有出口没有入口。cycle-104 把它补齐。

#### 4.6.1 唯一真源：`src/shared/diffStatus.ts`

纯函数、无副作用、无 React import。它同时承担四个角色：

| 导出 | 作用 |
|---|---|
| `DiffStatus` / `DIFF_STATUSES` / `DIFF_STATUS_CLASS` | 词汇表。`DIFF_STATUS_CLASS` 把 `'added'` 映射到 CSS class `'diff-added'` |
| `asDiffStatus(value)` | 不做 `String()` 强转：`0` / `true` / `null` / `'renamed'` 一律返回 `null` |
| `buildDiffIndex(nodes, edges)` | 返回 `DiffIndex & {unclassified:{nodes,edges}}`，节点与边 id **分账**（同名不冲突） |
| `summarizeDiff(index, presentNodeIds, presentEdgeIds)` | 返回 `{counts, missing, marked}`——`missing` 是「索引里有但当前视图里没有」的差额 |

#### 4.6.2 为什么用 cytoscape class 而不是属性选择器

`[diffStatus="added"]` 在 cytoscape 里对**字符串**做相等比较；仓库已经因为布尔属性被当字符串比较
死过 24 条样式规则（`tests/unit/styleSelectorContract.test.ts`）。用 class 让清除路径退化为
**一次 `removeClass(DIFF_STATUS_CLASSES.join(' '))`**，不需要遍历元素。

#### 4.6.3 样式选择器必须由常量拼出

`src/client/renderer/styles/ThemeStylesheet.ts` 的 `DIFF_NODE_STYLES` / `DIFF_EDGE_STYLES` 里，
选择器写成 `` `node.${DIFF_STATUS_CLASS.added}` `` 而不是裸字面量 `'node.diff-added'`。
`tests/unit/diffStatusContract.test.ts` 做**双向扫描**：样式侧出现裸字面量、渲染侧出现裸字面量
都会红。这是防「写入侧改名后样式侧静默失效」的唯一手段——行为测试看不到样式失效。

#### 4.6.4 `diffResult` 的生命周期：七处清空

`diffResult` 在 store 里是「相对发起对比时那张图」的索引。任何改变这张图的操作都必须清空它，
否则画布上会留下指向已不存在元素的 class：

| 清空点 | 文件 | 触发 |
|---|---|---|
| 整图替换 ×4 | `store/slices/graphDataSlice.ts` | `setGraphData` / `setBootstrapData` / `clearGraph` / `applyGraphDelta` |
| 工作区切换/新增/删除当前 | `store/slices/workspaceSlice.ts` | `setCurrentWorkspace` / `addWorkspace` / `removeWorkspace(removingActive)` |
| 面板关闭 | `hooks/useDiffComparison.ts` `clear()` | 用户点「清除对比」或切走面板 |
| 切运行时层 | `hooks/useViewModePanelGuard.ts` | `showDiff` 不在 `RUNTIME_PANELS` 里 |

`emptyDiffState()` 与 `emptyEdgeState()` **刻意分开**：前者是「diff 索引相对发起对比时那张图」，
后者是「按需分页进度作废」，语义不同。合并会让「只想清分页」的新调用点误清 diff。

#### 4.6.5 失败返回 `null`，不是空 diff

`fetchGraphDiff` 非 2xx 时返回 `null`，而不是返回一个「没有变更」的空 diff。
面板必须能区分**「两版本完全相同」**与**「这次对比没做成」**——否则用户会把一次失败读成
「这两个版本没有任何区别」。`DiffPanel` 的错误块 `role="alert"` 与空态文案互相互斥。

#### 4.6.6 能力矩阵按层门控，不按 `hasGraphData` 门控

`showDiff` 被加进 `STRUCTURAL_PANELS` 与 `BEHAVIORAL_PANELS`，**不加进 `RUNTIME_PANELS`**。
理由是「切到运行时层时该不该收起面板」必须有一个唯一答案——`useViewModePanelGuard` 依赖
`getAvailablePanels(getViewLayer(viewMode))` 决定自动关闭清单。若用单独的 `hasGraphData` 门控，
这一问就没有答案，会退化成「渲染层自己决定要不要保留」的隐式耦合。

#### 4.6.7 面板输入不进 store

两个 git 引用（`HEAD~1` / `HEAD`）只存在于 `DiffPanel` 的**受控本地 state**。
一旦进 store 就要回答「持久化还是不持久化」；恢复一个用户没发起的对比状态只会造成困惑。
`diffResult` 同理，**不在 `partialize` 白名单里**，跨会话不会复活。

#### 4.6.8 编排 hook 的三个不变量

`src/client/hooks/useDiffComparison.ts` 的 `compare()` 用**自增 generation 令牌**防慢旧请求覆盖，
失败时**保留原结果只报错**，并且 `useEffect` 依赖 `[enabled, diffResult, graphRevision(=lastUpdated), rendererRef]`
在图变化后**重放标记**（否则新图渲染出来但旧 diff 的 class 已经失去意义）。

## 5. 条件请求（ETag）的完整设计

这是 cycle-91 的核心交付，也是全仓库最「反直觉」的一处设计，**四个失败模式都有真实事故**。

### 5.1 五条链路

```
① 计算     computeGraphEtag(repoId, revision, resource, requestKey?)   shared/graphFingerprint.ts:198
              ↑ 省略第 4 参时 identity 串逐字节不变（向后兼容）
② 请求键   etagKeyForChildren / Outline / Ast / Edges                  shared/graphFingerprint.ts:141/145/149/166
③ 判定     etagGuard(req,res,corsConfig,deps,resource,repoId?,requestKey?) → { handled, etag }
              ↑ 把「算校验值」与「回传校验值」合并成**一个返回值**：结构上不可能只做一半
④ 回传     sendJson(res, 200, body, req, corsConfig, etagHeaders(etag))
⑤ 客户端   createEtagSink() → 请求 → 代际守卫 → if (sink.notModified) return → 应用载荷 → commitEtag(sink)
```

### 5.2 四个失败模式与对策

| # | 失败模式 | 症状 | 对策 |
|---|---|---|---|
| 1 | 校验值只写在 304 分支 | 客户端**从来没有**可回传的值，机制是死代码 | `etagGuard` 一个返回值同时给出 `handled` 与 `etag`；`etagContract.test.ts` 扫全部 20 处 `sendJson(res,200,…)` 必须带 `etagHeader` |
| 2 | 请求键缺维度 | 两个不同响应共用一个校验值 ⇒ **假 304** ⇒ 面板永久空白 | 每个维度都**计算**得出，绝不两侧各写常量（`resolveAstBudget`） |
| 3 | 304 被当成失败 | `res.ok` 对 304 是 `false`，复用 `if (!res.ok) return null` 会静默清空面板 | `EtagSink.notModified` 是唯一区分手段 |
| 4 | 响应收到即登记 | 调用方随后因代际检查**丢弃**了载荷，下次带该值收到 304 ⇒ 永久空白且无错误 | `commitEtag(sink)` 把登记时机移到「载荷已应用」 |

### 5.3 缓存失效的**刻意不对称**

校验值编码了 `(resource, workspace, revision, request key)`，因此陈旧值只可能
**不匹配**而得到 200，**绝不会**错误匹配到更新的 revision。

```
假 304（危险）：代价 = 永久空白 + 无错误         → 必须结构上不可能
多送 200（安全）：代价 = 一次传输                → 可接受
```

⇒ 缓存**不需要**工作区切换失效列表，也**不可能**成为跨工作区污染通道。
这是「两个方向的错误代价不对称时，故意偏向便宜的那个」的实例，注释里已写明，
防止后人当作「多余优化」删掉。

### 5.4 五处 `clearEtagCache()`

304 只承诺**服务端副本**未变。以下五处会整体替换 `rawNodes` 并通过 `emptyEdgeState()`
重置派生容器（丢弃已合并的 outline / AST / children），故**必须**同时清缓存：

`setGraphData` / `setBootstrapData` / `applyGraphDelta` / `clearGraph`（`slices/graphDataSlice.ts`）
/ `disposeStore`（`store/internals.ts`）。

**载荷生命周期必须与校验器生命周期对齐。**

## 7. 关键设计决策（ADR 风格）

### 7.1 为什么 `src/shared/` 必须无副作用

它是 host / client 两侧**唯一**的共享面。一旦它 import `node:*` 或 `react`，
客户端 bundle 会带上宿主依赖（或反之），且 tsconfig 隔离形同虚设。

**已知的越界案例**：`src/shared/Logger.ts` 有 `resetLoggerListeners()`——
它是**状态重置函数**而不是纯函数，但它只操作模块内数组，不触碰平台 API，故仍属安全。

### 7.2 为什么品牌类型（`Branded<T, Brand>`）

`RepoId` / `NodeId` / `EdgeId`（`src/types/index.ts`）在编译期互不可赋值。
它们在运行时就是 `string`（零开销），但能挡住 `children(nodeId, repoId)` 这类参数顺序错误——
这类错误在类型上「都是 string」，静态分析**永远发现不了**。

### 7.3 为什么 `noUncheckedIndexedAccess` 会改变设计

开启后每次索引访问都变成 `T | undefined`。这直接产生了：

- `useGraphRenderer` 把每个可选 `RendererCallbacks` 成员包成**具体箭头函数**
  （`hooks/useGraphRenderer.ts:124-141`），使该层每个回调**必然存在**；
- 边界接口必须把**必需回调声明为必需字段**，不能用
  `Record<string, (...args) => void>`——后者会逼出 `?.`，
  并把「hook 忘了转发这个回调」**静默变成通过的测试**。

### 7.4 为什么五个标签通道而不是一个

DSH 的 slot/tab 席位在**不同宿主形态下存在性不同**：

- `conversation.view` —— 需 slot 系统 + 会话面板在场（**最完整，顶部标签同级**）；
- `sidebar.right.pane.tab` —— DSH 原生右侧栏，两代都有；
- `betterSidebar.openTab` —— 第三方 `dsh-better-sidebar` 的 tab 服务（0.2 线）；
- `sidebar.footer.action` —— 兜底席位；
- 浮动面板 —— 无席位时自绘。

**注册表对重复 id 是抛错语义**（`dsh-client-ui-sidebar-right/lib/client.js:8690`：
`if (this.ids.has(id)) throw new Error(...)`），故必须严格串行、
由 `state.navButtonRegistered` 保证后续通道让位。

> **只有互斥通道才配进同步优先级链**：`BetterSidebarIntegration` 曾被移到 `ctx.inject`
> 又被**刻意回退**——因为兜底通道（slots/floating）会在同步阶段就占住
> `navButtonRegistered`，注入回调运行前竞态已结束，造成**优先级反转**，
> 最差的通道反而拿到唯一入口。异步注入只用于**叠加型**（非互斥）贡献面。

### 7.5 为什么宿主版本检测「诚实承认失败」

`detectHostVersion(ctx)`（`src/host/compat/HostVersionDetector.ts:89`）三路启发式：

1. `ctx.hostVersion` / `ctx.version` / `ctx.app?.version` / `ctx.runtime?.version`
   —— **DSH 从不向插件 context 暴露版本**（asar 全量 grep 四键零命中）；
2. `DSH_HOST_VERSION` / `DSH_VERSION` / `CODEARTS_HOST_VERSION`
   —— 同样全树零命中；DSH 保留 env 只有 `DSH_HOME` / `DSH_SHELL` / `DSH_SESSION_ID` /
   `DSH_PROFILE` / `DSH_PROFILE_DIR`，且只注入 shell 工具子进程；
3. `detectFromToolNames(ctx)` —— 按上游 `codegraph_*` 工具名推断。

三路全落空时 `log.info('host version unknown, using conservative flags')` 并返回
`unknownDshVersion()`——**保守但可用**。真机上本机 `dsh-codegraph@0.1.3` 只贡献
`mcp__codegraph__codegraph_explore` 一个工具，9 个候选工具名一个都不存在，
故真机**同样落到 unknown**，最终由运行时能力探针决定。

> 这是「宁可不承诺，也不假装知道」的例子。`src/shared/dshGeneration.ts` 是唯一真源
> （窗口曾被写死在四处：`HostVersionDetector.ts` / `ClientVersionDetector.ts` /
> `tests/unit/manifest.test.ts` / `package.json engines.dsh`，现已收敛）。

### 7.6 为什么保留 gen1 分类器却不承诺它

cycle-92 把承诺窗口抬到 `>=0.2.0-rc.2`，cycle-110 把上界收紧为 `<0.4.0-0`（排除 gen4 预发布），但 `generationOfVersion` 仍能识别 gen1：

```ts
export const DSH_PROMISED_GENERATIONS = ['gen2', 'gen3'] as const;   // 被承诺
export const DSH_LEGACY_GENERATIONS  = ['gen1'] as const;            // 容忍但不承诺
```

**理由**：把可识别的宿主报成 `unknown` 会让能力探针**失去保守基线依据**；
删掉分类器反而制造「以为自己在 gen2」的**静默降级**。故保留识别能力，
只把「承诺」与「容忍」两个语义**显式分成两个清单**，
并用「恰好划分」测试锁死（`DSH_GENERATIONS` 的每个成员恰好属于其中一个）。

### 7.7 为什么错误码集中在 `shared/constants.ts`

27 个 `ERROR_CODES`(`:426-452`) + 双语 `ERROR_MESSAGES`(`:454-480`)。
宿主与客户端要显示**同一句**错误文本；两侧各写字符串必然漂移。
`ERROR_MESSAGES` 每条含 `{ en, zh }`，客户端经 `t()` 之外的第二通道取值——
因为错误码是**协议的一部分**，不应被 i18n 词典的键名重构影响。

### 7.8 为什么源码形态守卫（source-shape guard）是必需品

有一类缺陷**任何行为测试都看不见**：

| 缺陷 | 为什么行为测试看不见 |
|---|---|
| 死样式规则（`[isCluster="true"]` 永不匹配） | 元素照常渲染，只是颜色/边框/z-index 错 |
| `LAYOUT_ORDER` 4 份副本漂移 | 工具栏能选、命令循环跳过、持久化当脏值回退——各自都"能用" |
| 测试里 `require()` 逃逸到 Node TS loader | `require` 与 `await import` 返回**同一个模块对象**，行为完全一致 |
| 13 张截图从不比对像素 | 每张都成功保存，每个元素断言都通过 |
| `perf-gate` 只查 3 项而文档写 6 项 | 门禁照常 PASS |

对策：`tests/unit/*Contract.test.ts` 共 **15 个**形态守卫
（`tokensContract` / `workerContract` / `treeSitterDeliveryContract` / `workspacePathContract` /
`pathParityAndRevealContract` / `contextMenuKeyboardContract` / `responsiveContract` /
`serviceKeyContract` / `layoutOrderContract` / `requireEscapeContract` / `e2eSelectorContract` /
`styleSelectorContract` / `visualBaselineContract` / `crossWorkspaceGuardContract` / `etagContract`）。

**三条铁律**（每条都有踩坑记录）：

1. 必须**剥离注释并保留换行**——第一个版本的 `visualBaselineContract.test.ts` 被自己的
   头注释（正文里引用了 `toHaveScreenshot(...)`）绊倒，把第 12 行报成缺失 `installDeterminism`。
   本项目已**第三次**踩这个坑，故用统一形状：块注释**逐字符置空**而不是删除，
   否则每个上报行号都会上移并指向错误位置。
2. 扫描器**不能匹配自己的样例字面量**——`requireEscapeContract` 首次运行就把
   `tests/unit/requireEscapeContract.test.ts` 自己列为违规。正样例必须用**字符串拼接**
   （`const REQ = 'requ' + 'ire';`），使文件里不存在连续的 `require(` 形状。
3. 必须带**反向自检**与**非空断言**——正则写坏会永远绿：
   断言扫描到的文件数 `> 100`，或加一个「不该匹配」的负样例
   （如 `crossWorkspaceGuardContract` 里 `'children'` 的负样例不得命中 `'outline'` 正则）。

### 7.9 为什么变异探针是测试的一部分

「测试通过」与「测试有鉴别力」是两件事。每个关键修复都要做**变异探针**：
故意把实现改坏，确认**指定的**测试变红。

cycle-91 的三条探针（全部红→绿）：

| 探针 | 变异 | 结果 |
|---|---|---|
| A | `commitEtag` 变 no-op | 1 failed / 2 passed |
| B | `expandSlice.ts` 把 `commitEtag(sink)` 前移到代际检查之前 | 1 failed / 2 passed |
| C | `etagKeyForOutline` 退化为常量 `'outline'` | 2 failed / 1 passed |

> 注意：探针脚本必须 `--exclude` 它要观察的那个守卫测试，
> 否则守卫红 → vitest 退出 1 → **不产出覆盖率报告** → 探针读不到文件，
> 看起来像工具故障而不是红探针。

## 11. 复杂度与依赖治理（架构视角）

策略条款在 [01-插件开发规范.md](./01-插件开发规范.md) §9（C9-C11），此处只写**架构后果**：

1. **复杂度预算 = 单文件 100**（`band-detector` 默认值；`.cycles/config.yml` 未显式配置 `complexity_budget`，
   脚本会打印提示而非静默取默认）。超预算意味着「这个文件承担了两种职责」——
   本仓库的标准解法是**提取纯函数**（`src/host/db/`、`src/adapters/codeGraph*.ts`、
   `src/shared/runtimeSnapshot.ts` 都是这样分出来的），**不是**加注释或拆 `if`。
2. **依赖方向是单向的**：`types → shared → merger/adapters → host`，`client` 只能向下看
   `types/shared`。要加一条反向依赖时，正确做法是把共享部分下沉到 `shared/`，
   而不是让 `shared/` 去 import 任何一侧——`shared/` 必须能被浏览器与 Node 同时编译。
3. **新增第三方依赖的判据**（详见 01 §9）：浏览器可用、许可证可接受、体积可承受（看 `perf-gate` 的
   3 MB 预算）、且**不能是「为了绕开自己没做对的抽象」**。
   `graphology` / `graphology-communities-louvain` / `web-tree-sitter` 是现存的正例；
   `pnpm.overrides` 里的 9 条是**安全修复**，不是功能引入。
4. **`pnpm.overrides` 的边界**：只做最小版本提升，不得借机动 DSH 下限
   （`engines.dsh` 与 peer 范围由 `tests/unit/dshGeneration.test.ts` 独立钉死）。

## 12. 会话工作区跟随与增量信号（cycle-121/122 架构注记）

### 12.1 会话跟随：客户端侧的「默认工作区」归属

**决策**：默认工作区的真相源在**客户端会话 scope**，不在宿主 `/workspace` 路由。

- 宿主 `/workspace` 回落 `workspaceRegistry[0]`（注册序）是**服务端语义**——多会话宿主里
  它本来就不等于「当前对话」；客户端是唯一知道「我现在渲染在哪个会话里」的地方；
- 跟随引擎（`sessionFollow.ts`，110 行）只在客户端：宿主注入 `sessionId/useSessions`
  ⇒ 读 cwd ⇒ 未 pin 时 `setCurrentWorkspace`。宿主侧零改动；
- **pin 是粘性状态不是一次性参数**（cycle-85 教训）：手动切换写 `pinnedWorkspace`，
  轮询抑制分支**不推进 `lastDshWorkspace`**——否则「抑制期间的宿主切换」被标记为
  已消费，解除 pin 后恢复跟随永远追不上（W-1，由负向用例先红抓出）;
- pin 不进 persist：刷新后回 following，天然满足「可切换但刷新后恢复对话工作区」。

**边界**：降级通道（better-sidebar/slots/floating）无会话 scope props ⇒ unknown 态
维持现状（不回归）；点亮跟随需逐通道接 props（已登记增强项）。

### 12.2 增量信号：「返回值必须有消费者」与传输层「修形不重造」

- **写返回值必写消费面**：`xuanjiPool.applyDelta` 曾整行丢弃返回值（XJ-11 死链）。
  本仓守卫 `xuanjiIntegrationContract` 现在钉住「捕获→消费→下发」三环——新增任何
  「库返回结构化结果」的调用点，应同轮把结果写进工具返回值或显式声明丢弃理由；
- **coerce 是修形不是重造**：`GraphValidator.coerceGraphData` 对**已验证的新字段**
  必须形状校验后透传，不得只重建白名单字段（cycle-88 hasMore 三层丢字段家族）；
- **显式缺席三分法**：全量重建=字段缺席；skipped=`{applied:false}` 不带数值；
  执行=完整信号。三种状态各被键存在性断言钉住（值断言区分不了键缺失与键为空）。

### 12.3 指纹豁免判据（重申）

metadata 扩展字段若只服务**观测/呈现**（不参与图内容语义），`computeGraphFingerprint`
天然豁免（它只取 5 个显式字段）——扩展前先确认字段不进指纹，避免一次意外的
全仓 re-fingerprint（cycle-119 §64.3 决策模式）。

## 13. 白盒可观测性与算法预算（cycle-141 架构注记）

### 13.1 observability 模块的三条不变量

`src/shared/observability.ts`（计数器 + 管线计时）是宿主/客户端共用的白盒层，
三条不变量缺一即静默腐坏：

1. **模块级可变状态必须进 `reset()`**：`counters`、`pipelineDurations`、
   `pipelinePendingMarks` 三样一起清。新增模块级 Map/数组的那次提交就要同时改
   reset（「clearMeasurements 不重置阈值表」教训的当轮复发证明 review 拦不住它）；
2. **计时窗口的所有权在 disposer 上，不在阶段名上**：`startPipelineTiming` 返回的
   disposer 只终结自己压入的栈帧（LIFO）。同阶段嵌套（scan 内重入 scan）时，
   绑定名字的 disposer 会终结别人的窗口——测量静默串号；
3. **挂起窗口被清时不伪造样本**：reset 丢弃 pending 标记后，迟到的 disposer 返回
   null 而不是 0ms 样本——没有发生的测量不能产生数据。

### 13.2 算法预算是「上界 + 披露 + 逃生口」三件套

图论指标（Brandes 介数 / BFS 距离）在同规模图上的成本特征相同，预算纪律必须一致：

- **上界单一真源**：`METRICS.BFS_SAMPLE_SOURCES = 200`（`constants.ts`），
  `computeBetweennessCentrality(adj, sampleRate, maxSample)` 与
  `computeDistanceStats(adj, maxSample)` 共用同一量级——两个旋钮取交集（先比例后封顶）；
- **近似必须如实披露**：采样结果经 `betweennessSampleSize`/`betweennessApproximate`
  /`sampled` 字段出栈，管理面板渲染——上界不是精度承诺；
- **显式 `null` 是唯一的全量逃生口**：默认值就是封顶（真机 8393 节点全量 Brandes
  实测 65.4s，封顶后 2.7s）。想跑全量必须显式传 `null` 表态，静默全量是缺陷。

### 13.3 子进程派生的 Windows 纪律

宿主侧所有 `execFile`/`spawn` 调用点（`prerequisites.ts` / `gitDiff.ts` /
`gitChurn.ts` / `scripts/sandbox-launch.mjs`）统一带 `windowsHide: true`——
缺它时 Windows 每次派生都闪一个控制台窗口。例外要写注释说明为什么（如
prerequisites 探测保留 `shell: win32` 解析 `.cmd`，参数是固定字面量无注入面）。
