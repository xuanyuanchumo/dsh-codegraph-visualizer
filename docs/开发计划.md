# dsh-codegraph-visualizer 生产级开发计划

> 基于 DSH 官方规范 + 测试策略 + 迭代验证流程，ponytail 模式（最小可行、零过度设计）

---

## 一、项目定位（一句话）

**DSH 插件**：打通 `dsh-codegraph`/`dsh-tool-lens` 数据源 → 聚合转换 → Cytoscape.js 渲染 → 交互式代码图谱面板。

**不做**：代码解析、AST 构建、图谱布局算法（上游完成）。

---

## 二、架构（两层 + 契约）

```
┌─────────────────────────────────────────────┐
│  Client (React + Cytoscape.js + Zustand)    │
│  • 图谱渲染、交互、状态管理                  │
│  • 通过 ctx.broadcast 接收 Host 推送         │
├─────────────────────────────────────────────┤
│  Host (Node.js + Cordis)                    │
│  • 适配器：CodeGraphAdapter / LensAdapter    │
│  • 融合器：GraphDataMerger                   │
│  • 工具：graph_status / graph_data / graph_symbol / graph_impact
│  • 推送：监听上游变更 → 推送到 Client        │
├─────────────────────────────────────────────┤
│  契约 (tsc 双面构建)                        │
│  • Branded 类型、Service Definition 签名     │
│  • 事件：codegraph/*                         │
└─────────────────────────────────────────────┘
```

**ponytail**: 无 Rust-Wasm 内核，上游 `dsh-codegraph`/`dsh-tool-lens` 完成解析与图谱构建。

## 四、数据流（最小路径）

```
[用户保存代码]
    → [上游 dsh-codegraph 监听 → 增量更新 → SQLite]
    → [Host: graph_data 工具调用 → 适配器转换 → 融合器聚合]
    → [Host → Client: ctx.broadcast('graph:update', data)]
    → [Client: Zustand store 更新 → Cytoscape.js 重绘]
```

**ponytail**: 前端轮询作为降级方案（3s 间隔），推送优先。

## 五、技术选型（stdlib 优先）

| 层级 | 选型 | 理由 |
|------|------|------|
| 渲染引擎 | **Cytoscape.js** | 成熟、交互丰富、布局内置、React 友好 |
| 状态管理 | **Zustand** | 轻量、DSH 生态常用 |
| UI 框架 | **React** | DSH Client 标准 |
| 构建工具 | **tsdown** | DSH 官方推荐 |
| 类型检查 | **tsc 双面构建** | Host/Client 隔离 |
| 测试 | **Vitest + Playwright** | DSH 官方工具链 |

**ponytail**: 不引入 G6、Redux、自定义布局算法。

## 十、已知简化（ponytail: 标记）

1. **轮询降级**：推送优先，3s 轮询作为兜底。升级路径：WebSocket 推送（DSH 原生支持）。
2. **布局算法**：Cytoscape.js 内置（force-directed / hierarchical / circle / grid）。升级路径：自定义布局（dagre / d3-force Wasm）。
3. **缓存策略**：内存 LRU + SQLite 持久化。升级路径：lru crate + 多级缓存。
4. **数据源**：仅支持 CodeGraph + Lens。升级路径：适配器扩展其他数据源。
