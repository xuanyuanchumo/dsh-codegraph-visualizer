## P0 — 必须立即修复

### 1. computeDataHash 碰撞风险 (评分 1/5)

**问题**: `DiagramCache.ts` 中 `computeDataHash` 仅使用字符串拼接结果的 `length` 属性作为哈希，完全丢弃内容信息。任何两组数据只要 `join('|')` 后字符串长度相同，哈希就相同。

**影响**: DiagramCache 和 ClusterCache 会错误命中缓存，返回与当前数据不匹配的结果，用户可能看到错误的图表数据。

**修复方案**: 使用 FNV-1a 或 djb2 哈希算法替代 length-based 哈希。

### 2. 新功能测试盲区

Phase 1-4 新增的核心模块完全无测试覆盖：

| 模块 | 行数 | 风险 |
|------|------|------|
| `DependencyAssembler.ts` | 173行 | 目录聚合、边聚合、BFS深度计算 |
| `DiagramCache.ts` | 90行 | LRU缓存、computeDataHash |
| `SpatialIndex.ts` | 94行 | 网格空间索引核心数据结构 |
| `DataController.ts` | ~400行 | 增量更新、属性变化检测 |

### 3. ClusterCache 边哈希 bug

`graphStore.ts` 中 `setClusterLevel` 的缓存键计算：
```typescript
const nodesHash = computeDataHash(sourceNodes, sourceEdges);
const edgesHash = nodesHash; // 边哈希直接复用节点哈希！
```
边的哈希从未被独立计算，缓存键无法区分边数据的变化。

## P1 — 短期改进

### 4. GraphNode.type 语义重载

`module` 类型被用于表示文件节点、包节点、目录节点、依赖节点。FlowchartAssembler 将控制流节点标记为 `type: 'function'`，语义不符。

**建议**: 扩展 `GraphNode.type` 联合类型，增加 `'package' | 'directory' | 'flowchart-node' | 'cfg-block'` 等语义明确的类型。

### 5. GraphNode.properties 缺少接口约束

`properties: Record<string, unknown>` 完全无类型约束。各 Assembler 随意写入字段，拼写错误不会被检测到，下游消费者无法获得 IntelliSense。

**建议**: 为每种 ViewMode 定义对应的 `properties` 接口，使用联合类型约束。

### 6. graphStore 上帝对象

graphStore 包含约30个状态字段和约30个 setter 方法。`setGraphData` 在一个函数中完成8种操作，`setViewMode` 包含5个分支。

**建议**: 拆分为 `diagramStore`、`viewportStore`、`clusterStore`、`historyStore` 等独立 store。

### 7. rawNodes/savedRawNodes 数据不一致

当 `viewMode === 'dependencies'` 时，新数据写入 `savedRawNodes`，但 `rawNodes` 保持旧值。切换回 code 模式时 `rawNodes` 中的数据是过时的。

### 8. GraphPanel.tsx 过大 (905行)

包含 30+ store 状态订阅、20+ store action 调用、多个复杂事件处理函数、直接 fetch 调用、内联 JSX 中包含 hotspot/godModule/impact 面板。

**建议**: 拆分为子组件 + 自定义 hooks。

### 9. CSS 冗余

图标按钮样式在3处重复定义（共约180行重复代码），`@keyframes cg-slide-up` 定义2次，`@container graphpanel (max-width: 768px)` 定义2次。

**建议**: 创建 `.cg-icon-btn` 共享类。

### 10. DiagramCache/ClusterCache 是 FIFO 不是 LRU

`get` 操作不更新条目位置，频繁访问的条目仍可能被驱逐。

## P2 — 中期改进

### 11. computeDepths 代码重复

5个宏观 Assembler 各自实现了几乎相同的 BFS 深度计算逻辑。

**建议**: 提取到公共工具模块，参数化遍历方向。

### 12. LOD 视觉跳跃

LOD 切换时直接替换整个 stylesheet，节点大小瞬间跳变（8px→16px→32px），标签突然出现/消失。

**建议**: 添加 CSS transition 或 Cytoscape animate() 渐变过渡。

### 13. 层级选择器交互改进

L0/L1/L2 标记过于抽象，切换视图模式时层级选择器突然消失无解释。

**建议**: 显示层级名称缩写，添加视图模式上下文提示。

### 14. 硬编码文本 (9处)

NodeDetail.tsx 中 "signature"、"docstring"、"kind"、"CFG" 等未国际化。GraphPanel.tsx 中 "nodes"、"edges" 硬编码。

### 15. 测试覆盖 exclude 范围过大

`vitest.config.ts` 排除了 `src/client/renderer/**`、`src/client/hooks/**`、`src/client/components/**`，使得覆盖率阈值失去约束意义。

**建议**: 至少将 SpatialIndex、LayoutController 等纯逻辑模块从 exclude 中移除。

### 16. E2E 测试验证深度不足

`v020-features.spec.ts` 主要验证按钮可见性和 CSS class 变化，未验证功能实际效果。

### 17. 对比度修复

Light 主题 `--cg-text-tertiary` (#9ca0a5) 对比度 2.8:1 不满足 AA 4.5:1。Dark 主题 `--cg-accent` (#6366f1) 对比度 4.2:1 略低于 AA。

## P3 — 长期改进

### 18. IRenderer 接口拆分

30+ 方法的 `IRenderer` 接口违反接口隔离原则。拆分为 `IDataRenderer`、`ILayoutRenderer`、`IHighlightRenderer` 等。

### 19. CSS 文件拆分

3605行单文件 CSS 按组件拆分为 `toolbar.css`、`node-detail.css` 等。

### 20. 内存泄漏检测

在 chaos 测试中加入长时间运行场景，检测缓存、历史栈、Worker 是否存在泄漏。

### 21. 并发操作测试

模拟快速连续的用户操作（快速切换布局 + 搜索 + 聚类），验证状态一致性。

### 22. 性能基准测试

对 10000+ 节点的 DiffEngine、SpatialIndex 查询、LayoutController 布局计算设置性能基线。

## 架构亮点

项目也有许多值得肯定的设计：

1. **Container Queries 响应式设计** — 正确选择了 CSS Container Queries 而非 Media Queries，适配 DSH 插件面板环境
2. **ThemeStylesheet 主题系统** — CSS 变量 + 运行时读取宿主主题，Light/Dark 双主题完善
3. **CytoscapeRenderer 门面模式** — 子控制器职责划分清晰
4. **DataController 增量更新** — requestAnimationFrame 分批处理，区分结构变化和数据变化
5. **SpatialIndex 网格空间索引** — 替代线性扫描，大幅提升虚拟视口性能
6. **DiffEngine 深度比较** — 测试覆盖最深入的模块，质量最高
7. **Chaos 测试** — 双层覆盖（unit + E2E），压力测试和异常输入测试结合
8. **i18n 国际化** — 295+ 翻译键，中英对齐
9. **可访问性基础** — ARIA 属性覆盖广泛，快捷键系统完整，焦点陷阱实现正确
