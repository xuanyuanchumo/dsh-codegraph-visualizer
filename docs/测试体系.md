# DSH 代码图谱可视化插件 —— 测试策略与工具链指南

> 本文档基于 DSH 官方测试工具链（`dsh-testkit`、`dsh-eval-harness`、`dsh-forge` 等），为 `dsh-codegraph-visualizer` 插件提供完整的测试工作流指南。

## 一、DSH 官方测试工具链总览

DSH 官方提供了一套完整的开发与测试工具链，利用它们可以系统地进行单元测试、集成测试、端到端测试、独立开发环境验证、质量门禁检查等。

### 1.1 工具清单

| 工具 | 类型 | 用途 | 在本插件中的应用 |
|------|------|------|-----------------|
| **Vitest** | 单元/集成测试 | `pnpm run test` 运行 `tests/**` 目录下的测试 | 数据适配器、融合器、状态管理、工具函数 |
| **dsh-plugin-template** | 集成测试模板 | 开箱即用的集成测试模板 | 验证插件能否被正确加载 |
| **dsh-trail-plugin** | 加载验证 | 安装到独立 `trail-test` profile 证明加载成功 | 验证 DSH 启动时加载本插件 |
| **Playwright** | E2E 测试 | `pnpm run test:e2e` 真实环境测试 | 测试"代码变更 → 图谱自动更新"完整流程 |
| **Chromium 快照** | UI 回归 | Playwright `visual` project（`tests/e2e/visual-screenshots.spec.ts`）：`npx playwright test --project=visual` | 检测 UI 是否发生意外变动（暂无 npm script） |
| **dsh-forge** | 独立开发环境 | 独立、可复现的插件开发环境，监听 `127.0.0.1:3188` | 需要可视化面板的复杂项目开发 |
| **dsh-webui-studio** | Client 端调试 | 交互式、可视化的 Client 端插件开发工具 | 调试 UI 组件、状态管理 |
| **dsh-testkit** | 安装冒烟 | 一次性环境安装精确版本 DSH 和插件包、启动真实 Host、探测运行时能力、卸载并生成证据报告 | 验证本插件在各种 DSH 版本下正常安装和加载 |
| **dsh-test-drive** | 冒烟测试 | `test_drive` 工具执行完整"安装 → 配置检查 → 无头启动冒烟 → 卸载 → 清理"流程 | 不触碰用户真实 `~/.dsh` 环境 |
| **dsh-lab** | 实测精选库 | 安装、冒烟、静态扫描、版本锁定四关真机测试 | 参考 143 个通过 + 48 个失败案例 |
| **dsh-eval-harness** | 回归评测 | YAML 用例驱动 → `eval_run` 驱动真实 agent 执行 → 解析 session trace 断言 → `eval_gate` 对比 baseline | 核心场景（如"用户点击节点跳转代码"）建立回归测试门禁 |
| **dsh-test-drive CI** | CI 集成 | GitHub Action，输出 `report.json`、`junit.xml` | 无缝接入 CI 流程 |

> **工具链现状（本次核对）**：上表中 `dsh-testkit`、`dsh-test-drive`、`dsh-lab`、`dsh-eval-harness` 与 `dsh-test-drive CI` 目前均为 `[设计目标]`——本项目 `package.json` 未引入对应依赖、没有对应 script，`tests/**` 下也不存在评测 YAML 用例。当前实际生效的工具只有 Vitest（单元/组件）与 Playwright（E2E），真实用法见 §6.2、§6.3。

## 四、性能门禁

> 对齐项目实际迭代验证流程附录C

### 4.1 项目性能门禁（目标层）

| 指标 | 门禁值 | 测试方法 |
|------|--------|---------|
| 图谱构建 | < 2s @ 1000 文件 | 导入 1000 文件仓库后重启 |
| 仓库扫描 | < 5s @ 500 文件 | 扫描中等规模仓库 |
| 搜索查询（端到端，含 UI 渲染） | < 500ms @ 10000 节点 | Playwright performance API |
| 图谱渲染 | ≥ 30 FPS @ 1000 节点 | Playwright performance API |
| 内存占用 | < 200MB | 打开大仓库后空闲 |
| 导出耗时 | < 3s @ 1000 节点 | 导出 JSON 格式 |

> **CI 实际门禁与上表的差距（本次核对）**：CI 中由 `scripts/perf-gate.mjs`（`.github/workflows/ci.yml:87`）执行的门禁只检查三项：client bundle ≤ 3MB、host bundle ≤ 512KB、测试用例总数 ≥ 4463（`scripts/perf-gate.mjs:27-65`）。它与上表六个端到端指标不是同一组；上表的构建 / 扫描 / 搜索 / FPS / 内存 / 导出指标目前只由 Playwright `performance` project 覆盖（`playwright.config.ts:44-48`），该项目没有 npm script，也不在 CI 中运行。
> 这三档本身是硬门禁：产物缺失、vitest 非零退出、JSON 解析失败都判 FAIL 并使 job 失败（`scripts/perf-gate.mjs:30`、`:38`、`:49-53`、`:57-61`）。其中"测试用例总数 ≥ 4463"没有文档化的来源。

### 4.2 当前可测代理基线

> **口径说明**：本节为服务层/单测层代理指标，与 §4.1 端到端指标不同层级，二者不可互相替代。

| 指标 | 门禁值 | 测量方法 |
|------|--------|---------|
| 图谱构建耗时 | < 2 s @ 1000 文件 | vitest 计时（固定数据） |
| 搜索查询时延（服务层） | < 50 ms @ 10^4 节点 | vitest 计时（内存图数据，非 SQLite `:memory:`） |
| 数据适配器转换延迟 | < 100 ms @ 1000 节点 | vitest 计时 |
| 页面内存峰值 | 浏览器页签配额内无告警 | Playwright + performance.memory 采样 |

## 八、成熟度模型
