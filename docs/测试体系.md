# DSH 代码图谱可视化插件 —— 测试策略与工具链指南

> 本文档基于 DSH 官方测试工具链（`dsh-testkit`、`dsh-eval-harness`、`dsh-forge` 等），为 `dsh-codegraph-visualizer` 插件提供完整的测试工作流指南。

---

## 一、DSH 官方测试工具链总览

DSH 官方提供了一套完整的开发与测试工具链，利用它们可以系统地进行单元测试、集成测试、端到端测试、独立开发环境验证、质量门禁检查等。

### 1.1 工具清单

| 工具 | 类型 | 用途 | 在本插件中的应用 |
|------|------|------|-----------------|
| **Vitest** | 单元/集成测试 | `pnpm run test` 运行 `tests/**` 目录下的测试 | 数据适配器、融合器、状态管理、工具函数 |
| **dsh-plugin-template** | 集成测试模板 | 开箱即用的集成测试模板 | 验证插件能否被正确加载 |
| **dsh-trail-plugin** | 加载验证 | 安装到独立 `trail-test` profile 证明加载成功 | 验证 DSH 启动时加载本插件 |
| **Playwright** | E2E 测试 | `pnpm run test:e2e` 真实环境测试 | 测试"代码变更 → 图谱自动更新"完整流程 |
| **Chromium 快照** | UI 回归 | `pnpm run test:web` 比对浏览器输出与快照 | 检测 UI 是否发生意外变动 |
| **dsh-forge** | 独立开发环境 | 独立、可复现的插件开发环境，监听 `127.0.0.1:3188` | 需要可视化面板的复杂项目开发 |
| **dsh-webui-studio** | Client 端调试 | 交互式、可视化的 Client 端插件开发工具 | 调试 UI 组件、状态管理 |
| **dsh-testkit** | 安装冒烟 | 一次性环境安装精确版本 DSH 和插件包、启动真实 Host、探测运行时能力、卸载并生成证据报告 | 验证本插件在各种 DSH 版本下正常安装和加载 |
| **dsh-test-drive** | 冒烟测试 | `test_drive` 工具执行完整"安装 → 配置检查 → 无头启动冒烟 → 卸载 → 清理"流程 | 不触碰用户真实 `~/.dsh` 环境 |
| **dsh-lab** | 实测精选库 | 安装、冒烟、静态扫描、版本锁定四关真机测试 | 参考 143 个通过 + 48 个失败案例 |
| **dsh-eval-harness** | 回归评测 | YAML 用例驱动 → `eval_run` 驱动真实 agent 执行 → 解析 session trace 断言 → `eval_gate` 对比 baseline | 核心场景（如"用户点击节点跳转代码"）建立回归测试门禁 |
| **dsh-test-drive CI** | CI 集成 | GitHub Action，输出 `report.json`、`junit.xml` | 无缝接入 CI 流程 |

## 二、分层测试策略

> 对齐项目实际迭代验证流程

### 2.1 四层测试架构

| 层 | 测试类型 | 载体/工具 | 门限 |
|----|---------|-----------|------|
| **Client UI** | 组件/交互/状态 | vitest（`packages/**/*.test.ts`）、Playwright | 关键路径与异常路径用例通过率 100% |
| **Host 服务** | 服务定义/实现/生命周期 | vitest（`tests/unit/*Service*.test.ts` 等） | 业务用例通过率 100% |
| **契约** | 类型对齐/序列化边界 | tsc 双面构建 | 零错位，`pnpm run typecheck` 零错误 |
| **E2E** | 端到端流程 | Playwright（`pnpm run test:e2e`） | 冒烟集每次提交全通过；全量集每循环全通过 |

### 2.2 覆盖率门限

> **唯一强制来源**：根目录 `vitest.config.ts` 的 `coverage.thresholds`，全局基线为行 / 函数 / 语句 ≥ 85%、分支 ≥ 86%。下表模块级目标通过 vitest 的 glob override 或 per-file threshold 实现，不改变全局基线。

| 模块 | 目标 |
|------|------|
| CodeGraphAdapter / LensAdapter | ≥ 90% |
| GraphDataMerger | ≥ 90% |
| GraphVisualizerService | ≥ 85% |
| 按需加载模块（视口裁剪 / 渐进式渲染 / Worker 调度） | ≥ 90% |
| CFGBuilder / FlowchartBuilder / SequenceBuilder | ≥ 90% |
| 微观视图组件（ParticipantNode / MessageEdge / BasicBlock） | ≥ 80% |
| 宏观↔微观切换状态机 | ≥ 90% |
| 工具函数/校验器 | ≥ 95% |
| React UI 组件 | ≥ 80% |

### 2.3 Mock 策略

| 依赖 | Mock 方式 |
|------|----------|
| `ctx.fs` | memfs |
| `ctx.web` | nock |
| `ctx.sessions` | 内存存储 |
| SQLite | `:memory:` |
| `dsh-codegraph` 工具 | 模拟工具返回 |
| `dsh-tool-lens` 工具 | 模拟工具返回 |

> Mock 仅用于单元/集成层。E2E 层必须使用真实 DSH 环境与真实上游工具，见 §6.5。

### 2.4 测试文件组织约定

| 目录 | 承载内容 |
|------|--------|
| `tests/unit/*.test.ts` | Host 服务、适配器、构建器、分析算法、工具函数 |
| `tests/component/*.test.tsx` | Client UI 组件与状态 |
| `tests/e2e/*.spec.ts` | 真实环境端到端流程（含集成、生命周期、混沌等） |

## 四、性能门禁

> 对齐项目实际迭代验证流程附录C

### 4.1 项目性能门禁（目标层）

| 指标 | 门禁值 | 测试方法 |
|------|--------|---------|
| 图谱构建 | < 2s @ 1000 文件 | 导入 1000 文件仓库后重启 |
| 仓库扫描 | < 5s @ 500 文件 | 扫描中等规模仓库 |
| 搜索查询（端到端，含 UI 渲染） | < 500ms @ 10000 节点 | Playwright performance API |
| 图谱渲染 | ≥ 30 FPS @ 1000 节点 | Playwright performance API |
| 内存占用 | < 200MB | 打开大仓库后空闲 |
| 导出耗时 | < 3s @ 1000 节点 | 导出 JSON 格式 |

### 4.2 当前可测代理基线

> **口径说明**：本节为服务层/单测层代理指标，与 §4.1 端到端指标不同层级，二者不可互相替代。

| 指标 | 门禁值 | 测量方法 |
|------|--------|---------|
| 图谱构建耗时 | < 2 s @ 1000 文件 | vitest 计时（固定数据） |
| 搜索查询时延（服务层） | < 50 ms @ 10^4 节点 | vitest `:memory:` 计时 |
| 数据适配器转换延迟 | < 100 ms @ 1000 节点 | vitest 计时 |
| 页面内存峰值 | 浏览器页签配额内无告警 | Playwright + performance.memory 采样 |

## 六、推荐测试工作流

### 6.1 开发阶段

1. 使用 **dsh-forge** 在独立环境开发（监听 `127.0.0.1:3188`，与主线 DSH `3080` 同时运行）
2. 使用 **dsh-webui-studio** 调试 UI 组件
3. 基于 **dsh-plugin-template** 编写测试

### 6.2 单元/集成测试

```bash
# 运行单元测试
pnpm run test

# 运行覆盖率检查（门限以 vitest.config.ts 为唯一强制来源）
pnpm run test:coverage

# 验证插件加载
pnpm run test:trail  # dsh-trail-plugin
```

### 6.3 E2E 测试

```bash
# 真实环境测试（调用真实 Provider API）
pnpm run test:e2e

# Web 浏览器快照测试
pnpm run test:web
```

### 6.4 发布前验证

```bash
# 安装冒烟测试（无需模型或 API Key）
dsh-testkit install --profile web dsh-codegraph-visualizer

# 完整冒烟流程
dsh-test-drive test_drive dsh-codegraph-visualizer

# 回归评测门禁
dsh-eval-harness eval_run --scenario graph-click-jump
dsh-eval-harness eval_gate --baseline baseline.yaml
```

### 6.5 本项目真实环境验证路径

本项目的功能与视觉验收以真实 DSH 环境为准，流程如下：

```bash
# 1. 更新插件到 web profile
dsh plugin --profile web add D:\Projects\TraeProjects\dsh-codegraph-visualizer

# 2. 启动 DSH 真实测试环境（先评估脚本内容再运行）
./scripts/start-dsh-test.mjs

# 3. 通过 Chrome DevTools MCP 连接浏览器
#    - 执行功能与组件测试
#    - 执行视觉效果验证与截图比对
#    - 采集性能指标（FPS / 内存 / 时延）

# 4. 验证完成后关闭运行资源，避免多实例并发
```

> **纪律**：同一时刻不得运行多个相同命令或重复实例。

### 6.6 CI 集成

将上述检查接入 CI，确保每次提交都通过质量门禁。dsh-testkit 提供 GitHub Action，可输出 `report.json`、`junit.xml` 等报告。

## 七、测试报告规范

> 对齐项目实际迭代验证流程 §6 及附录A §3.2

每次验证必须产出测试报告，必须包含**九要素**：

1. **通过数 / 失败数 / 错误数**
2. **断言明细**
3. **日志**
4. **复现步骤**
5. **手工操作记录**
6. **数据清理记录**（P10 纪律）
7. **环境版本信息**（DSH / Cordis / Node / 浏览器 / 插件版本）
8. **视觉验证产物**（截图路径、快照 diff 链接）
9. **性能指标采集值**（对应 §4.1 / §4.2 口径）

涉数据适配器/融合器变更须附复杂度说明与基准数据（附录 D §5.3）。

## 八、成熟度模型

| 级别 | TS 侧特征（UI/Host） | Host 侧特征 | 插件整体特征 |
|------|---------------------|------------|-------------|
| 1 | 基础组件、手动测试 | 单命令入口 | 可加载 |
| 2 | 组件化、单元测试 | 服务化定义、生命周期 | 可配置 |
| 3 | 状态管理、E2E 测试 | 契约测试、事件闭环 | 可集成 |
| 4 | 性能优化、a11y | 并发安全、降级策略 | 可组合 |
| 5 | 自动化发布、监控 | 资源治理、可观测性 | 可生态 |

**当前项目级别：L3**（依据：已具备状态管理、E2E 测试、服务化定义与契约测试（tsc 双面构建）；性能门禁与 a11y 尚未纳入强制门禁，并发安全与降级策略尚在补齐）。

> **工具链使用状态说明**：`dsh-testkit`、`dsh-test-drive`、`dsh-lab`、`dsh-eval-harness` 为 DSH 官方工具，本项目尚未集成到 CI 流程中。当前测试验证以 `vitest`（单元/组件）、`playwright`（E2E）和 Chrome DevTools MCP（真实环境视觉验证）为主。
