## 2. 派生分析成本与方案 C 的取舍

| 场景（3 倍边） | 2000 节点 | 5000 节点 / 14991 边 |
|---|---|---|
| 重建邻接表（任何增量实现的底价） | 2.19 ms | 3.48 ms |
| 死代码分析 | 3.73 ms | 10.20 ms |
| 热点分析 | 1.84 ms | 4.36 ms |
| 核心函数分析（SCC+bitset） | 5.04 ms | 11.20 ms |
| 健康评分 | 14.38 ms | 24.92 ms |

结论：全量分析已与「重建邻接表」同阶，增量协调器的收益上界只有几毫秒，而正确性风险
（增量结果必须与全量逐节点一致）远大于收益；且分析只在面板打开时计算。**方案 C 不做**，
登记为「已评估、收益不足」。

## 3. 组合代数的性能特征

- 组合是**纯函数**（只构造规则对象），无运行时成本；
- 枚举成本由组合后的剪枝超集决定：并/交取长度包络、拼接取长度和、差沿用 R1 剪枝；
  非法成员由 `pathConstraint` 终判，最坏为每条候选路径一次 `isLegalPath`（O(L)）；
- 200 组随机属性测试（含并/交/差/拼接四路 + oracle）在 ~40 ms 内完成，不构成 CI 显著负担。

## 4. `graph_cycles` 工具的成本边界

| 参数 | 默认 | 上限 | 影响 |
|---|---|---|---|
| `maxLength` | 6 | 12 | DFS 深度上界（简单环） |
| `limit` | 100 | 500 | 物化条数上界（达到即停） |
| 图规模 | — | 50000 节点 | 超过返回空 + truncated（与 `graph_path_find` 同口径） |

最坏情况是密图 + `maxLength=12`：DFS 会探索大量死路后才攒够 `limit` 条环。
对照 `graph_path_enumerate` 的 4.2 ms（1200 节点 / 4797 边 / 5 跳 / 11 条路径），
本工具在同一规模图上为毫秒级；上游图默认来自 codegraph 稀疏调用图，未观察到长尾。
