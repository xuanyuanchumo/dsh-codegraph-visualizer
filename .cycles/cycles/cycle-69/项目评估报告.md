## 四、P0-P3 问题清单

### P0（阻断级）
1. `ApiCompatLayer` 工具名映射失效：`createInvoke` 传入蛇形名（`codegraph_query`），映射 key 为驼峰，回退链完全失效。（`src/tools.ts:111` / `src/host/compat/ApiCompatLayer.ts:7-21`）
2. `readEdgesForNodesFromDb` 跨批丢边：`(source IN batch AND target IN batch)` 且分批，跨批边静默丢失。（`src/adapters/CodeGraphAdapter.ts:436`）
3. E2E 探针 `window.__cytoscape` / `window.__graphStore` 无生产注入 → 大量 E2E 永久超时。（`tests/e2e/helpers.ts`）
4. CI `test:web=playwright test --project=chromium` 指向不存在的 project。（`package.json:29` / `playwright.config.ts`）
5. `createGraphTools` 的 `dispose`（graphCache.clear）未接线 → 卸载泄漏。（`src/index.ts:43`）

### P1（重要）
6. 死代码 `ToolbarDropdown.tsx` 无任何引用、无 CSS。
7. 外部点击/Escape 关闭逻辑在 5 处重复，无共享 hook。
8. `BetterSidebarIntegration` 与 `RemoteWebUiIntegration` 逐行同构。
9. `integrationMode` 命名分裂（compat 返回 `better-sidebar`，store 写入 `sidebar`）。
10. GraphRepository 无 PRAGMA（WAL/busy_timeout），snapshot 仅存计数非真实数据。
11. 无用/重叠测试 `virtualViewportAndLayout.test.ts`。
12. `docs/用户旅程.md` 映射指向不存在的 `integration.spec.ts`，J6/J25 无用例。
13. `graphCache` 之外的 graphStore dispose 资源清理核对。

### P2（优化）
14. responsive.css 死类名（11+）与 @supports 大段重复。
15. 面板可见性字段在 3 处重复枚举。
16. 路由 `/ast` 的 `parseInt` 无 NaN 防护；edges 游标推进错位。
17. `FileSystemAdapter` 整类死代码；`readGraphFromDb` 无调用者。
18. 陈旧 ETag（基于内存 timestamp，DB-first 路由 304 风险）。

### P3（辅助）
19. package.json 缺 `repository/homepage`，市场元数据不足。
20. `WrenchIcon` 未使用；`config.ts` 校验文案遗漏 `dependency`。

## 五、本轮处置范围（cycle-69）

**P0 全做**（1-5）+ **P1 高价值低风险**（6,7,8,9,10,11,12）+ **P2 针对性**（15,19）。

数据库路径决策：经评估，drizzle-orm 0.45.3 无 `node:sqlite` 驱动，强行接入 query builder 需替换驱动或加 proxy，风险高且收益低。**结论：保留 drizzle schema 作为类型契约，运行时继续使用 `node:sqlite` 并优化 SQL（PRAGMA + 真实 snapshot），移除误导性死接线。**
