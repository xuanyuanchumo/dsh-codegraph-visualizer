## 1. P0-A 根因与修复（工具输出 ContentBlock 契约）

**根因（安装版宿主源码逐行取证）**：DSH 契约要求 `output.render(args, value): ContentBlock[]`。`makeToolOutput()` 曾返回裸字符串 `JSON.stringify(value)`。注册期不校验 render 返回类型（dsh-tools/lib/index.js:2564 snapshotProjection 只验无损 JSON，字符串合法），直到请求组装期 dsh-llm/lib/index.js:594 `contentHasImage(content)` 调 `content.some(...)` 才崩溃——「注册成功、对话必崩」的延迟爆炸形态，stub 宿主永远看不见。

**修复**（dsh-anic/src/host/toolsSlot.ts）：
- 新增 `TextContentBlock { type: 'text'; text: string }`（含宿主证据注释）；
- `ToolOutput.render` 返回类型 `string` → `TextContentBlock[]`；工厂实现改为 `[{ type: 'text', text: JSON.stringify(...) }]`，12 个工具一处修复全覆盖；
- `JSON.stringify(undefined)` 返回 undefined（非字符串）——值缺失时兜底 `null` 保证 text 恒为 string。

**回归守卫**（tests/contract/toolOutputContract.test.ts，7 用例）：
- 行为面：render 返回数组（非字符串）、每块 `{type:'text', text:string}`、text 可被模型 JSON.parse 无损还原、schema object-rooted、undefined 兜底 null；
- 源码形态面：src/host/tools*.ts 全域零「裸字符串 render」（`=> JSON.stringify(...)` 直返 / 字符串字面量直返），守卫纪律三件套（反向自检 / 拼接样本 / 非空扫描集）。

**变异探针**：render 退回裸字符串 → 3 failed | 4 passed（红）；恢复 → 7 passed。

## 2. P0-B 根因与修复（事件信封 data 嵌套）

**诊断先行的取证路径**：理论分析穷尽（cordis dispatch / dsh-scope filter / dsh-session collectSessionCallbacks）无法定论 → 在 attachInvocationFeed 加五计数器诊断（sessionEvents / sessionToolCalls / toolsResults / anicCalls / anicResults）→ 路由响应携带 diagnostics → 真宿主实测。

**真宿主第一轮读数（重启后）**：`{sessionEvents: 0, sessionToolCalls: 0, toolsResults: 4, anicCalls: 0, anicResults: 0}` —— tools/result 通道活着，session/event 通道静默。

**真宿主第二轮读数（模型实际调用 anic_status 后）**：`{sessionEvents: 11, sessionToolCalls: 1, toolsResults: 5, anicCalls: 0, anicResults: 0}` —— **session/event 通道也活着**，事件到达但被过滤！锁定过滤层。

**根因（dsh-agent-loop/lib/index.js:681-689 + dsh-session/lib/index.js:1453-1459）**：
```js
session.append("tool/call", { turn, step, callId, name, arguments })
// Session.append 包装为：{ type, seq, time, data: { turn, step, callId, name, arguments } }
```
载荷在 **event.data** 里，不在顶层。旧 handler 读 `event.callId` 恒 undefined → 全部被 `!payload.callId` 过滤。kb 文档记录的是 data 变体字段，接线时漏了信封层。

**修复**（dsh-anic/src/host/runtime/invocationFeed.ts）：handler 改读 `event.data?.callId` 等，信封契约注释引 dsh-session 源码行号。

**回归锚**：tests/unit/invocationFeed.test.ts 新增信封回归用例 + 全部 fixture 改为转录真实信封 `{type, seq, time, data}`（fixture 写什么形状代码就只会什么形状——本轮再次验证）。

**变异探针**：payload 退回扁平读取 → 6 failed（红）；恢复 → 24 passed。
