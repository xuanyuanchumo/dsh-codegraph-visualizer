### 2.2 架构现状

| 层 | 文件数 | 关键模式 | 技术债务 |
|---|---|---|---|
| 适配器层 | 4 | 策略模式，统一输出 AdapterResult | 缺少统一 IAdapter 接口；DependencyAdapter 是纯函数式，与其他3个类适配器不一致 |
| 渲染层 | 15+ | 组合式控制器（8个子控制器） | LOD 阈值固定；缺少热力图叠加；缺少 circo/treemap/sfdp 布局 |
| 组件层 | 26 | React 函数组件 + Zustand | 缺少右键上下文菜单 |
| Store 层 | 8 | Zustand 单一全局 store | 集群深度阈值固定，未根据屏幕尺寸动态调整 |

### 2.3 适配器层详细分析

| 适配器 | 接口模式 | 状态 | 数据源 |
|---|---|---|---|
| CodeGraphAdapter | class + fetchData(repoId, invoke) | 有状态 | SQLite DB + UpstreamInvoker |
| LensAdapter | class + fetchData(repoId, invoke) | 有状态 | lens_analyze 工具 |
| DependencyAdapter | 纯函数式 | 无状态 | package.json/Cargo.toml/go.mod |
| TreeSitterAdapter | class + init() + parseFile() | 有状态(WASM) | AST 解析 |

**统一接口设计方向**：
- `IDataAdapter`：数据源适配器接口（CodeGraph/Lens/Dependency），统一 `fetchData` 方法
- `IAnalysisAdapter`：分析适配器接口（TreeSitter），统一 `init` + `parseFile` 方法
- 或者统一为 `IAdapter` 带可选方法

### 2.4 渲染层详细分析

**StyleController**：
- LOD 三级阈值固定：`minimal < 0.2`, `compact < 0.5`, `full >= 1.0`
- 缺少热力图叠加模式
- 节点颜色仅按类型区分（6种节点类型），未按语义角色区分

**LayoutController**：
- 支持 7 种布局：cose/fcose/dagre/circle/grid/radial/tree
- 缺少 circo（环形循环依赖布局）
- 缺少 treemap（体积占比可视化）
- 缺少 sfdp（超大规模布局）

**ThemeStylesheet**：
- 24种颜色定义（6节点类型 + 4依赖类型 + 7边类型 + 4依赖scope + text/border）
- 缺少入口/孤儿/叶子/高扇入扇出节点的语义颜色

## 4. 执行策略

### 4.1 优先级排序

1. **P1-1**: 适配器统一抽象接口（架构基础，其他任务依赖）
2. **P1-3**: 语义化颜色编码（视觉效果，独立于P1-1）
3. **P1-2**: 右键上下文菜单（交互体验，独立于P1-1）
4. **P2-1**: 热力图叠加模式（依赖P1-3的颜色系统扩展）
5. **P2-2**: 动态LOD阈值（独立）
6. **P2-3**: 动态聚类阈值（独立）
7. **P3-1~P3-3**: 视条件推进

### 4.2 并行执行计划

- P1-1 和 P1-3 可并行（互不依赖）
- P1-2 独立执行（仅依赖 InteractionController）
- P2-1 在 P1-3 完成后执行
- P2-2 和 P2-3 可并行

### 4.3 验证策略

1. 每完成一个任务，运行 `npx vitest run` 验证测试不回归
2. 新功能需编写对应单元测试
3. 所有任务完成后，运行 `npx vitest run --coverage` 验证覆盖率不回归
4. 运行 `npx tsc --noEmit` 验证类型安全
5. 构建插件并在 DSH 环境验证
