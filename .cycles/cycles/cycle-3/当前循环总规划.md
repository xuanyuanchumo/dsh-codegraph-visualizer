### 2.4 开源项目研究关键发现

1. **dependency-cruiser**: Instability 度量 `I = Ce/(Ca+Ce)` 可用于热力图颜色梯度
2. **hpcc-js-wasm**: 提供 circo/sfdp/patchwork(treemap) 布局引擎的 WASM 实现
3. **npmgraph**: 多维颜色映射模式（Bus Factor、版本健康度等）
4. **focus + focus-depth**: 最优雅的动态 LOD 实现

### 2.5 DSH 官方文档关键发现

1. **Cordis 框架**: 插件向共享上下文贡献服务，注册即副作用
2. **ESM only**: 全 ESM，跨包使用包名，本地相对导入用 .ts
3. **Branded Types**: 跨边界的不透明 ID 必须使用 Branded<B>
4. **配置显式化**: 不允许硬编码调参，配置错误应大声失败

## 4. 执行策略

### 4.1 优先级排序

1. **P2-2**: 动态LOD阈值（独立，改善用户体验）
2. **P2-1**: 热力图叠加模式（依赖P1-3的颜色系统，增强可视化）
3. **P2-3**: 动态聚类阈值（独立，改善大图体验）
4. **TD-1**: LOD切换性能优化（与P2-2关联）
5. **TD-4**: 魔法数字提取（低风险重构）
6. **P3-1~P3-3**: 视条件推进（需要引入新依赖）

### 4.2 并行执行计划

- P2-2 和 P2-3 可并行（互不依赖）
- P2-1 在 P2-2 完成后执行（热力图需要LOD系统扩展）
- TD-1 与 P2-2 一起执行（同文件优化）
- TD-4 独立执行

### 4.3 验证策略

1. 每完成一个任务，运行 `npx vitest run` 验证测试不回归
2. 新功能需编写对应单元测试
3. 所有任务完成后，运行 `npx vitest run --coverage` 验证覆盖率不回归
4. 运行 `npx tsc --noEmit` 验证类型安全
5. 构建插件并在 DSH 环境验证
