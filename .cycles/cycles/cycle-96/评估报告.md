## 1. 本循环定位

cycle-96 是一次由**真实用户反馈驱动的缺陷修复循环**。用户在真实会话中报告（m02105）：

> 之前开启技能插件会导致直接返回错误（本轮运行失败 tool "anic_evaluate" parameters must be lossless JSON before schema projection UNKNOWN）

该错误把 cycle-93/94/95 的一个根本性盲区暴露出来：**插件的所有既有测试都在 stub 宿主上通过，但 DSH 真实宿主的工具调用链路从未被端到端验证过**。本循环以该用户报告为入口，做了一次「真实宿主契约 vs 测试桩契约」的全面对账，修复了三个 P0/P1 级缺陷，并把 J0 探针（真实宿主验证层）自身的两个假阴性也修掉了。

## 2. 缺陷清单与本轮裁决

### P0-TOOLS-FIELDS（用户报告错误的根因）— 已修复（96feb75）

- **症状**：真实会话中模型调用任何 anic_* 工具，宿主立即返回 `tool "anic_evaluate" parameters must be lossless JSON before schema projection UNKNOWN`。
- **根因**：DSH 宿主的工具契约要求字段名 `parameters`（object 根 JSON Schema）+ `execute(args, exec)`；dsh-anic 的 12 个工具全部用 `inputSchema` / `handler` 字段名注册。宿主 ToolRuntime.register() 只校验 output（所以日志显示 12 tools registered，注册成功），到**会话发起、schema 投影时**才读 parameters → undefined → 抛错。stub 宿主从不读这两个字段，所以 235→315 个既有用例全绿——又一个「fixture 写什么形状，stub 就只会什么形状」的教科书案例。
- **修复**：`dsh-anic/src/host/toolsSlot.ts` 接口字段名迁移（inputSchema→parameters、handler→execute），`tools.ts`（5）、`toolsPointerGateway.ts`（3）、`toolsSkillGateway.ts`（4）共 12 工具同步；`skillToolNative.test.ts` / `flowTrackerIntegration.test.ts` 的 stub 同步；新增「契约：DSH 工具槽位字段名」describe 4 用例（全工具 parameters 为 object 根 + JSON 往返 lossless、execute 为函数、output{schema,render} 齐全、源码形态守卫防 inputSchema/handler 回潮）。
- **变异探针**：anic_evaluate 退回 inputSchema/handler → 红（`缺 parameters` + `缺 execute`）；恢复 → 11/11 绿。
- **端到端证据（三层）**：
  1. 新会话发「请调用 anic_evaluate…」不再报 lossless 错误（schema 投影通过）；
  2. 模型工具列表可见全部 12 个 anic_* 工具且描述/参数正确投影（模型自我纠正了此前「工具不存在」的说法）；
  3. 模型真实调用 anic_evaluate → eval-runner.mjs 真实执行 → 落盘 609,260 B 评估报告（`.cycles/cycles/cycle-95/项目评估报告.md`）。

### P0-BOOTSTRAP-PARSER（自举链解析器三连虚构契约）— 已修复（96feb75）

- **症状**：docs/anic/17 指出的最大缺口「selfBootstrap ↔ eval-scripts 链断开」在 cycle-93 M10-b 已由 bootstrapOrchestrator 连通，但输出解析器是**按虚构格式写的**，真实工作区上 parseEvalScore 恒 0、parseGateVerdict 恒 'unknown'（真实工作区永远到不了 CONVERGED）、parseFixApplied 恒 null。
- **根因**：三个真实技能脚本（eval-runner.mjs / gate-check.mjs / auto-fix-loop.mjs）从不输出 "Overall score: 0.875" / "GATE: PASS" / "Applied: fix-typecheck" 这些行——旧测试断言的正是这些虚构格式（fixture 写什么格式，解析器就只会什么格式）。真实契约：
  - eval-runner：失败清单在 **stderr**（`N dimension(s) failed: E3, E8, Q8`，exit 1），通过行在 stdout（`All N evaluated dimension(s) passed.`，exit 0）；无 score 行；
  - gate-check：逐门禁 `[PASS|FAIL] G0: …` 在 stdout，总裁决成功 `All gates PASSED.` 在 stdout、失败 `Gate check FAILED.` 在 **stderr + exit 1**；
  - auto-fix-loop：`Identified N failure(s):` + 缩进清单行、`Fix successful. All tests now pass.`；fixAction 在对象里不在 stdout。
- **修复**：新建 `dsh-anic/src/host/runtime/scriptParsers.ts`（~100 行，单一实现消灭 bootstrapOrchestrator.ts 与 selfBootstrapRoute.ts 的重复解析器）；parseEvalScore 忠实二值（连续分数不可推导，evalScore 在状态机中只记录不分支）；parseGateVerdict 总裁决行优先 + 逐门禁行兜底（LEDGER 行天然不匹配）；parseFixApplied null=未修复、string=「修复并通过: <清单>」（多次尝试取最后一次清单）。调用点全部改传完整 result（丢 stderr 就丢裁决证据）。
- **测试重写**：bootstrapOrchestrator.test.ts 解析器 describe 全部改为**真实格式逐行转录 fixture**（19 个解析器用例，含 3 个防倒退用例：旧虚构格式必须不再匹配）。
- **变异探针**：恢复虚构解析器 → 9 红（eval 4 + gate 5，全部真实格式用例）；恢复 → 23/23 绿。
- **真实行为验证**：`node gate-check.mjs <tmp> --gate all` 无 config → exit 1 + stderr 无裁决行 → unknown（忠实报告，fail-closed）；补 config.yml + cycles/cycle-1/ → stdout `[FAIL] G0..G3` 行 + stderr `Gate check FAILED.` → 'FAIL' 路径实测覆盖。
- **端到端断言修正**：runSelfBootstrapCycle 端到端用例断言真实裁决（evalScore=0、gateVerdict='unknown'——临时工作区无 config.yml，gate-check 在入口校验即死，无可识别裁决行；unknown 在 advanceBootstrap 中按未通过处理，fail-closed）。

### P1-CHAINHEAD（账本 chainHead 字段同步）— 已修复（96feb75）

- 真实账本写入者是技能脚本 `assets/skill/scripts/lib/ledger.mjs`（维护顶层 `chainHead` == 末条 hash）；插件 `src/host/runtime/ledger.ts` 的 serializeLedger 只写 `{entries}` → 走插件 append 会让技能脚本侧 HEAD_MISMATCH、下次 append 以 undefined 接链。
- 修复：readLedgerFile 返回 `{entries, shape, chainHead}`（缺失自愈为末条 hash）；serializeLedger 保留并推进 chainHead；verifyLedger 增加 HEAD_MISMATCH 同判。runtime.test.ts 扩 10 用例（含 HEAD 断裂、自愈、追加推进断言）。探针：serializeLedger 退化丢 chainHead → 2/30 红。

### J0 探针两个假阴性 — 已修复（8941b41）

- **症状**：重启宿主后 J0 报 2/8 FAIL（J0-2 circles=0 lines=0；J0-4），但面板实际渲染正常。
- **根因**：J0-2 用 `document.querySelector('svg')`（文档序第一个）——宿主图标 svg（实测 71 个）排在前面，命中宿主图标而非 ANIC 图；J0-4 的全文档 leaf 扫描同理会命中宿主含 "snapshot" 字样的文本。**作用域错误**：探针要验证的是插件面板，选择器却作用于全文档。
- **修复**：两处收窄到 `[data-anic-workflow]` 作用域；J0-2 加 `waitForSelector('[data-anic-workflow] svg', {timeout: 8000})`（面板 svg 点击标签后才挂载，懒加载本身就是要验证的对象，waitFor 代替拍脑袋 sleep）。
- **验证**：修复后 J0 **8/8 全绿**（circles=154 lines=190，来源行 `ANIC · live 2026-10-16T03:59:35.726Z · 154 nodes / 190 edges`）。
