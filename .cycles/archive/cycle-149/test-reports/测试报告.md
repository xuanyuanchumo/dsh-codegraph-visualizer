## 3. 修复的缺陷（本轮探明 + 修复）

| # | 缺陷 | 家族 | 修法 |
|---|---|---|---|
| D1 | `onSelectionToggle` 回调全仓 **0 消费方**——cycle-141 的多选是死链路（注册✓/生产✓/消费✗） | 「The entry point exists is not reachable」 | 消费面三跳全接：useGraphRenderer 转发 → GraphPanel 传参 → multiSelectSlice 镜像 + BatchActionBar |
| D2 | `multi-selected` / `canvas-focused` class **无样式条目**——class 被应用但不可见 | dead-style（§59.29 家族） | ThemeStylesheet 补两条目（accent 边 + 半透明底 / 虚线描边） |
| D3 | 普通点击**静默**清空多选（无回调）→ 消费方必留幽灵集合 | 写侧/守卫方向不对称家族 | 新增 `onSelectionClear` 回调；`clearMultiSelect()` 三件事一体（集合+class+通知），单一实现双触发方共用 |
| D4 | 批量操作条「清除」若只清 store 镜像会双集合漂移 | 双事实源漂移 | 清除走渲染器事实源（`onClearSelection` → `clearMultiSelect()`），store 镜像经回调同步；渲染器缺位时诚实降级 |

## 4. 失败与修复记录（本轮红→绿）

| 轮次 | 症状 | 根因 | 处置 |
|---|---|---|---|
| 1 | MS-BAR-5 无限递归（Maximum call stack） | mock `document.createElement` 内部再调自身命中 spy | 先绑存原实现再 spy（经典 mock 递归陷阱） |
| 2 | MS-BAR-5 `createObjectURL does not exist` | jsdom 无 `URL.createObjectURL`（著名缺口），spyOn 直接抛 | 手动定义两静态方法（原生不存在⇒不遮蔽），afterEach 删除还原 |
| 3 | styleSelectorContract 2 红 | 本轮注释**字面引用** `[isCluster="true"]` 被扫描器当 offender（CLAUDE.md 记载第 4 次同类自陷） | 注释改述不含字面量 |
| 4 | GraphCanvasControls「plain click 清空」红 | 既有 mock 的 `cy.batch` 不执行回调，而新实现把 removeClass 包进了 batch | batch 对单条 class 无益，移除包装（与原实现同形）；测试按新契约强化（+onSelectionClear 断言） |
| 5 | M1 探针恢复误用 `git checkout --` | 该文件改动**未提交**，checkout 抹掉全部未提交编辑 | 改用内存备份恢复（M2 起 node 脚本同写 `.m2-orig.ts` 备份）；教训：变异恢复必须备份驱动，绝不 git checkout 未提交工作区 |
