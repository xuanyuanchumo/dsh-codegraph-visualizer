# cycle-149 当前循环总规划

## 目标

深化前端交互：**多选链路复活 + 批量操作条**。

## 背景与根因（本轮探明的缺陷）

cycle-141 D 已交付画布级 Shift+Click 多选（`InteractionController.multiSelectedIds` +
`multi-selected` class + `onSelectionToggle` 回调），但该能力是**死代码**：

1. **消费面缺失**：`onSelectionToggle` 在全仓 **0 个调用方**（grep 证据：仅声明处
   InteractionController.ts:19 与触发处 :86）——`useGraphRenderer.ts` 的转发清单里没有它，
   `GraphPanel.tsx:198` 的 callbacks 组装里也没有它。多选集合只存在于渲染器内部，
   父层/store/UI 全都看不到。
2. **视觉面缺失**：`multi-selected` class 与键盘导航的 `canvas-focused` class 在
   `ThemeStylesheet.ts` **均无样式条目**（grep 证据：仅有 `.selected`/.highlighted/
   .neighbor-*/.search-match 等）。class 被应用但不可见——CLAUDE.md §59.29 家族
   （「A dead style rule is invisible to every behavioural test」）。

即：**注册（class 应用）✓ / 生产（回调触发）✓ / 消费（store+UI）✗ / 视觉（样式）✗**
——正是用户 objective 中「功能业务的注册、生产与消费」链路完整性要求的反例。

## 设计决策

- **状态位置**：新建 `multiSelectSlice`（第 13 个 slice，沿用既有 slice 模式
  `(set, get) => Partial<GraphState>`），不塞进 viewModeSlice——单一职责。
- **不持久化**：`multiSelectedIds` 不进 `partialize` 白名单（画布选区是会话瞬时态，
  reload 后节点可能已变，持久化只会产生过期信号；与 xuanjiSignal 同判据）。
- **disposeStore 清理**：多选集合随 store 释放清空（与 pendingRequests 同批）。
- **批量展开/收起**：复用 expandSlice 的 `expandNode`/`collapseNode`（经 `get()` 取全量
  store 动作），不重写聚类逻辑；返回成功处理数供 UI 反馈。
- **导出选区**：复用渲染器 `getNodeData`（与 getDataRef 同源），只导出选中节点的数据快照
  （JSON 下载），不引入新数据通道。
- **样式**：`.multi-selected` 用 accentColor 边框 + 半透明底（与 .selected 的 errorColor
  区分，多选是"待操作集合"不是"当前详情"）；`.canvas-focused` 用虚线描边（键盘焦点，
  不与鼠标选中混淆）。

## 守卫策略（防复活失败）

`multiSelectWiringContract.test.ts` 源码形状守卫（CLAUDE.md「A tool factory returning a tool
is NOT registering it」家族的接线版）：

1. `useGraphRenderer.ts` 必须含 `onSelectionToggle:` 转发行（缺行 = 静默断裂 = 红）
2. `GraphPanel.tsx` 必须含 `onSelectionToggle:` 传参
3. `ThemeStylesheet.ts` 必须含 `.multi-selected` 与 `.canvas-focused` 选择器
4. zh/en 字典必须都含 `batchBar.` 键（双语一致性由 i18nKeyContract 双保险）
5. **反向自检**：负样本（`onSelectionUntoggle` 等）不得命中同一正则；扫描文件集非空断言
