# dsh-anic 设计令牌与主题

> 本文件描述 `src/shared/tokens.ts`（98 行）的两层令牌模型、注入机制、组件消费纪律，以及**当前的落地程度**。
>
> 读取本文件的时机：新增颜色、新增内联样式、新增暗色适配，或判断某个颜色该不该走 `token()` 时。

## 1. 两层模型：原语 → 语义

`src/shared/tokens.ts` 是全工程**唯一的调色板定义处**，分两层：

### 第一层：`PALETTE`（原语，`tokens.ts:22-39`）

16 个十六进制字面量，`as const`，命名是「色相 + 明度档位」：

| 键 | 值 | 键 | 值 |
| --- | --- | --- | --- |
| `green500` | `#22c55e` | `slate50` | `#f8fafc` |
| `green600` | `#16a34a` | `slate200` | `#e2e8f0` |
| `green700` | `#2d8a3e` | `slate300` | `#cbd5e1` |
| `red500` | `#ef4444` | `slate400` | `#94a3b8` |
| `red600` | `#dc2626` | `slate500` | `#64748b` |
| `red700` | `#c0392b` | `slate600` | `#475569` |
| `amber500` | `#f59e0b` | `slate700` | `#334155` |
| `amber600` | `#e6a700` | `amber700` | `#b45309` |

**纪律**（`tokens.ts:21`、`:43`）：组件**禁止**直接引用 `PALETTE` 的值，只能引用第二层。

### 第二层：`SEMANTIC`（语义别名，`tokens.ts:45-57`）

11 个键，**键名就是 CSS 变量名去掉 `--` 前缀**，值是 `PALETTE` 的成员：

| 语义键 | 指向原语 | 用途 |
| --- | --- | --- |
| `anic-pass` | `green700` | 门禁通过 |
| `anic-fail` | `red700` | 门禁失败 |
| `anic-doubt` | `amber600` | 存疑 |
| `anic-ok-text` | `green600` | 通过态文本 |
| `anic-bad-text` | `red600` | 失败态文本 |
| `anic-surface` | `slate50` | 面板底色 |
| `anic-border` | `slate200` | 分隔线 |
| `anic-text` | `slate700` | 主文本 |
| `anic-text-dim` | `slate500` | 次级文本 |
| `anic-text-faint` | `slate400` | 三级文本 |
| `anic-warn-text` | `amber700` | 警告文本 |

`export type TokenName = keyof typeof SEMANTIC;`（`tokens.ts:60`）—— 令牌名是**编译期封闭集合**，拼错名字过不了 typecheck。

### 这个模块修的是什么缺陷（`tokens.ts:2-8`）

头部注释记录的原始症状：改造前 4 个特性模块**各自硬编码一套十六进制调色板**，且 `renderOrgStatus` 引用的 `--anic-pass` / `--anic-fail` / `--anic-doubt` **从未被任何地方定义** —— 变量永远走 fallback，注释称之为「**半接线主题**」（half-wired theme）。

## 2. `token(name)`：引用表达式（`tokens.ts:68-70`）

```ts
export function token(name: TokenName): string {
  return `var(--${name}, ${SEMANTIC[name]})`;
}
```

产出形状：`var(--anic-pass, #2d8a3e)` —— **变量引用 + 同源 fallback**。

**为什么内联 style 必须用它而不是裸 `var(--anic-pass)`**（`tokens.ts:65-66`）：宿主未注入变量时，裸引用会让属性**计算为无效值**，颜色回退到 `initial`。组件「看起来没坏但没样式」—— 这类缺陷在 DOM 断言里与「渲染正确」无法区分。

**关于 fallback 的边界条件**（`tokens.ts:17-18`，注释明确）：`var(--x, fallback)` 的 fallback 只在变量「**未定义或计算期无效**」时生效，**它不是老浏览器缺自定义属性时的 polyfill** —— 所以注入必须真的发生。

## 3. `tokenCssBlock()`：`:root` 注入块（`tokens.ts:78-98`）

```ts
export function tokenCssBlock(): string
```

结构（`tokens.ts:80-97`）：

```css
:root {
  color-scheme: light dark;
  --anic-pass: #2d8a3e;
  ... 每个 SEMANTIC 键一行（由 Object.entries 生成，tokens.ts:79）
}
@media (prefers-color-scheme: dark) {
  :root {
    --anic-surface: #0f172a;
    --anic-border: #1e293b;
    --anic-text: #e2e8f0;
    --anic-text-dim: #94a3b8;
    --anic-text-faint: #64748b;
    --anic-pass: #22c55e;   /* PALETTE.green500 */
    --anic-fail: #ef4444;   /* PALETTE.red500 */
    --anic-doubt: #f59e0b;  /* PALETTE.amber500 */
  }
}
```

**三个设计决定**：

1. **亮色块由 `Object.entries(SEMANTIC)` 生成**（`tokens.ts:79`），因此新增语义键自动进入 CSS 块 —— 不存在「加了令牌忘了加变量」的漏配。
2. **暗色块是手写的 8 行**（`tokens.ts:87-94`），只换语义层：`pass`/`fail`/`doubt` 换成 500 档（更亮，因为暗底上 700 档对比度不足），文本与表面整体反转。**不碰任何组件文件** —— 这是两层模型的核心收益（`tokens.ts:15`）。
3. **`color-scheme: light dark`**（`tokens.ts:82`）让宿主的**滚动条与表单控件**跟随主题，否则暗色下会留一条亮色槽（`tokens.ts:75-76` 注释）。

## 4. 注入点：`useTokenCss()`（`WorkflowGraphPanel.ts:47-57`）

```ts
function useTokenCss(): void {
  useEffect(() => {
    const id = 'anic-design-tokens';
    if (document.getElementById(id)) return;          // 同页面多实例不重复注入
    const el = document.createElement('style');
    el.id = id;
    el.textContent = tokenCssBlock();
    document.head.appendChild(el);
    return () => { el.remove(); };                      // 卸载时移除
  }, []);
}
```

调用点在 `WorkflowGraphPanel.ts:129`（组件体首行）。

**为什么必须真的注入**（`WorkflowGraphPanel.ts:44`）：「令牌块必须真的注入一次，否则全站都走 fallback，『换主题只需改变量』就是空话」。

## 5. 守卫：`tests/contract/clientRenderContract.test.ts`

| 断言 | 行 | 保护什么 |
| --- | --- | --- |
| 扫描集非空（`SRC_FILES >= 20`、`CLIENT_FILES >= 5`） | `:95-98` | 静默空扫描 = 永久绿 |
| 反向自检：`BARE_VAR_RE` 匹配裸样例、**不匹配 `token()` 样例** | `:135-138` | regex 写坏则守卫恒绿；且不误伤正确写法 |
| **除 `tokens.ts` 外，任何文件不得出现裸 `var(--anic-*)`** | `:140-151` | 本文件的核心守卫（见下） |
| 每个语义令牌产出 `var(--name, #hex)` 且与 `SEMANTIC` 同源 | `:153-168` | fallback 不能是第二张表 |
| fallback **不得是另一个 `var()`**（`expect(expr).not.toMatch(/, var\(/)`） | `:166` | 否则只是把失败推后一层 |
| `tokenCssBlock()` 含每个语义键 + 显式三个历史症状键 + `color-scheme` + `prefers-color-scheme: dark` | `:170-183` | 注入块不漏配、暗色块存在 |

核心守卫（`:140-151`）：

```ts
if (rel === join('src', 'shared', 'tokens.ts')) continue;  // 令牌定义处自身是权威
lines.forEach((line, idx) => {
  if (BARE_VAR_RE.test(line)) offenders.push(`${rel}:${String(idx + 1)}`);
});
expect(offenders).toEqual([]);
```

**豁免只有一处**：`src/shared/tokens.ts` 自己（它是变量名的权威来源）。因此**任何组件写裸 `var(--anic-*)` 都会让这条测试变红**。

`:154-156` 的注释记录了一个重要的工具选择教训：`token()` 用模板串拼 fallback，源码里**不存在**字面 `var(--anic-pass, #2d8a3e)`，所以「扫描字面量」的写法在这里**永远匹配 0 条** —— 因此这条断言写成**行为断言**（调 `token(name)` 再检查返回值）而不是源码 regex。

## 6. 当前落地程度（诚实陈述）

`token()` / `tokenCssBlock()` 的实际消费点**只有 3 个文件**：

| 文件 | 行 | 用量 |
| --- | --- | --- |
| `src/client/WorkflowGraphPanel.ts` | `:25`（import）、`:129`（注入）、`:36,140,145,157-168`（消费） | 面板壳层、工具栏、分区边框/文本 |
| `src/client/features/org/renderOrgStatus.ts` | `:22`（import）、`:36,41,44,45,87` | 全部颜色走 `token()`，**零十六进制** |
| `src/client/features/prefs/prefsDrawer.ts` | `:11`（import）、`:77,78,92,94,97,100` | 全部颜色走 `token()`，**零十六进制** |

**但 `tokens.ts:4-6` 头部声称已收敛的那 4 套硬编码调色板，目前仍然存在且仍在使用**：

| 文件 | 常量 | 行 |
| --- | --- | --- |
| `src/client/features/graph/renderGraph.ts` | `TYPE_COLORS`（8 个类型色） | `:14-22` |
| `src/client/features/graph/gateColors.ts` | `GATE_COLORS`（5 个） | `:13-19` |
| `src/client/features/graph/gateColors.ts` | `BAND_COLORS`（3 个） | `:68-72` |
| `src/client/features/stepTrace/renderStepTrace.ts` | `STATUS_COLORS`（5 个） | `:27-32` |

`src/client/` 下仍有 **40+ 处十六进制字面量**，分布在 `renderGraph.ts`（12 处）、`gateColors.ts`（15 处）、`renderStepTrace.ts`（15 处）、`renderDiagnostics.ts`（7 处）。

**结论**：`tokens.ts` 的**机制**（两层模型、`token()`、注入、守卫）是完整且被测试强制的；但它的**迁移**只覆盖了 3 个文件，`tokens.ts:4-6` 那段「改造前 4 个模块各自硬编码」的描述**描述的是待办，而不是已完成的事实**。图表域与诊断域尚未接入令牌。

**为什么守卫没有发现这一点**：`clientRenderContract.test.ts:140-151` 只禁止**裸 `var(--anic-*)`**，不禁止十六进制字面量。一个模块完全可以「既不用令牌、也不写裸 var」—— 它直接写 `#22c55e`，守卫完全看不见。**这是守卫的已知盲区**，不是疏忽。

**若要收口**，需要一个新守卫：禁止 `src/client/features/**` 出现十六进制字面量（豁免 `tokens.ts`），并同样带上 §5 的三条纪律（反向自检、不匹配自身、扫描集非空）。这条守卫**目前不存在**。

## 7. 相关约定

**`.anic-*` CSS 类名**：全工程只有一处使用 —— `gateColors.ts:40,44` 的 `.anic-fail-node`（FAIL 脉冲动画，`prefers-reduced-motion` 禁用）。该 CSS 经 `renderGraph.ts:116` 的 `createElement('style', ...)` 注入。

**本工程没有 `.css` 文件**（`Get-ChildItem -Recurse -Include *.css` 无结果），全部样式是 React `createElement` 的内联 `style` 对象 + 两处运行时注入的 `<style>` 元素（`WorkflowGraphPanel.ts:51` 的令牌块、`renderGraph.ts:116` 的脉冲块）。因此父工程的 `cg-` 前缀约定**不适用于本工程** —— 详见 [开发规范-守卫与约束.md](开发规范-守卫与约束.md) §6。
