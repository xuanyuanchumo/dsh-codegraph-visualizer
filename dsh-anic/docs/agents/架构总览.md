# dsh-anic 架构总览

> 本文描述 dsh-anic 插件**实际存在的**模块布局与依赖方向。所有结论均来自源码阅读，行号为写作时的真实行号。
> 读取本文件的时机：新增模块、判断一段逻辑该放哪个目录、或需要确认某条依赖是否合法时。

## 1. 双入口与隔离规则

dsh-anic 是一个 DSH 插件，同时导出宿主半部与客户端半部（`package.json` 的 `exports`）：

| 入口 | 文件 | `name` | `inject` |
| --- | --- | --- | --- |
| 宿主 | `src/index.ts:16` `apply(ctx)` | `'dsh-anic'`（`src/index.ts:13`） | `['tools','webServer','sessions']`（`src/index.ts:14`） |
| 客户端 | `src/client/index.ts:16` `apply(ctx)` | `'dsh-anic-client'`（`src/client/index.ts:13`） | `['slots']`（`src/client/index.ts:14`） |

宿主入口 `apply` 用 `ctx.effect()` 承接两个注册器（`src/index.ts:18-20`）：`registerAnicRoutes`（`src/host/routes/index.ts:48`）与 `registerAnicTools`（`src/host/tools.ts`）。宿主无 `webServer` 时路由整体跳过，插件主体不受影响。

### 隔离由 `lib` 与 `include` 双重保证

两个 tsconfig 各自独立、**不 extends 任何根配置**（各 17 行）：

- `tsconfig.host.json`：`lib: ["ES2022"]`，**无 DOM**；`include: ["src/index.ts"]` —— 宿主半部按**可达性**从单一入口编译，不是目录 glob。
- `tsconfig.client.json`：`lib: ["ES2022","DOM","DOM.Iterable"]`；`include: ["src/client/**/*.ts","src/client/**/*.tsx"]` —— 目录 glob，构造上**永远到不了** `src/host/`。

因此「宿主不能碰 `document`」不是纪律而是编译错误（DOM 不在 lib 里）；「客户端不能 import 宿主」同样由 glob 边界保证。两者共同启用 `allowImportingTsExtensions: true` + `noEmit: true`，这是 import 里写 `.ts` 扩展名合法的原因；`noUncheckedIndexedAccess: true` 是代码里大量 `?.` 与 `!` 的真实来源。

### 依赖方向（单向）

```
src/index.ts (host entry)          src/client/index.ts (client entry)
      │                                    │
      ▼                                    ▼
src/host/routes/*  ──┐              src/client/integrations/*
src/host/tools*.ts ──┤                     │
src/host/{runtime,evolution,governance,llm}/│
src/host/{logger,config,agents,skillInvoker,i18n}.ts
      │                                    │
      └──────────────► src/shared/* ◄──────┘
                    src/adapters/*
```

`src/shared/` 是**唯一**双向共享层，且必须是纯函数或无 DOM 假设的代码 —— `src/shared/flows.ts:10-11` 明确记录「本模块不接触 window/localStorage，存储读取在 client 集成层完成」。`src/shared/errors.ts:2` 声明为 client/host 共用单实现。

## 2. `src/host/` — 宿主半部

### 2.1 `src/host/routes/` — HTTP 面（按端点拆文件）

聚合器 `src/host/routes/index.ts:48` `registerAnicRoutes(ctx, options)` 是**纯组合层**，头部 `index.ts:4-10` 声明六域分区：

| 域 | 路由模块 | 聚合位置 |
| --- | --- | --- |
| data | `snapshotRoute.ts` / `stepTraceRoute.ts` / `selfCheckRoute.ts` / `selfInitRoute.ts` | `index.ts:57-62` |
| cycle | `cycleRoute.ts` / `ledgerRoute.ts` / `stackProbeRoute.ts` / `segmentedLedgerRoute.ts` | `index.ts:65-70` |
| review | `reviewRoute.ts`（条件性 LLM） | `index.ts:73-83` |
| evolution | `evolutionRoute.ts` | `index.ts:86` |
| governance | `governanceRoute.ts` | `index.ts:89` |
| self | `selfBootstrapRoute.ts` / `skillRoute.ts` / `skillInstallRoute.ts` | `index.ts:92-94` |
| native | `nativeRoute.ts`（7 脚本原生等价物） | `index.ts:97-101` |
| dual | `dualBootstrapRoute.ts` / `truthAuditRoute.ts` | `index.ts:104-108` |

共享依赖经 `src/host/routes/routeContext.ts` 的 `buildRouteContext(ctx)` 提取（单一职责），产出 `{ send, getWorkspaceRoot, loadFlows }`。`SendFn` 类型定义在 `routeContext.ts` 并由 `index.ts:35` 再导出。

`src/host/snapshotRoute.ts` 是 data 域的**形状权威**：`SNAPSHOT_ROUTE`（`snapshotRoute.ts:22`）、`SnapshotCtx` 接口（`snapshotRoute.ts:28`）、`resolveWorkspaceRoots(ctx)`（`snapshotRoute.ts:44`）、`sendJson(res, status, body, extraHeaders)`（`snapshotRoute.ts:63`）都定义于此，其余路由模块复用同一份窄化，不各自发明。

**disposer 纪律**：每个路由注册都返回 `(() => void) | null`，聚合器在 `index.ts:110-112` 过滤出函数并返回一个统一 cleanup：

```ts
const cleanups = disposers.filter((d): d is () => void => typeof d === 'function');
if (cleanups.length === 0) return null;
return () => { for (const d of cleanups) d(); };
```

被 `tests/contract/dshConformance.test.ts:145-173` 以源码形状守卫钉死（要求 `typeof d === 'function'` 与 `for (const d of cleanups) d()` 两个形状同时在）。

## 3. `src/client/` — 客户端半部

唯一 React 组件是 `src/client/WorkflowGraphPanel.ts:65` `WorkflowGraphPanel()`。它只负责**状态 + 并行 fetch + 分区编排**，纯渲染全部提取到 `features/`（`WorkflowGraphPanel.ts:4` 声明「特性模块制」）。

| 特性模块 | 导出 | 行数 |
| --- | --- | --- |
| `features/graph/renderGraph.ts` | `renderGraph`（:88）、`buildVerdicts`（:215）、`verdictKey`（:69）、`GraphData`（:39） | 230 |
| `features/graph/gateColors.ts` | `GATE_COLORS`（:13）、`gateFillOf`（:22）、`FAIL_PULSE_STYLE`（:35）、`bandStatus`（:61）、`BAND_COLORS`（:68）、`renderControlBand`（:75）、`renderNodeDetail`（:101） | 128 |
| `features/stepTrace/renderStepTrace.ts` | `renderStepTrace`（:36）、`StepTraceJson`（:20）、`TraceStepJson`（:8） | 83 |
| `features/diagnostics/renderDiagnostics.ts` | `renderDiagnostics`（:21）、`SelfCheckJson`（:15）、`ProbeJson`（:8） | 39 |
| `features/prefs/prefsDrawer.ts` | `renderPrefsDrawer`（:57）、`readPrefsRaw`（:30）、`writeUserPrefs`（:39）、`PREFS_PANEL_ID`（:54） | 103 |
| `features/org/renderOrgStatus.ts` | `renderOrgStatus`（:48）、`OrgStatusJson`（:24） | 136 |

`integrations/WorkflowTabIntegration.ts`（176 行）负责 `conversation.view` 顶层标签注册，走 `ctx.slots.inject('conversation.view', cb)`，disposer 暴露在 `window.__ANIC_TAB_SPIKE__` 供 J0 探针驱动，并实现 kill-switch（`localStorage['anic-workflow-tab'] === 'off'` 时零行为）。

`workflowGraphData.ts`（37 行）是**生成文件**（`GENERATED FILE — do not edit by hand`），承载构建期嵌入快照，是三层数据降级的安全底线。

### 数据热更新三层（`WorkflowGraphPanel.ts:7-10`）

1. 嵌入快照（构建期生成，永远可用）；
2. live 路由 `GET /anic/api/workflow-snapshot`（挂载时与点「刷新」时拉取）；
3. 路由缺失/404/5xx/无 fetch → 回退嵌入快照，底行**如实显示来源**。

`fetchLive`（`WorkflowGraphPanel.ts:79`）用 `inFlight` ref 守卫防抖、`typeof fetch !== 'function'` 早退（smoke 沙盒），并以 `Promise.all` 并发 4 个独立任务（snapshot / step-trace / self-check / org-status），各自独立降级、各自拒绝畸形形状。
