# dsh-anic 开发规范

> 本文只写**代码库实际执行的**规范，并逐条标注它的执行者。规范共 9 条，分两册：
>
> | 分册 | 覆盖 | 内容 |
> | --- | --- | --- |
> | 本册 | §0–§3 | 总览表 + 模块化纪律（行数 / 一域一文件 / 路由拆分） |
> | [开发规范-守卫与约束.md](开发规范-守卫与约束.md) | §4–§9 | 日志 / i18n / CSS 前缀 / ESM / G-IND / DSH 清单 + 新增文件清单 |
>
> 三种执行状态的含义：
>
> - **测试强制**：有测试会红。
> - **构建/运行时强制**：没有测试扫它，但违反后 build / typecheck / 运行会失败。
> - **仅文档约定**：写在 `dsh-anic/CLAUDE.md` 或注释里，**当前没有任何机制拦它**。
>
> 读取本文件的时机：新增文件、新增路由、或评审一次改动是否越界时。

## 1. 单文件 ≤ 250 行 —— 测试强制（限 `src/`）

**权威常量**：`src/host/evolution/truthAuditChecks.ts:6`

```ts
const MAX_FILE_LINES = 250;
```

**判定逻辑**：`truthAuditChecks.ts:72-84` `auditStructure(pluginDir)`

```ts
const tsFiles = collectTsFiles(join(pluginDir, 'src'));   // :74
const oversized = tsFiles.filter((f) => f.lines > MAX_FILE_LINES);   // :75
for (const file of oversized) findings.push({ check: `file:${file.path}`, status: 'fail', ... });  // :76
return { dimension: 'T3_structure', passed: oversized.length === 0, score, findings };  // :83
```

**测试断言**：`tests/unit/truthAudit.test.ts:34-40`

```ts
it('T3 structure: no file exceeds 250-line modular limit', () => {
  const result = auditStructure(PLUGIN_DIR);
  const oversized = result.findings.filter((f) => f.status === 'fail' && f.check.startsWith('file:'));
  expect(oversized).toEqual([]);
  expect(result.passed).toBe(true);
});
```

**扫描范围**：只有 `join(pluginDir, 'src')`（`truthAuditChecks.ts:74`）。因此：

- `tests/`、`scripts/`、`docs/` **不受**这条约束。
- 本文件与分册都可以超过 250 行而不触发任何红 —— 但工程约定仍按 250 行自律。

**实际状态**：写作时全部 71 个 `src/**/*.ts` 都在限内（最大 `src/host/toolsSkillGateway.ts` 237 行、`src/host/runtime/segmentedLedger.ts` 230 行、`src/host/tools.ts` 206 行、`src/host/routes/selfBootstrapRoute.ts` 204 行）。

**这条约束是真实的拆分动因**，注释即证据：

- `src/host/evolution/truthAudit.ts:4`：「四维检查函数拆至 truthAuditChecks.ts 以满足 250 行模块限制。」
- `src/host/toolsSkillGateway.ts:4`：「拆分自 tools.ts（T3 ≤250 行模块化纪律，truthAudit T3 结构守卫实测拦截 320 行）。」
- `src/host/toolsSlot.ts:2`：「独立成文件以避免 tools ↔ toolsSkillGateway 的 type-only 循环引用。」
- `src/host/toolsPointerGateway.ts:4`：「拆分自 tools.ts（T3 ≤250 行模块化纪律）。」

**拆分的正确姿势**：按**域**拆，不按行数机械切。`toolsSkillGateway.ts:6-7` 写明「工具域拆分与『路由按端点拆』同构：eval/gate 命名工具留 tools.ts，技能调用域（安装 + 通用网关）独立成文件」。

## 2. 一域一文件 —— 仅文档约定

写在 `dsh-anic/CLAUDE.md`「模块化纪律：单文件 ≤~250 行 / 一域一文件 / 路由按端点拆 / 特性模块制」。

**唯一的机械检查**是 `truthAuditChecks.ts:78-81`，它只检查五个域**目录存在**，且状态是 `warn` 而非 `fail`：

```ts
for (const domain of ['runtime', 'evolution', 'governance', 'llm', 'routes']) {
  const exists = existsSync(join(pluginDir, 'src', 'host', domain));
  findings.push({ check: `domain:host/${domain}`, status: exists ? 'pass' : 'warn', detail: exists ? 'separated' : 'MISSING' });
}
```

`warn` 不影响 `passed`（`truthAuditChecks.ts:83` 只由 `oversized.length === 0` 决定），因此**删掉一个域目录不会让任何测试变红**。

「一域一文件」的落地形态可以从实际布局观察（见 [架构总览.md](架构总览.md) §2），但它靠评审而非守卫维持。

## 3. 路由按端点拆 —— 仅文档约定

`src/host/routes/` 的实际形态：一个端点族一个文件（`ledgerRoute.ts` 承载 `/anic/api/ledger` 三个端点，`segmentedLedgerRoute.ts` 承载 `seg-ledger` 四个端点），聚合器 `src/host/routes/index.ts:48` 只做组合，不实现业务。

**机械检查**：`truthAuditChecks.ts:90-94` 只验证每个路由文件里出现字符串 `register` 或 `reg(`：

```ts
const hasReg = content.includes('register') || content.includes('reg(');
findings.push({ check: `route:${file}`, status: hasReg ? 'pass' : 'warn', detail: hasReg ? 'has registration' : 'no registration' });
```

同样是 `warn`。**一个把全部 47 个端点塞回单个文件的改动不会被这条检查拦下**（只要文件里还有 `register` 字样），真正会拦下它的是 §1 的 250 行上限。

另有 `truthAuditChecks.ts:96-99` 检查 `routes/index.ts` 的 `^import ` 行数 ≥ 8，也是 `warn`。

### 3.1 聚合器纪律（测试强制）

`src/host/routes/index.ts:110-112` 的 disposer 聚合形状被 `tests/contract/dshConformance.test.ts:145-173` 钉死，要求同时出现：

```ts
const cleanups = disposers.filter((d): d is () => void => typeof d === 'function');
if (cleanups.length === 0) return null;
return () => { for (const d of cleanups) d(); };
```

守卫断言 `/typeof d === 'function'/` 与 `/for \(const d of cleanups\) d\(\)/` 两个形状，并要求四个注册函数名 `registerSnapshotRoute` / `registerStepTraceRoute` / `registerSelfCheckRoute` / `registerSelfInitRoute` 必须出现，且**不得**出现 `registerNonexistentRoute`。

### 3.2 每个注册点必须保留 disposer（测试强制）

所有注册统一返回 `(() => void) | null`，聚合器在 `index.ts:110` 过滤。**每个** `registerXxx` 里 `c.webServer.register(...)` 的返回值都必须判 `typeof d === 'function'`，不能丢弃。`dshConformance.test.ts:146-147` 单独断言 `snapshotRoute.ts` 含 `/typeof disposer === 'function'\s*\?\s*disposer/`。

**教训**：`dshConformance.test.ts` 的注释记录了一个真实的泄漏 —— 聚合器一度写成 `cleanups[0]?.()`，只清理第一条路由而静默泄漏其余三条；断言必须是 `toHaveBeenCalledTimes(routes.length)` 而非「被调用过」。

### 3.3 方法判定在 handler 内

位置参数式注册的 `method` 在 `evolutionRoute.ts:34` 与 `dualBootstrapRoute.ts:37` 被显式丢弃（`void method;`），宿主只拿到 `path`。**HTTP 方法检查因此必须写在 handler 里**，只有三个 handler 真正实现了：`selfInitRoute.ts:44`、`skillInstallRoute.ts:53`、`skillInstallRoute.ts:90`。
