# DSH CodeGraph Visualizer

## Commands
- Build: `pnpm run build`
- Test: `pnpm run test`
- Lint: `pnpm run lint`
- Typecheck: `pnpm run typecheck`
- Coverage: `pnpm run test:coverage`
- E2E: `pnpm run test:e2e`

## Verifying your work
- Run build, test, and lint before reporting done.
- Paste output as evidence.

## Conventions
- ESM only: `"type": "module"` in package.json, `.ts` extensions in imports
- Host/Client isolation: tsconfig.host.json and tsconfig.client.json separate compilation
- Branded types: NodeId, EdgeId, RepoId prevent ID mixing across boundaries
- Plugin lifecycle: ctx.effect() for side effects, return disposer for cleanup
- State management: Zustand with persist middleware, graphStore as single source of truth
- Rendering: Cytoscape.js via IRenderer interface abstraction
- Logging: scoped() logger from shared/Logger.ts, not console directly
- i18n: All user-facing text via t() from i18n/index.ts
- CSS: cg- prefix for all class names, CSS variables for theming
- Testing: vitest for unit/component, Playwright for E2E

- SearchController Trie index is NOT auto-rebuilt when rawNodes change — must call rebuildIndex() after setRawNodes
- SQLite IN clause has a parameter limit (999/32766) — use SQLITE.MAX_IN_PARAMS batching for large node ID lists
- expandNode async callbacks (fetchFileOutline/fetchSymbolAST) must check expandGeneration before applying state to avoid stale writes
- disposeStore must clean up prefetchAbortControllers and prefetchInFlightCount to prevent memory leaks
- fuzzyScore with empty pattern returns 1 (matches everything) to stay consistent with fuzzyMatch semantics
- Routes data endpoint has no built-in size limit — must check payload size and slim if exceeding API.DATA_RESPONSE_MAX_BYTES
- ctx.slots.inject() returns a disposer — must save and track it alongside other disposers, not discard the return value
- color-mix() CSS function needs rgba fallback in a separate file — every usage must have a corresponding fallback entry in color-mix-fallback.css
- @container CSS Container Queries need @supports not (container-type: inline-size) fallback for older browsers
- betterSidebar.registerTab() may not return a disposer — must guard with typeof dispose === 'function' before calling
- prefetchExpand uses requestIdleCallback/setTimeout — must save the handle and cancel it in disposeStore to prevent stale writes after dispose
- LayoutController worker timeout must auto-retry via retryWorkerInit() — never set workerInitFailed=true on timeout, or worker layout is permanently disabled
- DataController.processBatchQueue RAF callback must check this.destroyed at the top — destroy() may be called before the RAF fires
- FilterController.safeRegExp must check for nested quantifiers (e.g. (a+)+, (a*)*) — simple length checks are insufficient for ReDoS prevention
- readEdgesFromDb file scope must NOT use LIMIT/OFFSET per IN-clause batch — query all edges then slice in memory, because SQL OFFSET applies to the whole result set not per-batch
- VirtualViewportController.handleStructureChange must schedule updateVisibility via RAF, not just set indexDirty — otherwise new nodes won't be indexed until next viewport change
- assembleMultiFunction must use fetchWithTimeout (not bare fetch) and check multiAssemblyGeneration before applying state — bare fetch has no timeout and no stale-write protection
- progressiveCluster module-level caches (_dirToNodesCache/_fileToNodesCache) must be invalidated in disposeStore via invalidateExpandCostCache() — otherwise they hold stale rawNodes references

Always read the error-context page snapshot first and confirm whether the element exists in the DOM before touching any timeout. This is why the host scopes the validator by the REQUESTED workspace while taking the revision from the single slot

- "Two green unit tests" is not "the combination works": both cycle-84 defects sat in the seam of "A writes state / B guards state" with no test crossing A∘B. - A fixture whose new set-valued parameter defaults to the EMPTY set hides cross-path defects: `pinnedIds: new Set()` made "honours pin" and "ignores pin" assert identically. Any newly added set that participates in a decision needs a NON-EMPTY regression case
- A component test that asserts "method X was called" must bind to the SAME instance the component holds: the default `usePanelState` mock returned a fresh object per call, so `mock.results[0].value` was not the object used at click time and the assertion read `Number of calls: 0`. - Two or more copies of an order/enum list WILL drift, and the drift is silent: collapse them into one `Object.freeze`d source of truth (readonly is compile-time only) and add a source-level guard test that regex-scans for bare literal arrays. That guard MUST carry a reverse self-check, or a broken regex stays green forever
- When a value is dropped at every layer, the feature is invisible and no existing test turns red: the AST budget shipped a server-side truncation whose `hasMore` the client never parsed and the UI never showed — three independent single-layer fixes were each useless. Trace producer → transport → consumer → presentation, and assert every decision-carrying field at the CONSUMER, because "the response had data" keeps passing when one field is discarded
- A degraded default must decline, not promise: with missing pagination fields, `hasMore: true` renders a button that can never load anything (a false promise), while `hasMore: false` ("this page is everything") is the only safe fallback for multi-generation hosts
- A generation counter cannot double as request ownership: `expandGeneration` advances on unrelated expand/collapse, so it answers "did the graph change", not "is this the newest page for this node". Reusing it lets a slow earlier page overwrite a newer one — use a per-key monotonic token (`astRequestSeq`, same shape as `edgeRequestSeq`)
- A partial page must never enter the "complete result" cache: writing a one-page AST means the next visit hits the cache, skips the fetch and never recomputes `hasMore`, so the user permanently loses the folded part. Gate writes on `!hasMore && cursor === 0`; test that gate explicitly
- After changing a HOST route you must restart the host process, not just rebuild: the running process kept the old bundle, so the live `/ast` response had 4 keys instead of 6 until `stop` + `start` + `reload`. A stale-process probe silently reports the previous behaviour
- Derive assertions from the source's actual behaviour, not from what the semantics "should" do: `fetchSymbolAST` deliberately omits the `workspace` param when it equals `'.'`, so an assertion written as `?workspace=.&cursor=800` failed against the real URL `?cursor=800`. Read the branch, then write the expectation
- "The entry point exists" is not "the entry point is reachable": the file-pair aggregate shipped a "show more edges" button that only ran `setShowAll(true)` on the local array — it rendered, it changed the UI on click, and it never issued a request, so the collapsed edges were unreachable while every existing test stayed green. - An aggregate page impersonates a complete page: `/edges` reports `hasMore: false` and `total === edges.length` for a collapsed neighbourhood, which is exactly the definition the "already fully loaded" early-return guard tests for — so the guard turns from an optimisation into a lock. Any guard of the form `loaded.length >= knownTotal` must be able to distinguish "complete" from "complete but folded", and needs BOTH a case that is let through (aggregate + detail request) and a case that is still blocked (plain complete page + detail request), or weakening it to `if (true)` stays green
- Aggregation is a contract about ORDER, not an implementation detail: aggregating after pagination splits one file pair across pages, so every page looks correct alone and the merged result is wrong. Read the full un-sliced set first, then decide aggregate-or-slice (`readIncidentEdgesWithFilePathsFromDb` deliberately takes no cursor/limit)
- Two data paths for the same semantics must share ONE implementation: the DB-first branch and the in-memory fallback each had their own aggregation, and divergence in `total`/`hasMore`/`filePair` only shows up as "expanding the detail gets the wrong cursor". Extract the shared builder (`buildFilePairAggregate`) and assert its contract (pair-key ordering) directly
- A remote endpoint's file must be looked up, not assumed: the file-scope reader only pre-seeds `file_path` for nodes in the requested file, so every cross-file edge's far end collapsed into the single fake file pair `'?'`. Batch-query the unresolved endpoints before aggregating
- An explicit user intent must become sticky state, not a one-shot parameter: `detail=1` on the first page only means page two is re-collapsed and the user silently loses what they just asked for — hence `detailEdgeNodeIds`, checked as `options?.detail === true || state.detailEdgeNodeIds.has(nodeId)`. - A cache must not answer a question the user explicitly left behind: the cached edge payload IS the aggregate the user clicked away from, so detail mode skips both the cache read and the cache write (`!append && !detail`, `!data.hasMore && !detail`) — same constraint as cycle-85's "a partial page must never enter the complete-result cache", applied to the opposite direction
